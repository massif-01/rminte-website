# TianshanOS 安全页面完整操作指南

对应版本：TianshanOS 0.6.4。核查日期：2026-11-03。

这份指南帮助你修改设备密码、连接 SSH 服务器、核对服务器身份，并管理设备证书和配置包。首次使用可按第 1、2、3 章操作。证书签发与恢复操作请与设备或服务器管理员一起完成。

> 请在可信管理网络中使用。完整管理页面使用 HTTP；安装证书不会把它切换到 HTTPS。目前部分证书操作仍可在未登录时被调用，退出登录不能代替网络隔离。不要把设备管理入口暴露在公共网络中。

## 1. 开始前先确认

### 1.1 找到你需要的功能

1. 在浏览器输入目标设备的 IP 地址，使用自己的设备账号登录。
2. 在导航中点击“安全”。请先确认地址正确，再输入密码或操作密钥。
3. 按下表找到对应区块。root 登录后还会看到“账号安全”。

| 你要做什么 | 到哪里操作 |
|---|---|
| 修改 root 或 admin 的设备登录密码 | 账号安全，见第 2 章 |
| 让设备用密钥连接服务器 | 密钥管理、已部署主机，见第 3 章 |
| 复制密钥、修改或删除主机、核对指纹 | 密钥管理、已部署主机、已知主机指纹，见第 4 章 |
| 申请和安装设备证书 | HTTPS 证书，见第 5 章 |
| 检查或制作通用加密配置包 | 配置包，先阅读第 6 章的限制 |

### 1.2 账号与设备身份

- **admin** 可进入安全页，管理 SSH 密钥、主机及页面提供的证书功能，但看不到“账号安全”。
- **root** 还能设置 root/admin 密码、恢复 admin 访问，并管理需要 root 的自动化配置和网页终端。已登录的 admin 仍可使用首页提供的服务控制。
- **Developer 设备** 是证书中标明开发身份的设备，不是登录账号。导出加密配置包和 SSH 主机配置要求这种身份；以 root 登录不会改变设备身份。

需要登录的操作会检查账号；部分查询和证书操作仍未要求登录。按钮可见不代表当前账号或设备满足全部条件。遇到权限提示时，先确认登录状态和操作要求，不要反复提交。

### 1.3 操作前的准备

1. 确认电脑和目标设备处在可信管理网络中。
2. 向服务器管理员确认 SSH 地址、端口、登录账户和完整主机指纹。
3. 页面部署或撤销公钥需要远端账户密码，且账户允许密码登录。后续是否保留密码登录，由服务器管理员决定。
4. 撤销授权、删除密钥或更换证书前，确认另一条管理入口可用，例如服务器控制台、另一管理员密钥或设备的 HTTP 管理入口。

## 2. 修改设备登录密码

这里修改的是 TianshanOS 登录密码，不会修改远端服务器的 SSH 密码。

### 2.1 首次登录的密码提醒

账号尚未标记为已修改密码时，登录后会出现改密提醒。请设置独有的长密码。选择“稍后修改”只会关闭提醒。

这个提醒不是可以随时打开的账号设置入口。admin 已改过密码后如需再次改密，请由 root 在安全页设置。

### 2.2 由 root 设置密码

1. 以 root 登录，打开“安全”。
2. 在“账号安全”找到 root 或 admin 密码管理，填写新密码和确认密码。
3. 点击“设置 root 新密码”或“设置 admin 新密码”。建议使用 12 位以上的独有密码；为避免长度计算差异，可使用英文、数字和符号。

页面提示长度为 4-64 个字符，设备按 UTF-8 字节检查。英文、数字和常用半角符号各占 1 字节，中文通常占多个字节。4 是最低接受长度，不是推荐长度。

**确认结果**：用无痕窗口重新登录，确认新密码可用，再退出原会话。设置新密码不会自动结束已有会话。

**登录失败时**：先核对账号和设备地址。连续 5 次失败会锁定约 5 分钟，不要反复猜测。

### 2.3 重置 admin 密码

root 可点击“重置 admin 为默认密码”，将 admin 密码恢复为 `rm01`，并清除登录锁定。恢复后，用新会话登录 admin，立即设置独有密码。

> 默认密码只用于临时恢复访问。完成后及时改密，并退出不再需要的旧会话。

### 2.4 忘记 root 密码

请联系设备管理方，使用与当前设备匹配的恢复方案。当前恢复固件只适用于新的配置存储方案，并会同时重置 root 和 admin 密码。不要自行刷入旧恢复固件。恢复访问后，两种账号都要重新设置独有密码。

## 3. 用 SSH 密钥连接服务器

首次设置按“生成 RSA 密钥、部署公钥、检查结果、测试连接”进行，并核对服务器指纹。退役密钥时，先撤销各服务器上的授权，确认旧密钥不能登录，再删除本地密钥。

### 3.1 生成密钥

1. 在“密钥管理”点击“生成新密钥”。
2. 输入未使用的密钥 ID，例如 `backup01`。使用不超过 10 位的英文、数字组合，不要包含逗号。实际限制为 10 个 UTF-8 字节，不能按 10 个汉字计算。
3. 选择 RSA 2048 或 RSA 4096。默认是 RSA 2048；页面也列出 ECDSA，但当前 SSH 流程不支持它，请为 SSH 选择 RSA。
4. 按需填写备注和别名。只有需要备份或迁移私钥时，才打开“可导出”。生成后没有修改该选项的页面入口。
5. 按需设置“隐藏”，点击“生成”。隐藏只影响显示，不会阻止他人读取真实 ID 或访问密钥。

**确认结果**：窗口关闭、列表刷新后，找到正确 ID 和 RSA 类型。点击“公钥”，确认完整文本以 `ssh-rsa` 开头。

**等待过程中**：不要重复提交。关闭窗口不会取消设备上的生成操作。

| 你看到的提示 | 下一步 |
|---|---|
| ID 已被使用 | 换一个未使用的 ID，不能靠新建覆盖旧密钥 |
| 已达到数量上限 | 最多保存 8 个 SSH 密钥，先按撤销流程清理不用的密钥 |
| 存储空间或内存不足 | 先处理设备资源问题，不要把失败当成已生成 |
| 密钥已生成，但列表刷新失败 | 手动刷新并核对，无需重新生成 |
| 生成结果未确认 | 等待并检查记录，不要重复生成同一 ID |
| 数据清理未完成 | 暂停生成，请管理员检查存储状态 |

同 ID 记录存在，不等于本次生成已完整成功。结果不明时，还要核对记录和密钥材料。

### 3.2 部署公钥

部署会把公钥加入远端账户的授权文件 `~/.ssh/authorized_keys`，使对应私钥可以登录。服务器密码不会因此改变。

1. 在目标密钥行点击“部署”。
2. 填写服务器地址、用户名、SSH 端口和“SSH 登录密码”。
3. 核对地址与账户，点击“开始部署”。
4. 阅读结果，在“已部署主机”检查对应记录。

> 部署会先检查主机指纹，再使用密码。已知主机的指纹变化会被拒绝；但首次部署到新主机时，设备仍会自动保存并信任指纹，不会先要求你确认。因此首次部署应在受控网络中进行，并通过可信渠道核对完整指纹。

### 3.3 分清部署结果

| 结果提示的含义 | 下一步 |
|---|---|
| 公钥已部署、主机已登记、公钥登录已验证 | 核对主机信息，再测试实际任务 |
| 公钥已部署、主机已登记，但公钥登录未确认 | 点击“测试”；失败时从另一管理入口检查远端授权和账户设置 |
| 公钥已部署，但主机登记失败或未确认 | 先核对本地列表和远端授权，不要直接重复部署 |
| 部署完成，但列表刷新失败 | 手动刷新；刷新失败不代表远端公钥未写入 |

每次部署都会追加公钥，重复部署可能产生重复行。需要确认远端结果时，请从另一管理入口检查授权文件。

### 3.4 测试连接

1. 在“已部署主机”核对地址、端口、用户名和密钥 ID，点击“测试”。
2. 首次连接出现指纹窗口时，按第 4.3 节核对完整指纹，再决定是否点击“信任并连接”。
3. 指纹变化时，窗口会显示已保存和当前两个指纹。先取消并核实原因；确认是合法变更后，才点击“更新主机密钥”。

测试会尝试执行固定回显命令 `echo "TianshanOS SSH Test OK"`。当前成功提示没有进一步检查命令退出码和回显内容，只能用于基础连接检查，不能证明 sudo 权限或实际业务命令可用。

**失败时**：检查网络、SSH 服务、账户和远端授权。身份不明或指纹变化时，停止重试，先核对服务器身份。

### 3.5 撤销远端授权，再清理本地记录

> 撤销会影响后续登录。先确认其他管理方式可用，并处理仍需停止或核验的任务。撤销公钥、删除主机或删除密钥，都不会自动停止远端程序。

1. 在对应主机行点击“撤销”，输入服务器密码，再点击“撤销远端公钥”。也可从密钥行发起撤销并填写目标信息。
2. 阅读远端结果。撤销成功后，页面会打开本地主机配置的删除检查；这仍需你另行确认，尚未自动删除本地记录。
3. 从可信入口检查远端授权文件，确认对应公钥及重复行已移除，再验证旧密钥不能登录。撤销留下的 `authorized_keys.bak` 应按服务器备份策略处理，防止恢复旧授权。
4. 如要删除本地主机配置，按第 4.2 节检查关联和影响后确认。
5. 所有目标服务器都完成撤销、相关任务也已处理后，再按第 4.1 节删除设备中的旧密钥及不需要的私钥副本。

**提示未找到公钥**：先核对目标账户和远端授权。页面的“检查并删除本地主机配置”只处理本地记录，不能代替远端核查。

**撤销失败或结果未确认**：从可信入口检查远端授权，不要先删本地密钥。远端撤销与本地删除分别判断；其中一步失败，不表示另一步一定没有发生。

## 4. 管理密钥、主机与指纹

### 4.1 复制、导出和删除密钥

SSH 密钥行按下文操作。列表中标为 `https` 的行是设备证书密钥；删除这一行会清除整套证书凭证，操作前请阅读第 5.6 节。

**复制公钥**：点击“公钥”，把完整的一行交给服务器管理员。公钥可以分享；管理员将它加入账户授权后，才会产生访问权限。

**导出私钥**：只有生成时打开“可导出”的密钥才能导出。请在可信电脑和隔离管理网络中点击“私钥”，保存到受控密钥库。清理剪贴板和下载目录中的临时副本，不要粘贴到聊天、工单或日志中。

**复制无响应**：HTTP 页面可能受浏览器剪贴板限制。可手动选中复制，再核对内容是否完整。不要为此放宽浏览器安全设置。

**删除密钥前**：先撤销服务器授权，并检查确认框列出的关联主机和运行记录。删除后，本设备不能再用这把密钥连接、核验或停止相关任务，远端任务却可能继续运行。先通过其他入口处理这些任务；影响无法完整列出时，不要把它当作“没有关联”。

确认删除后刷新检查。若提示存储删除未完成，先检查现状并请管理员处理，不能只看列表中是否还显示该密钥。

### 4.2 删除主机配置并处理关联

| 操作 | 实际改变什么 |
|---|---|
| 撤销公钥 | 删除远端账户中的对应授权，需要远端密码 |
| 移除主机 | 删除设备中的主机配置，按选择处理相关命令和规则 |
| 删除密钥 | 删除设备中的密钥材料 |
| 移除已知主机指纹 | 删除设备保存的服务器身份记录 |

后三项都不会撤销远端公钥，也不会停止远端程序。“已部署主机”只是本地清单，列表为空不代表远端授权已清理。

1. 在主机行点击“移除”，等待“关联检查”完成。
2. 有关联时，检查受影响的命令、模板或规则。可选择替代主机，或解除关联并停用相关配置。替代主机应具备所需账户、密钥和任务条件。
3. 点击“删除”，阅读结果，再检查相关命令和规则。被解除关联的命令需要重新选择主机并启用。

“最终强制删除”用于明确决定清理配置的场景。它不要求远端服务已停止或状态已确认。影响无法确认时，可能要求勾选“我确认暂停自动化，并继续删除。”；完成后自动化保持暂停，需要 root 检查配置并手动启用。

> 不要为了消除错误提示就强制删除。先确认远端任务由谁继续管理，以及哪些自动规则会受影响。

提示配置已改变时，点击“重新检查删除影响”，按新结果决定。存储失败或结果未确认时，刷新检查当前配置，不要直接重复删除。

### 4.3 核对 SSH 服务器指纹

指纹用于确认服务器身份。这里显示 SHA-256 摘要的 64 位十六进制值，常见 OpenSSH 工具则显示 `SHA256:base64`。请管理员提供相同格式，不能直接比较这两种字符串。

**核对完整值**：在“已知主机指纹”点击“查看”，与服务器控制台、资产记录或另一可信渠道提供的值比较。表格仅显示前 32 位，不足以完成核对。

**测试时要求确认**：首次确认窗口显示当前指纹；变化警告显示已保存和当前指纹，默认可取消。核对服务器、地址、端口和维护记录后再决定。确认只针对这次显示的指纹；后续再次变化仍需核对。

**不一致或来源不明**：取消连接并调查。若已通过可疑连接使用密码，请从可信入口修改密码、检查登录日志和授权。不要通过可疑连接发送密码来撤销公钥。

**服务器正常重装或换钥**：核对新指纹和变更记录后，在测试窗口选择“更新主机密钥”。不要靠移除旧指纹绕过核对；移除记录不会证明下一次连接可信。

指纹保存在设备内部，不再按旧方式与 SD 卡上的指纹文件同步。配置备份和 SSH 主机导入不包含这些记录，恢复或迁移后仍要核对服务器身份。

### 4.4 编辑主机

1. 在“已部署主机”点击“编辑”。
2. 在“编辑 SSH 主机”中修改地址、端口或登录账户。密钥登录的主机还可修改登录密钥编号；端口范围为 1-65535。
3. 点击“保存”，刷新核对，再测试连接。更换目标服务器时，应核对它的完整指纹。

修改用于后续连接，已启动任务的运行记录仍使用原主机信息。不要因为改了地址就认为旧任务已迁移或停止。

### 4.5 导入与导出 SSH 主机配置

“导入主机”是专用流程，与第 6 章的通用配置包入口不同。包中包含地址、端口、登录账户、认证方式和密钥 ID，不包含 SSH 密码、私钥或已记住的主机指纹，也不会授予服务器访问权限。

**导出**：在 Developer 设备点击主机行的“导出”。给另一设备使用时，粘贴并核对目标设备证书，生成后点击“下载”，确认文件已保存。普通设备不能靠 root 登录获得导出资格。

**导入前**：确认来源可信、包为本设备制作，且本设备已有正确密钥。同 ID 不够，密钥本身必须与远端授权匹配。当前配置位置也必须可写，不要求一定有 SD 卡。

1. 点击“导入主机”，选择 `.tscfg` 文件，等待检查。
2. 阅读预览中的主机、地址、账户和变更项。只有确实要替换已有同名配置时，才勾选覆盖。
3. 点击“确认导入”。设备会再次检查配置包、设备凭证和当前配置，避免使用过期预览。
4. 看到保存成功后，刷新主机列表并核对，再测试连接。配置保存后立即生效，无需重启；自动化原有的启用或暂停设置保持不变。

这个入口会在预览时检查目标设备、签名、可信签发方及签名者资格，并解密检查内容。来源仍应通过可信渠道确认，不能仅凭名称或“官方”文字作决定。

**检查未通过**：按提示核对设备时间、设备证书、客户端 CA 链和可信签发方设置。能用于 HTTPS 的证书不一定有配置包签名资格；请设备管理方处理，不要为导入陌生包安装陌生 CA。

**预览失效**：点击“重新检查配置包”，重新阅读变更。若要求重新打开窗口，先保存需要保留的输入，再按第 7.2 节处理。

### 4.6 备份与恢复会带回哪些配置

SSH 主机与自动化规则、模板、命令等一起保存。日常使用 SD 卡配置；使用内部应急配置时，修改直接保存在设备内。主机导入、编辑和删除都写入当前使用的那套配置。

root 可在自动化页的“配置与备份”中查看当前使用位置。“保存应急副本”会手动更新内部整套副本，不会在每次修改后自动同步；“从应急副本恢复”会先显示差异，再替换当前配置，无需重启。

恢复较旧副本可能带回旧主机、命令和规则，也可能改变自动化启停设置。先阅读差异，再确认恢复。恢复不会停止或重启远端服务，也不会恢复私钥或已知主机指纹。

删除当前配置不会同步清理另一份手动副本。主机退役后，请安排更新应急副本。重新插卡也不会自动切换配置，应由 root 在“配置与备份”中确认使用哪一套。不要通过文件管理器直接删除或覆盖自动化内部管理文件。

## 5. 配置 HTTPS 证书与 mTLS

本次核查的构建配置未启用 HTTPS 服务。证书功能可用于准备凭证，但不能据此认为 443 端口已开放。若需要 HTTPS，请先让设备管理方确认所用固件已启用该服务。

启用后，当前 HTTPS 服务提供健康、身份和权限测试接口，不承载完整管理页面。以下连接测试适用于已启用 HTTPS 的部署。

### 5.1 先分清证书方向

- **设备证书和私钥**让设备向客户端证明身份。
- **客户端证书和私钥**由电脑或服务持有，让客户端向设备证明身份。
- **设备上的客户端验证 CA**用于验证客户端证书，不会自动让浏览器信任设备证书。

双方都出示证书的方式叫 mTLS。客户端仍需信任设备证书的签发方，并核对访问名称、允许用途和有效期。CA 是签发、验证证书的机构或相应证书。

### 5.2 读懂状态，先校准时间

“已保存”“在有效期内”“HTTPS 运行中”分别说明材料已存入、时间有效和服务正在运行，不能相互替代。

| 页面状态 | 下一步 |
|---|---|
| 缺少设备证书、私钥或客户端验证 CA | 补齐对应材料 |
| 有效期：待校时确认 | 先确认电脑时间正确，再点击“用当前电脑时间校时（来源：浏览器）” |
| 尚未生效或已过期 | 核对设备时间和证书日期，需要时续签 |
| 时间有效但 HTTPS 未运行 | 先确认固件已启用 HTTPS，再处理页面列出的材料、匹配或启动问题 |
| 运行中的服务仍使用旧材料 | 保存其他工作，按提示重启设备，再检查实际使用的证书 |
| 保存或读取结果不确定 | 先刷新核对，不要反复安装或删除 |

在已启用 HTTPS 的固件中，未运行的服务会在材料和时间条件满足后尝试启动。校时后仍要查看设备时间、同步状态和 HTTPS 状态，不能只看安装成功提示。

### 5.3 生成设备私钥与证书申请

> 已有私钥时，先阅读第 5.6 节。重新生成会覆盖它，可能使旧证书和配置包无法继续使用。

1. 点击“生成密钥对”。它生成独立的 ECDSA P-256 私钥，与 SSH 密钥不同，不能从此界面导出。
2. 点击“生成 CSR”，填写设备 ID（CN）、“组织”和“部门”，或全部留空。部门对应证书中的组织单位（OU）。
3. 点击“生成证书签名请求”，复制完整 CSR 文本交给 CA 管理员。

设备 ID 建议使用简短、稳定的英文和数字。表单字段最多 63 个 UTF-8 字节，中文会占多个字节；过长时按提示缩短。

**签发前核对访问名称**：自定义字段时，此表单不生成证书访问名称列表（SAN）。全部留空时，设备 ID 固定为 `TIANSHAN-DEVICE-001`；取得当前 IP 时只加入该 IP，不加入域名。请 CA 管理员在受控签发流程中加入实际访问的 IP 或域名，并核对认证用途。此表单不能编辑 SAN。

CSR 只是申请，不含私钥，也不会自动安装证书。签发前应核对申请中的公钥、主体和访问名称。

### 5.4 安装设备证书

1. 取得与当前设备私钥匹配的 PEM 证书。PEM 是带有 BEGIN/END 首尾标记的文本。
2. 点击“安装证书”，粘贴完整文本，再点击“安装”。
3. 检查保存结果、主体、签发者和有效期，再查看 HTTPS 实际状态。

安装会检查格式和公私钥匹配；客户端仍需另行检查信任、访问地址和用途。

需要查看证书文本时，在“密钥管理”的 `https` 行点击“证书”，核对或复制完整 PEM。公开证书可以交给配置包发送方，私钥仍应保密。

**密钥不匹配**：先找回当前 CSR 对应的证书，不要为了消除错误就重新生成私钥。结果未确认时，刷新核对已保存内容后再决定是否重试。

### 5.5 安装客户端 CA 链并测试

1. 点击“安装 CA”，粘贴验证客户端所需的一个或多个 PEM CA 证书，再点击“安装”。只安装管理方确认的可信 CA。
2. 检查状态。固件已启用 HTTPS 时，未运行的服务会在材料和时间齐备后尝试启动；已运行的服务如需应用新材料，按提示重启。
3. 由管理员用可信、用途和角色正确的客户端证书访问对应测试接口。
4. 再用不受信任的证书或不提供证书测试，确认连接被拒绝。

**确认结果**：HTTPS 显示运行中，且使用预期证书；显示“活动证书 SHA-256”时，核对其指纹。可信客户端只能访问其角色允许的接口。连接与拒绝结果都应在目标设备上另行确认。

### 5.6 续签、替换或删除凭证

**证书到期**：可沿用未泄露的私钥申请新证书，安装后按页面提示应用并测试。配置包绑定接收方证书指纹；即使用同一私钥，换证书后重新加载的旧包也可能被拒绝。先安排替代包。

**替换私钥**：旧 CSR 和证书不再匹配，依赖旧私钥的包可能无法恢复。旧私钥泄露时，还要请 CA 管理员处理证书吊销；生成新私钥不会替你完成吊销。

**删除全部凭证**：先确认 HTTP 管理入口可用，并安排仍需保留的配置包。点击“删除凭证”会一起删除设备私钥、设备证书和客户端 CA 链。公开证书备份不能恢复私钥。

删除后刷新检查材料是否缺失。正在运行的 HTTPS 服务可能仍持有旧凭证，删除存储不等于在线撤销。按提示重启，再确认旧凭证不再使用。需要恢复时，重新准备密钥、设备证书和 CA 链并测试。

## 6. 使用通用配置包前先看限制

Config Pack 是加密、签名的 `.tscfg` 文件。“配置包”区块中的通用操作，与第 4.5 节的“导入主机”不同。主机、命令、数据源、模板和规则的专用导入不能用通用入口的行为来判断。

### 6.1 各按钮实际做什么

| 操作 | 当前结果 |
|---|---|
| 导出设备证书 | 提供公开证书，供发送方为本设备制作包，不导出私钥 |
| 仅验证 | 检查结构和包内证书对应的签名，不确认签名者可信或目标设备匹配 |
| 在通用窗口选择或粘贴后导入 | 此入口目前不能完成导入 |
| 配置包列表中的导入 | 检查设备上已有文件，不复制、不解密、不应用配置 |
| 应用 | 会解密并列出配置类别，但尚未写入对应设置，仍可能提示成功 |
| Developer 导出配置包 | 生成包并保存到 SD 卡；成功后提供下载 |

> 不要用通用“应用”承担批量配置、灾难恢复或生效验收。即使显示成功，也应回到对应功能页设置并检查结果。

### 6.2 核对来源与目标

通用“仅验证”使用包内自带的签名者证书，尚未验证它是否由可信签发方签发。签名保护加密内容，不能据此认为所有显示信息都可信。“官方”文字、包名称和目标名称都不能代替来源核对。

通过资产记录或独立可信渠道，确认签名者证书指纹、接收设备证书和用途。同一条消息中的证书与指纹，不算独立核验。来源、目标或用途不清时停止。

### 6.3 提供设备证书与检查收到的包

**提供本设备证书**：点击“导出设备证书”，复制完整 PEM 和显示的指纹。把公开证书交给发送方，再通过另一可信渠道核对指纹。

**检查收到的包**：打开“导入配置包”，选择或粘贴文件，点击“仅验证”，查看签名信息并核对来源。这不会应用配置，也不证明本设备就是接收方。

验证通过后仍不能依赖通用“导入”“应用”完成设置。SSH 主机包应使用“导入主机”；其他配置使用对应功能页已支持的操作。

### 6.4 Developer 设备导出通用配置包

1. 准备 SD 卡上有效的 JSON 配置文件，并取得已核对的目标设备证书。
2. 点击“导出配置包”，选择文件。确认所需文件均已读入；有读取错误时，先处理错误，不要漏选所需内容。
3. 填写名称和说明，粘贴接收方证书，生成配置包。
4. 检查成功提示和设备保存路径，再点击“下载”，确认浏览器已保存 `.tscfg`。

此入口会保存到 `/sdcard/output_config/`。设备保存失败时，当前流程会报错，不会提供本次新包的下载；不要把先前结果当作本次成功。先检查 SD 卡及保存结果，再决定是否重新生成。

导出不修改源配置。目标填错或接收方证书更换时，应重新制作包。成功导出也不代表接收端的通用应用已可用。

## 7. 故障与安全事件处理

### 7.1 常见问题

| 现象 | 处理方式 |
|---|---|
| 看不到账号安全 | 该区块仅对 root 显示 |
| 提示身份验证或权限不足 | 核对登录账号和所需设备身份，不要靠重复点击绕过 |
| 生成或部署结果未确认 | 先查本地记录和远端结果，不重复提交 |
| 列表读取失败 | 修复连接后刷新；读取失败不等于列表为空 |
| 主机指纹变化 | 取消，先从可信渠道核对，见第 4.3 节 |
| 撤销后本地主机仍在 | 分别核对远端撤销和本地删除，见第 3.5 节 |
| 移除主机后仍能登录 | 还需撤销远端公钥，本地移除不会撤销授权 |
| 删除影响或配置包预览过期 | 重新检查，按新结果决定，不使用旧预览继续确认 |
| 证书已保存但 HTTPS 未运行 | 先确认固件启用 HTTPS，再核对时间、材料和启动提示 |
| 客户端拒绝证书 | 核对客户端信任、访问名称、用途和有效期 |
| 通用应用成功但设置没变 | 当前通用入口未写入设置，回到对应功能页操作 |

### 7.2 配置变化或操作结果不明

**编辑时提示配置已改变**：窗口中的输入可能仍在，但没有自动保存成草稿。先复制需要保留的内容到安全位置；关闭并重新打开编辑器，读取当前配置后再修改。不要把密码或私钥放进普通笔记。

**配置包预览失效**：点击“重新检查配置包”，重新阅读变更；设备凭证或配置已变化时，不能继续使用旧预览。

**删除检查失效**：点击“重新检查删除影响”，确认最新关联。已在另一窗口完成的操作可能改变结果。

**超时、断线或没有完整结果**：先查看当前配置、密钥、证书或远端授权。没有收到确认不代表操作没有发生；核对后再决定是否重试。

### 7.3 私钥或密码可能泄露

1. 限制设备和相关资料的访问，保留必要调查记录。
2. SSH 私钥泄露时，从可信入口逐台撤销对应公钥，检查备份，确认旧密钥不能登录。
3. 用新 ID 生成 RSA 密钥并部署，验证后删除旧密钥和导出副本。
4. SSH 密码泄露时，从可信管理入口修改远端密码，检查登录记录。
5. 设备证书私钥泄露时，按第 5.6 节替换凭证，并请 CA 管理员处理吊销和旧配置包。

本地主机列表可能未覆盖所有曾授权的服务器，应结合服务器和资产记录清理。分享日志前检查其中是否含密码、密钥或其他敏感信息。

### 7.4 当前使用边界

使用前应接受第 1 章的 HTTP 和访问限制、第 3 章的首次部署信任方式，以及第 6 章的通用配置包限制。“隐藏”不构成访问控制。

本次核查的构建配置未启用 NVS Encryption、Flash Encryption 和 Secure Boot，不能承诺设备内密钥已受加密存储和安全启动保护。实际设备的固件与硬件安全设置还需另行核验。无法接受这些限制时，请安全负责人安排隔离或修复。

## 8. 适用范围与常用术语

### 8.1 本版指南的依据

本指南对应 TianshanOS 0.6.4，依据核查时上游代码及其中的中英文界面编写，核查日期为 2026-11-03。判断功能以已核查代码为准，不能仅凭版本号判断。

后续更新不一定影响本指南；如页面、步骤或结果不同，请结合实际界面和更新说明确认。本次文档检查不代替目标设备的 SSH 登录、远端授权、HTTPS 连接、重启或恢复验证。

### 8.2 常用术语

- **公钥 / 私钥**：公钥交给授权方，私钥保密；登录使用匹配的一对密钥。
- **指纹**：用于核对服务器或证书身份的摘要，不同显示格式需先统一。
- **CSR / CA**：证书签名申请，以及签发、验证证书的机构或相应证书。
- **CN / OU**：证书中的设备名称和组织单位；表单“部门”对应 OU。
- **SAN**：证书覆盖的访问域名或 IP 列表。
- **PEM**：带 BEGIN/END 标记的证书、申请或密钥文本。
- **mTLS**：连接双方都出示证书的认证方式。
- **NVS**：设备内部保存设置与密钥的区域，名称本身不表示已加密。
