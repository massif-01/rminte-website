# TianshanOS root 運用ガイド

root アカウントで TianshanOS を管理する運用担当者向けのガイドです。第 1 部は admin と root 共通の日常機能、第 2 部は root 専用のターミナル（「终端」）、コマンド（「指令」）、自動化（「自动化」）を説明します。セキュリティ管理は『TianshanOS セキュリティガイド』をご覧ください。

<!-- operational-note -->

root は機器、リモートホスト、自動化フローに大きな影響を及ぼす操作を実行できます。対象機器、ホスト、実行中のタスクを確認してから操作してください。

画面に実際に表示される機能に従ってください。ハードウェアの接続や設定後に表示されるボタンもあります。

このガイドでは操作名の訳と機器画面の中国語ラベルを併記します。機器 WebUI の対応言語は中国語と英語であり、サイトの言語切り替えで機器の対応言語が増えるわけではありません。

## 第 1 部：admin と root 共通の日常機能

## 1. 使い始める

### WebUI を開く

1. 管理者から案内された機器の Web アドレス（WebUI）をブラウザーで開きます。
2. 画面右上のログイン（「登录」）を選択します。
3. `root` と機器に付属する root パスワードを入力します。
4. ログイン（「登录」）を選択します。ログインすると、右上に現在のユーザー名が表示されます。

初期パスワードで初めてログインすると、セキュリティの通知（「安全提醒」）が表示されます。現在のパスワードと新しいパスワードを入力し、今すぐ変更（「立即修改」）を選択できます。新しいパスワードは確認用と合わせて同じものを 2 回入力してください。後で変更（「稍后修改」）を選ぶと通知を閉じます。

使い終わったら、右上のログアウト（「退出登录」）を選択します。次に機器を操作するときは、再度ログインが必要です。

### 言語を切り替える

画面上部の言語ボタンを選び、メニューから中文または English を選択します。画面の内容とボタン名が選んだ言語に切り替わります。

### ページを移動する

root が使える主なページは次のとおりです。

- システム（「系统」）：機器の状態を確認し、モジュール、ファン、LED を操作します。OTA 更新もここから開きます。
- ネットワーク（「网络」）：Ethernet と DHCP の状態を確認し、WiFi と NAT 転送を設定します。
- ファイル（「文件」）：SD カードと SPIFFS のファイルを管理します。
- ターミナル（「终端」）：機器コンソールとシステムログを使います。
- 自動化（「自动化」）：データソース、変数、アクションテンプレート、ルールを管理します。
- コマンド（「指令」）：リモート SSH コマンドを管理・実行します。
- セキュリティ（「安全」）：専用のセキュリティ管理ページを開きます。詳しい操作はセキュリティガイドをご覧ください。

## 2. システムの状態確認と基本操作

上部ナビゲーションのシステム（「系统」）を選択します。

### リソースとサービスの状態を確認する

リソースモニター（「资源监控」）には CPU、DRAM、PSRAM の使用状況が表示されます。DRAM と PSRAM は、機器がプログラムの実行に使うメモリーです。

- 詳細（「详情」）でメモリーの総容量、使用量、空き容量、断片化率を確認できます。
- サービス（「服务」）ボタンの横には、稼働中のサービス数と総サービス数が表示されます。
- サービス（「服务」）で各サービスの状態、段階、健全性を確認できます。

サービスが失敗（「失败」）または健全性に異常がある状態の場合は、まずページを更新して現在の状態を確認してください。

### システムと電源の情報を確認する

システム概要（「系统总览」）にはチップ、ファームウェアのバージョン、稼働時間、ビルド日時が表示されます。電源状態（「电源状态」）には入力電圧、内部電圧、電流、電力、保護状態が表示されます。

保護状態の横のスイッチで低電圧保護を有効または無効にできます。有効にすると、入力電圧が下がりすぎたときに、設定済みのシャットダウンと復旧処理を実行します。

### ネットワークと時刻を確認する

ネットワークと時刻（「网络与时间」）には Ethernet、WiFi、IP アドレス、現在時刻、同期状態、時刻の取得元、タイムゾーンが表示されます。

- 時刻を同期（「同步时间」）でブラウザーの現在時刻を機器に反映します。
- タイムゾーン（「时区」）でプリセットを選ぶか、画面が対応するタイムゾーン設定を入力して保存します。
- OTA 更新（「OTA 升级」）でファームウェア更新ページを開きます。

### 詳細操作

#### TianshanOS を再起動する

再起動中は WebUI、ターミナル、自動化、機器の管理機能が一時的に使えなくなります。作業が完了していることを確認してから、再起動（「重启」）を選択し、確認します。再起動中の案内が表示されます。機器が復旧したら WebUI を開き直してください。

#### 個別のサービスを再起動する

サービスを再起動すると、そのサービスの機能が一時的に停止します。サービス状態（「服务状态」）で対象サービスを探し、その行の再起動（「重启」）を選択します。完了後に状態と健全性を確認し直してください。

#### シャットダウン設定を変更する

電圧が低下したときにいつ機器を停止し、電源が回復したときにいつ起動するかを設定します。電圧と待機時間は機器の電源要件に合わせて指定してください。

シャットダウン設定（「关机设置」）で次の項目を変更できます。

- 低電圧しきい値（「低电压阈值」）：この電圧を下回るとシャットダウンのカウントダウンを開始します。
- 復旧電圧しきい値（「恢复电压阈值」）：この電圧を上回ると復旧処理を開始します。
- シャットダウンまでの時間（「关机倒计时」）：低電圧を検知してから停止するまでの待機時間です。
- 復旧安定待機時間（「恢复稳定等待」）：電圧の回復後、電源が安定したことを確認するための待機時間です。
- ファン停止遅延（「风扇关闭延迟」）：シャットダウンからファン停止までの待機時間です。

保存すると、新しい保護設定が適用されます。

#### 上部 USB ポートの接続先を切り替える

<!-- operational-note -->

USB の接続先を切り替えると、接続中の周辺機器が一時的に切断されることがあります。接続先と進行中の作業を確認してから操作してください。

USB 切り替え機能が表示されている場合、「USB」ボタンを押すたびに上部 USB ポートの接続先が ESP、AGX、LPMU の順に切り替わります。ボタンには現在の接続先が表示され、切り替えが成功すると画面に通知されます。

## 3. デバイスパネル

システム（「系统」）ページのデバイスパネル（「设备面板」）には、モジュールの電源操作、クイックアクション、データウィジェットがあります。

### AGX と LPMU を操作する

AGX と LPMU のボタンは現在の状態を示します。緑は稼働中、赤は電源オフ、検出中は待機状態を表します。

<!-- operational-note -->

強制的に電源を切ると、未保存のデータが失われるおそれがあります。電源を切る前に、モジュール上の作業を保存し、通常のシャットダウンを完了してください。

- AGX の状態ボタンで AGX の電源を入れたり切ったりできます。画面に最終結果が表示されるまで待ちます。
- LPMU の状態ボタンは、物理電源ボタンを 1 回押すのと同じ操作を行います。その後も状態の検出が続きます。検出がタイムアウトした場合は画面の案内に従い、続けて何度も押さないでください。

### クイックアクションを使う

クイックアクション（「快捷操作」）には、手動トリガー専用（「仅手动触发」）に設定された自動化ルールが表示されます。

1. カードを選択して操作を実行します。
2. 処理中と表示されている間は、完了を待ちます。
3. バックグラウンド実行に対応するカードには、実行状態とログ（「日志」）と停止（「停止」）が表示されます。
4. ログ（「日志」）で現在の出力を確認し、停止（「停止」）で実行中のタスクを終了します。

実行中のタスクを再実行するには、先に停止する必要があります。操作を開始したら、別の操作を始めるまで数秒待ってください。カードを長押しし、並べ替えの表示が出てからドラッグすると順序を変更できます。クイックアクションがありません（「暂无快捷操作」）は、設定済みの手動ルールが現在ないことを示します。設定方法は第 2 部の自動化管理をご覧ください。

### データウィジェットを管理する

データウィジェットはデバイスパネル（「设备面板」）に機器のデータを継続して表示します。

1. ウィジェット管理（「组件管理」）を選択します。
2. 更新間隔を選ぶか、自動更新を無効にします。
3. プリセットのウィジェットを追加するか、画面にある表示形式とデータソースを選択します。
4. 必要に応じて名前、表示方法、単位を編集し、保存します。

既存のウィジェットは編集、削除、並べ替えができます。カードを直接選択して編集画面を開くこともできます。長押ししてドラッグすると、パネル内の位置を変更できます。

## 4. ファン管理

システム（「系统」）ページのファン制御（「风扇控制」）には、現在の機器が提供するファンだけが表示されます。

### ファンの状態を確認する

上部のステータスバーには実効温度（「有效温度」）と目標速度（「目标转速」）が表示されます。カードのパーセント値は、自動・カーブモードでは目標制御値、手動モードでは現在の設定値を示します。RPM は実測の毎分回転数で、有効な測定値がある場合にのみ表示されます。パーセント値と RPM は異なる指標です。

自動モードでは、カーブに従って動作（「按曲线运行」）、適応制御（「自适应调速」）、保護動作中（「保护介入」）、温度無効（「温度失效」）といった状態や、安全基準温度、45 秒後の予測温度、温度上昇率が表示されることもあります。予測温度は、温度が上がる前に速度を調整するために使われます。温度無効（「温度失效」）と表示されたら、温度ソースが更新を続けているか確認してください。機器は保護用の速度設定を使います。カードの情報ボタンで自動モードの説明を確認できます。

右上の更新ボタンで現在の状態を取得し直せます。

### 動作モードを選ぶ

| モード | 動作 |
| --- | --- |
| オフ（「关闭」） | ファンを停止します。 |
| 手動（「手动」） | 固定の制御パーセント値を使います。スライダーで 0-100% に設定できます。 |
| 自動（「自动」） | ファンカーブを基に、温度の変化傾向と保護状態に応じて速度を調整します。 |
| カーブ（「曲线」） | 設定した温度と速度の対応関係に従って動作します。 |

<!-- operational-note -->

ファンを停止したり手動速度を低くしすぎたりすると、冷却能力が下がります。変更前に負荷と温度を確認し、変更後も温度を監視してください。

手動（「手动」）モードでは速度調整（「转速调节」）スライダーを動かして設定します。他のモードではスライダーは使えません。

### ファンカーブを設定する

ファン制御（「风扇控制」）の見出しにあるカーブ（「曲线」）でファンカーブ管理（「风扇曲线管理」）を開きます。ファンカード内のカーブ（「曲线」）は、動作モードを切り替えるボタンです。

1. ファンを選択（「选择风扇」）で対象番号を選び、システムページのカードと照合します。
2. 温度変数の割り当て（「绑定温度变量」）に温度ソースを 1 つ以上追加し、重みを設定します。
3. すべて割り当て（「绑定全部」）で温度ソースを適用します。このソースは自動・カーブモードのファンで共有されるため、変更はそれを使うすべてのファンに影響します。
4. 温度・速度カーブ（「温度-转速曲线」）で点を追加または編集します。1 つのカーブには最低 2 点が必要で、最大 10 点まで設定できます。
5. 最小デューティ比（「最小占空比」）と最大デューティ比（「最大占空比」）を設定します。最小値は最大値以下にしてください。
6. 必要に応じて温度ヒステリシス（「温度迟滞」）と最小間隔（「最小间隔」）を設定します。範囲はそれぞれ 0-20°C、500-30000 ms です。
7. カーブを適用（「应用曲线」）を選択します。設定が保存され、対象ファンがカーブ（「曲线」）モードに切り替わります。

最小デューティ比（「最小占空比」）と最大デューティ比（「最大占空比」）は制御パーセント値の範囲を指定します。温度ヒステリシス（「温度迟滞」）は小さな温度変動による頻繁な速度変更を抑えます。最小間隔（「最小间隔」）は速度変更と次の変更の間に設ける最短時間です。1000 ms は 1 秒です。

カーブを適用するとカーブモードになります。自動制御を続ける場合は、ファンカードに戻り自動（「自动」）を選択してください。

### カーブをインポート・エクスポートする

- 設定をインポート（「导入配置」）で有効なカーブ JSON ファイルを選びます。読み込んだカーブとパラメーターを確認し、カーブを適用（「应用曲线」）で反映します。
- 設定をエクスポート（「导出配置」）で現在のカーブをブラウザーにダウンロードします。同時に SD カードの `/sdcard/config` にコピーの保存を試み、結果が画面に表示されます。

### テスト温度を使う

<!-- operational-note -->

テスト温度は通常の温度ソースを一時的に置き換え、自動・カーブ制御に影響します。テスト中はファンと機器の状態を監視してください。

1. テスト温度（「测试温度」）に 0-100°C の値を入力します。
2. テスト（「测试」）を選択し、目標速度とファンの応答を確認します。
3. 終了後はすぐにテストを解除（「清除测试」）を選び、通常の温度ソースに戻します。

## 5. LED 管理

システム（「系统」）ページの LED 制御（「LED 控制」）には、現在の機器が提供する LED だけが表示されます。

### 基本操作

- デバイスカードのスイッチで、その LED を点灯・消灯します。
- 明るさ（「亮度」）で対象の明るさを調整します。
- 色の制御に対応する機器では、色またはプリセット色を選択します。
- アニメーション効果（「动画特效」）の項目で再生し、アニメーションを停止（「停止动画」）で終了します。
- 設定を保存（「保存配置」）で現在の機器の LED 設定を保存します。
- すべて消灯（「全部关闭」）で画面に表示されたすべての LED を消します。

色、明るさ、アニメーションの選択肢は LED ごとに異なります。対象のカードと設定ダイアログにある項目に従ってください。

### LED マトリクスの詳細機能

LED マトリクスを搭載している場合、設定ダイアログには次の機能が表示されることもあります。

- 画像を表示（「显示图像」）：SD カードから画像を選択して表示します。
- QR コードを生成（「生成 QR 码」）：内容、色、誤り訂正レベルを設定して生成します。
- テキストを表示（「显示文本」）：文字を入力し、フォント、配置、スクロール速度、前景色、背景を設定します。
- 後処理フィルター（「后处理滤镜」）：画面にあるフィルターを適用します。停止ボタンで終了します。
- 色補正（「色彩校正」）：マトリクスの表示を調整し、画面のボタンで設定のリセット、インポート、エクスポートを行います。

マトリクスの寸法、アニメーション、フィルターは機器により異なります。実際に表示される機能に従って操作してください。

## 6. ネットワーク管理

<!-- operational-note -->

上部ナビゲーションのネットワーク（「网络」）でネットワーク設定（「网络设置」）を開きます。ネットワークモード、アクセスポイント、NAT を変更すると WebUI、ターミナル、自動化の接続が切れることがあります。保存前に、新しいネットワークアドレスから再接続できることを確認してください。

### ネットワークの状態を確認する

上部には Ethernet、WiFi クライアント、WiFi アクセスポイントの接続状態が表示されます。各パネルで IP アドレス、サブネットマスク、ゲートウェイ、DNS、MAC アドレス、SSID、信号、接続台数などを確認できます。

Ethernet パネルはリンクとアドレスの確認用で、アドレスの編集機能はありません。

### WiFi モードを選ぶ

| モード | 動作 |
| --- | --- |
| オフ（「关闭」） | WiFi を無効にします。 |
| ステーション（STA）（「站点 (STA)」） | 既存の WiFi ネットワークに接続します。 |
| アクセスポイント（AP）（「热点 (AP)」） | 機器が WiFi アクセスポイントになります。 |
| 「STA+AP」 | 既存の WiFi に接続しながら、機器のアクセスポイントも維持します。 |

<!-- operational-note -->

モードを選んだら状態の更新を待ちます。切り替え中は無線接続が一時的に切れることがあります。

### WiFi に接続する

1. WiFi モードをステーション（STA）（「站点 (STA)」）または「STA+AP」にします。
2. ステーション接続（「站点连接」）でスキャン（「扫描」）を選択します。
3. 一覧からネットワークを選びます。SSID、信号強度、チャネル、認証方式が表示されます。
4. パスワードを入力して確定します。オープンネットワークの場合は空欄にできます。
5. 接続済み（「已连接」）になるまで待ち、新しい IP アドレスを確認します。

切断（「断开」）で現在の WiFi クライアント接続を終了できます。

### WiFi アクセスポイントを設定する

1. WiFi モードをアクセスポイント（AP）（「热点 (AP)」）または「STA+AP」にします。
2. アクセスポイント（「热点」）で設定（「配置」）を選択します。
3. SSID を入力します。パスワードを空欄にするとオープンになります。設定する場合は 8 文字以上必要です。
4. チャネルを選び、必要に応じて SSID を非表示（「隐藏 SSID」）を有効にします。
5. 適用（「应用」）を選択し、状態の更新を待ちます。

デバイス（「设备」）で現在接続している機器を確認できます。

### ホスト名を設定する

ネットワークサービス（「网络服务」）のホスト名（「主机名」）に新しい名前を入力し、設定（「设置」）を選択します。更新後、現在のホスト名が表示されます。

### DHCP クライアントを確認する

DHCP は接続機器にネットワークアドレスを自動で割り当てます。クライアント（「客户端」）で「WiFi AP」または「Ethernet」を選び、現在の割り当て記録を確認します。更新ボタンで一覧を読み込み直せます。

### ネットワークの詳細操作

#### NAT ゲートウェイを設定する

NAT は機器のネットワークインターフェース間でトラフィックを転送します。有効・無効を選んだら、保存（「保存」）で設定を保持します。操作後に WiFi と Ethernet の状態を確認してください。

#### LPMU 経由で上位ネットワークに接続する

上位ネットワークへの接続（「接入上层网络」）が表示される場合は、LPMU 経由で接続（「通过LPMU接入」）を選択します。処理中（「处理中」）から成功（「成功」）または失敗（「失败」）に変わるまで待ってください。処理中に再実行しないでください。失敗したら、画面のエラーと出力を確認します。

## 7. ファイル管理

上部ナビゲーションのファイル（「文件」）でファイル管理（「文件管理」）を開きます。

SD カードは着脱式ストレージ、SPIFFS は機器内部のファイルストレージです。SD カード（「SD 卡」）または「SPIFFS」で切り替えます。上部に現在のフォルダーのパスが表示され、パス内のフォルダー名を選ぶと、その階層に戻れます。

### ファイルを閲覧・管理する

- フォルダー名を選択して開きます。
- ファイル右側のダウンロードボタンで、ブラウザーのダウンロード先に保存します。
- 名前変更ボタンで新しい名前を入力し、確定します。
- 新規フォルダー（「新建文件夹」）で名前を入力して作成します。
- 更新ボタンで現在のディレクトリとストレージ状態を再読み込みします。

### ファイルをアップロードする

1. 保存先ディレクトリを開きます。
2. ファイルをアップロード（「上传文件」）を選択します。
3. アップロード領域を選んで 1 つ以上のファイルを指定するか、そこにドラッグします。
4. 一覧を確認し、不要なファイルを外します。
5. アップロード（「上传」）を選び、各ファイルが完了するまで待ちます。`.tscfg` 設定パッケージをアップロードすると、検証と適用の手順が始まります。入手元、署名、適用条件についてはセキュリティガイドをご覧ください。

### 一括操作

ファイルやフォルダーを選択すると、一括操作のツールバーが表示されます。

- 一括ダウンロード（「批量下载」）は選択したファイルをダウンロードします。フォルダーは対象外です。
- 一括削除（「批量删除」）は選択したファイルとフォルダーを削除します。
- 選択を解除（「取消选择」）は現在の選択をすべて解除します。

### ファイル・フォルダーを削除する

削除は WebUI から取り消せません。フォルダーを削除すると中身もすべて削除されます。名前とパスを確認してから削除（「删除」）または一括削除（「批量删除」）を選び、確認してください。

### SD カードをマウント・アンマウントする

アンマウントすると、SD カード内のファイルに一時的にアクセスできなくなります。アップロード、ダウンロードなどのファイル操作がないことを確認してから、SD をアンマウント（「卸载 SD」）を選択してください。

未マウント時は SD をマウント（「挂载 SD」）が表示されます。選択し、マウント済み（「已挂载」）になるまで待ってから SD カードのディレクトリを開き直します。

## 8. OTA 更新

システム（「系统」）ページのネットワークと時刻（「网络与时间」）で OTA 更新（「OTA 升级」）を選び、ファームウェア更新（「固件升级」）を開きます。

更新中に機器は再起動し、WebUI、ターミナル、自動化の接続が一時的に切れます。作業を保存し、安定した電源を確保してから開始してください。更新が完了するまで電源を切らないでください。

### OTA サーバーから更新を確認する

1. 現在のバージョン（「当前版本」）を確認します。
2. OTA サーバー（「OTA 服务器」）に管理者または配布元から案内されたアドレスを入力します。
3. 保存（「保存」）、続けて更新を確認（「检查更新」）を選択します。
4. 新しいバージョンの有無、最新である旨、サーバーのバージョンが古い旨、またはエラーが表示されます。
5. 更新先を確認し、今すぐ更新（「立即升级」）または画面の更新ボタンを選択します。
6. ダウンロード、インストール、再起動の完了を待ちます。中止ボタンがある場合は、中止に対応した段階で停止できます。
7. 機器がオンラインに戻ったら WebUI に再接続し、現在のバージョン（「当前版本」）を確認します。WebUI を含む場合はファームウェアと WebUI が順に更新されます。両者は同じリリースのものを使ってください。

### 手動更新

手動更新（「手动升级」）を展開し、次の方法を選択できます。

- URL から更新（「从 URL 升级」）：ファームウェアの URL を入力し、リリースの説明に従って WebUI を含める（「包含 WebUI」）を選び、更新（「升级」）を実行します。
- SD カードから更新（「从 SD 卡升级」）：`/sdcard/firmware.bin` などのパスを入力します。WebUI を含める（「包含 WebUI」）を選ぶと、同じディレクトリの WebUI ファイルも処理します。

URL から更新するときの検証をスキップ（「跳过验证」）は、HTTPS サーバー証明書の検証を省略します。この場合、証明書によるダウンロードサーバーの身元確認ができません。通常の更新では選択しないでください。証明書エラーが出た場合は、管理者にサーバーアドレスと証明書の確認を依頼してください。

### パーティション管理とロールバック

パーティション管理（「分区管理」）には実行中のパーティションと他の利用可能なパーティションが表示されます。

- 有効とマーク（「标记有效」）は現在のバージョンを承認し、そのバージョンの自動ロールバック保護を解除します。正常な動作を確認してから実行してください。
- このバージョンにロールバック（「回滚到此版本」）は別の起動可能なバージョンを選び、再起動で切り替えます。現在のサービスが中断するため、対象バージョンとデータの互換性を先に確認してください。

操作と再起動の完了後、WebUI を開き直し、バージョンと機器の状態を確認します。

## 9. セキュリティ管理を開く

上部ナビゲーションのセキュリティ（「安全」）で管理ページを開きます。SSH 鍵、リモートホスト、ホストのフィンガープリント、HTTPS 証明書、設定パッケージ、アカウント管理については『TianshanOS セキュリティガイド』をご覧ください。本ガイドでは重複して説明しません。

## 第 2 部：root 専用の運用機能

## 10. ターミナルとシステムログ

ターミナル（「终端」）は root にだけ表示されます。機器のコンソールコマンドを直接実行し、ログを確認できます。コマンドは機器の状態を即座に変える場合があります。入力前に出所、引数、影響を確認してください。

### ターミナルに接続して使う

1. 上部ナビゲーションのターミナル（「终端」）を選択します。
2. 接続済み（「已连接到设备」）と `tianshan>` プロンプトが出るまで待ちます。
3. `help` を入力し、現在のファームウェアが提供するコマンドを確認します。
4. コマンドを入力して Enter を押し、出力が終わりプロンプトが戻るまで待ちます。

未接続（「未连接到设备」）の間、入力は実行されません。切断すると再接続の案内が出ます。復旧してから送信し、重複実行を避けてください。

次のキー操作が使えます。

| 操作 | 動作 |
| --- | --- |
| Ctrl+C | 現在の入力を消し、コマンドの中断を要求します。止まるかどうかはコマンドの中断対応に依存します。 |
| Ctrl+L | 画面を消去します。 |
| ↑ / ↓ | 今回のページセッション内のコマンド履歴を参照します。 |
| ← / → | 入力内のカーソルを移動します。 |

上部の画面消去（「清屏」）は表示だけを消し、実行済み操作は取り消しません。切断（「断开」）はターミナル接続を終了します。

### リモート SSH Shell を使う

SSH Shell では以後のキー入力がリモートホストに送られます。アドレス、ユーザー、認証方式を確認し、セキュリティガイドの SSH 準備を完了してから接続してください。

1. `ssh --help` で説明を確認します。
2. `ssh --host <主机地址> --user <用户名> --shell` の形式で実際のアドレスとユーザー名を指定します。山括弧とその中の文字をすべて置き換えてください。ポート指定が必要なら --shell の前に `--port <端口>` を加え、ポート番号に置き換えます。
3. 接続成功の表示を待ってからリモートコマンドを入力します。
4. Ctrl+\ で SSH Shell を終了し、tianshan> に戻ります。

画面共有、録画、他人が見られるターミナルで平文の認証情報を入力しないでください。

### システムログを見る

上部のシステムログ（「系统日志」）でログウィンドウを開きます。

- レベル（「级别」）：表示する最低レベルを指定します。ERROR、WARN+、INFO+、DEBUG+ で範囲を絞れます。
- 「TAG」：ログの発生元で絞り込みます。
- 検索（「搜索」）：現在のログをキーワードで絞ります。
- 自動スクロール（「自动滚动」）：最新ログを追従表示します。
- 更新ボタン：履歴ログを読み直します。
- 消去ボタン：現在のウィンドウの表示だけを消します。

何も表示されない場合は TAG とキーワードを空にし、レベルを調整してください。ウィンドウを閉じてもサービスは停止しません。

## 11. リモートコマンドの管理と実行

コマンド（「指令」）では再利用する SSH コマンドを保存し、選んだリモートホストで実行します。ホストと認証情報はセキュリティ（「安全」）で管理します。手順はセキュリティガイドをご覧ください。

### ホストを選んでコマンドを確認する

1. 上部ナビゲーションのコマンド（「指令」）を選択します。
2. ホスト選択（「选择主机」）から対象を選びます。
3. コマンド一覧（「命令列表」）で登録内容を確認します。

孤立コマンド（「孤儿命令」）は参照先ホストがなくなったコマンドで、実行できません。削除するか、インポート時のホスト割り当てで有効なホストに関連付け直してください。

### コマンドを作成・編集する

保存したコマンドはリモートで実行されます。事前に対象ホストでコマンドと権限を手動確認し、削除、電源オフ、再起動、ファイル上書きなどを誤操作しやすい形で登録しないでください。

1. ホストを選び、新規作成（「新建指令」）を選択します。編集時は対象の編集ボタンを使います。
2. コマンド ID（「指令 ID」）を入力します。一意である必要があり、英字、数字、アンダースコア、ハイフンだけを使えます。先頭と末尾はアンダースコア・ハイフンにできません。
3. 名前（「指令名称」）と「SSH 命令」を入力します。複数行の場合は 1 行に 1 コマンドを記述します。
4. 必要なら説明とアイコン、または SD カードの画像を選びます。
5. 詳細オプションを確認して保存（「保存」）します。

名前は識別用、ID は自動化からの参照用です。既存 ID は読み取り専用です。新しい ID が必要なら新規作成し、アクションテンプレートとデータソースの参照も確認してください。

### 実行結果を確認する

1. コマンドカードの実行ボタンを選択します。
2. 実行結果（「执行结果」）で出力と状態を確認します。
3. キャンセル（「取消」）があれば、まだ実行中のセッションを終了できます。
4. 消去（「清除」）は現在の結果表示を消します。

消去してもリモートで完了した操作は戻りません。成功・失敗、抽出内容、最終状態はコマンドの照合設定によって決まります。

### 結果の照合を設定する

リモート出力を判定しやすい状態に変換する機能です。

- 成功パターン（「成功匹配模式」）：指定テキストを含むと成功になります。
- 失敗パターン（「失败匹配模式」）：指定テキストを含むと失敗になります。
- 抽出パターン（「提取模式」）：1 つの `(.*)` キャプチャグループで対象内容を保存します。
- 一致後に自動停止（「匹配后自动停止」）：一致すると継続中のコマンドを終了します。
- タイムアウト（「超时」）：指定時間内に一致しなければ待機を終えます。成功・失敗パターンを設定した場合、または自動停止を有効にした場合だけ有効です。
- 保存先変数名（「存储变量名」）：状態と抽出結果を保存し、自動化で選べるようにします。

成功・失敗には安定した明確な出力を使ってください。広すぎる文言は誤判定の原因になります。保存後に一度実行し、照合結果（「匹配结果」）を確認してからルールに使います。

### バックグラウンド実行とサービスモード

nohup は SSH 切断後もリモートでコマンドを継続させる仕組みです。WebUI を閉じても自動停止しません。バックグラウンド実行（「后台执行（nohup）」）では次が使えます。

- ログ表示（「查看日志」）：現在のログを読みます。
- リアルタイム追跡（「实时跟踪」）：ログを継続更新します。
- 追跡停止（「停止跟踪」）：画面の更新だけを止め、リモートタスクは止めません。
- プロセス確認（「检查进程」）：まだ動作中かを調べます。
- プロセス停止（「停止进程」）：対応するタスクを終了します。

サービスモード（「服务模式（监测就绪状态）」）は、利用可能になるまでバックグラウンドタスクを監視します。準備完了パターンと保存先変数名は必須です。失敗パターンと待機設定は必要に応じて調整します。

- 準備完了パターン（「就绪匹配模式」）：ログに現れると準備完了とします。複数は `|` で区切ります。
- 失敗パターン（「失败匹配模式」）：ログに現れると失敗とします。
- タイムアウト（「超时」）：準備完了を待つ最大時間です。
- 検出間隔（「检测间隔」）：ログ確認の頻度です。
- 保存先変数名（「存储变量名」）：checking、ready、timeout などを保存します。

追跡停止とプロセス停止は別です。閲覧を終えるときは追跡停止、タスクを終了してよいと確認できたときだけプロセス停止を使います。

### コマンドをインポート・エクスポートする

- コマンドのエクスポートボタンで取り出せます。画面の選択肢に応じて、依存するホスト設定も含められます。
- インポート（「导入指令」）で `.tscfg` を選び、プレビューして、必要に応じて既存設定を上書きするか表示されたホストに割り当てます。

同名設定が上書きされ、リモートホスト情報が含まれる場合があります。署名、証明書の信頼、出所はセキュリティガイドに従って確認してください。再起動が必要なら、先にターミナルと自動化タスクを終了します。

削除前にデータソースやアクションテンプレートから参照されていないことを確認してください。コマンドページから削除を取り消すことはできません。

## 12. 自動化管理

自動化（「自动化」）はデータと操作を繰り返し実行できるフローに結び付けます。

```text
自動実行：データソース → 変数 → ルール判定 → アクション実行
手動実行：システムページのクイックアクション → アクション実行
```

- データソースは外部または機器のデータを読みます。
- 変数は判定に使う値を保持します。
- ルールは実行するタイミングを決めます。
- アクションテンプレートは実行内容を定義します。
- 手動専用ルールはシステムページのクイックアクションに表示されます。

### 自動化エンジンの確認と操作

上部にはエンジン状態、ルール数、変数数、データソース数、トリガー回数、稼働時間が表示されます。

| 操作 | 影響 |
| --- | --- |
| 起動（「启动」） | 停止中のエンジンを起動し、有効なルールを処理します。 |
| 一時停止（「暂停」） | 後続の自動判定を止め、設定を保持します。開始済みアクションは続く場合があります。再開は「停止」、次に「启动」の順です。 |
| 停止（「停止」） | ルール処理とデータソースの読み取りを停止します。設定は削除しません。 |
| 再読み込み（「重新加载」） | 保存済み設定を読み直します。稼働中なら読込後に再開します。先に編集内容を保存してください。 |

冷却、警報などの継続タスクが自動化に依存していないか確認してください。一時停止・停止でも、送信済みの非同期アクションやリモートプロセスの終了は保証されません。対応するタスク画面で確認し、操作後に状態を更新してください。

### 最小の自動化フローを作る

次の順をお勧めします。

1. データソースを作り、画面のテストで接続を確認します。
2. 有効にして、変数欄に必要な値が現れることと更新時刻を確認します。
3. アクションテンプレートを作り、引数を確認してテスト（「测试」）します。即座に実行されるため、機器とリモートホストで許可された操作か先に確認してください。
4. ルールを作り、今すぐ有効化（「立即启用」）はまだ選びません。
5. 条件、クールダウン、順序、遅延、繰り返しを確認します。
6. 保存後に有効化し、変数、トリガー回数、実際の結果を観察します。

### データソースを管理する

データソース（「数据源」）の追加（「添加」）で種類を選びます。

| 種類 | 用途 |
| --- | --- |
| 「REST API」 | HTTP アドレスから定期的にデータを取得します。 |
| 「WebSocket」 | 継続接続で配信されるデータを受信します。 |
| 「Socket.IO」 | Socket.IO サービスのイベントを受信します。 |
| コマンド変数（「指令变量」） | コマンドページに保存された実行結果を読みます。 |

REST API は URL に要求して取得する方法、WebSocket と Socket.IO は更新を継続受信する方法です。コマンド変数は設定済み SSH コマンドの結果です。

1. ID、表示ラベル、種類ごとの接続情報を入力します。
2. 接続テスト（「测试连接」）などのテストボタンを使います。
3. REST API、WebSocket、Socket.IO は結果から保存するフィールドを選びます。Socket.IO のイベント名が空なら、テストは配信イベントの検出を試みます。
4. コマンド変数は、ホストと保存先変数名を設定済みのコマンドを選び、検出間隔を設定します。
5. 保存・有効化後、変数欄で結果を確認します。

一覧には種類、状態、更新間隔が表示されます。有効化、無効化、変数表示、エクスポート、削除ができます。無効化・削除すると依存ルールが判定できなくなる場合があるため、先に参照を確認してください。

インポートとエクスポートには設定パッケージを使います。インポート前に ID、種類、対象を確認し、同名上書き前にルールの依存を確認します。信頼性についてはセキュリティガイドをご覧ください。

### 変数を確認する

変数（「变量」）には自動化で使えるデータが表示され、検索欄で名前を絞れます。

次を確認してください。

- 名前と所属データソースが意図どおりか。
- 値とデータ型がルールの比較に適するか。
- 更新時刻が継続して変わっているか。
- 期限切れや有効データなしの通知がないか。

更新されない場合はデータソースの有効状態を確認し、テストで接続とフィールド選択を調べます。

### アクションテンプレートの作成とテスト

ルールが発火したときのタスクを定義します。アクションテンプレート（「动作模板」）の追加（「添加」）で選びます。

| 種類 | 動作 |
| --- | --- |
| CLI コマンド（「CLI 命令」） | TianshanOS のローカルコンソールを実行します。 |
| SSH コマンド（「SSH 命令」） | コマンドページの登録済みリモートコマンドを実行します。 |
| LED 制御（「LED 控制」） | 対応 LED と表示機能を操作します。 |
| ログ記録（「日志记录」） | 指定レベルで 1 件のログを書きます。 |
| 変数設定（「设置变量」） | 指定値を自動化変数に書きます。 |
| 「Webhook」 | 指定 HTTP アドレスに要求を送ります。 |

CLI は機器内、SSH はリモートで実行します。Webhook は外部サービスの通知・呼び出しに使います。

一意の ID は必須です。表示名、説明、実行遅延を設定でき、必要に応じて非同期実行（「异步执行」）を有効にできます。送信後はバックグラウンドで継続するため、ログ、変数、対象機器で結果を確認します。

種類ごとの追加項目は次のとおりです。

- CLI：コマンド行、任意の結果変数とタイムアウト。
- SSH：画面のホスト・コマンド選択とプレビュー確認。
- LED：機器と、対応する色、アニメーション、明るさ、テキスト、画像、QR コード、フィルター操作。
- ログ：レベルとメッセージ。変数を参照できます。
- 変数設定：変数名と値。
- Webhook：メソッド、URL、要求内容。JSON は構造化した要求内容を書くテキスト形式です。

テストは即時実行します。電源オフ、再起動、リモートコマンド、LED 表示、外部要求の影響を確認し、テスト成功後にルールへ追加してください。

削除前にルールの参照を確認します。インポートは同名を上書きする場合があります。パッケージの信頼要件はセキュリティガイドをご覧ください。

### ルールを作る

ルールは変数条件とアクションテンプレートを結び付けます。

1. ルール（「规则」）の追加（「添加」）を選びます。
2. 一意のルール ID（「规则 ID」）、名前、アイコンを入力します。
3. 条件論理（「条件逻辑」）を選びます。
- AND：すべて満たすと発火します。
- OR：いずれかを満たすと発火します。
4. クールダウン（「冷却时间」）で連続発火の頻度を制限します。
5. 条件の変数、比較方法、値を設定します。
6. テンプレートを 1 つ以上追加し、順序に必要な遅延を設定します。
7. 内容を確認して保存し、実行するときに有効にします。

比較方法は等しい、等しくない、より大きい、以上、より小さい、以下、値の変化、含むです。比較値は変数の型に合わせてください。

### アクションの繰り返しと実行条件

各アクションで選べます。

- 1 回（「单次」）：ルールの発火ごとに 1 回実行します。
- 条件継続中の繰り返し（「条件持续时重复」）：個別条件を判定し、指定間隔ごとに継続します。1 回の実行サイクルで最大 100 回です。
- 回数指定（「指定次数」）：指定回数・間隔で繰り返します。

個別の実行条件とルール全体の発火条件は別設定です。条件継続中の繰り返しを使う前に個別条件を設定してください。空欄なら上限まで繰り返します。上限到達後もルールが再び発火する可能性があります。

ルール無効化は後続の自動発火だけを止め、開始済みサイクルは続く場合があります。止めるときは無効化して実行中のアクションを確認し、リモートタスクはコマンドページで対応プロセスを止め、終了を確認します。

### クイックアクションを作る

手動専用（「仅手动触发」）では発火条件が不要で、システムページにカードとして表示されます。

1. ルール ID、名前、アイコンを入力します。
2. 手動専用（「仅手动触发」）を選びます。
3. 必要なテンプレートを追加します。
4. 保存して有効にするとシステムページに表示されます。
5. システムのクイックアクションでカードを確認し、一度実行して結果を確かめます。

手動ルールも全アクション、遅延、繰り返しを実行します。admin に提供する前に、名前が明確で影響が予測でき、ログや停止手段が使えることを確認してください。

### ルールと設定を保守する

一覧から有効化、無効化、手動発火、編集、エクスポート、削除ができます。

- 手動発火は有効状態やクールダウンに関係なくアクションを実行します。無効ルールでも読み取り専用の確認ではありません。
- 無効化は後続の自動発火を防ぎ、完了済み操作は戻しません。
- 削除は画面から取り消せません。
- 編集時は変数とテンプレートがまだあることを確認します。
- インポート前に ID、条件、アクション参照を確認し、同名上書きの影響を確かめます。

データソース、アクション、ルールのインポート・エクスポート・変更後は、エンジン状態と一覧の有効状態を確認します。再読み込みや再起動が必要なら、先に実行中のリモートタスクを終了してください。
