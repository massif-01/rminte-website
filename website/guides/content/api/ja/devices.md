# 機器と名称

TianshanOS は、管理コントローラーと接続先のコンピューターを管理します。API を呼び出す前に操作対象を確認してください。対象が異なれば、状態値が示す意味も異なります。

| ユーザーに表示される名前 | API識別子 | 目的 |
| --- | --- | --- |
| 管理コントローラー | system.* | TianshanOS バージョン、メモリ、タスク、およびコントローラーの再起動 |
| 推論コンピューター | device:"agx" | 電源状態、電源操作、リセット。monitor.* は計算リソースのテレメトリを提供 |
| アプリケーションコンピューター | device:"lpmu" | 電源状態、電源制御、リセット、および上位レベルのネットワーク アクセスのセットアップ |
| 冷却ファン | fan.* と数値の id | RPM、制御モード、温度曲線、および出力制限 |
| タッチライト、ボードライト、マトリックスディスプレイ | touch, board, matrix | 色、効果、画像、QR コード、テキスト |
| ローカルストレージ | /sdcard/... などの対応するパス | ファイル、設定パッケージ、およびサポートされているアップデート資料 |
| リモートホスト | 保存済み SSH ホストの id/host | サーバー コマンドまたは管理対象プロセス。必ずしも内蔵コンピュータの 1 つである必要はありません |

API 識別子には agx と lpmu をそのまま使用します。たとえば、アプリケーションコンピューターを指定するときも `{"device":"lpmu"}` と記述します。

## 測定値を正しく解釈する

- **ファンのデューティ比**は出力の割合を示し、範囲は 0〜100 です。RPM は回転数です。デューティ比が不明な場合は null になることがあります。duty_valid も確認してください。
- **温度ソース**は、ローカル センサー、計算リソースのテレメトリ、変数、または手動テスト値の場合があります。ソース、有効なフラグ、およびタイムスタンプを確認してください。
- **power_good** は、ハードウェアに電源が供給されていることを示します。OS やアプリケーションの準備完了を示すものではありません。
- **USB 接続先**は共有 USB の接続経路を選択します。切り替えると、それまで使用していた経路の通信が中断されることがあります。
- **run_id** は、管理対象のリモートサービスを実行ごとに識別します。履歴が残っていても、そのプロセスが現在動作しているとは限りません。状態を確認してください。
- **操作受付情報**には、操作の識別子と結果照会用の認証情報が含まれます。表示名だけでなく、返された情報一式を保存してください。

## 完了までの 3 段階

1. API は、たとえば、started:true を返すことによってリクエストを受け入れます。
2. 機器の動作またはリモートプロセスが、要求した状態に到達します。
3. ヘルスチェックに合格するなどして、アプリケーションの準備が完了します。

タスクに必要なステージを確認します。コントローラーの再起動、コンピューターの電源投入、アプリケーションの起動は別の操作です。
