# 応答データモデル

以下のフィールドは `data` 内にあります。HTTP ステータスと `code` は [共通ルール](conventions.md) に従って処理してください。返されるフィールドは機器の状態、初期化の状況、ロールによって異なります。フィールドがない場合は不明として扱い、`0` や `false` で埋めてはいけません。

## 温度

| フィールド | 読み方 |
| --- | --- |
| `temperature_c` | 摂氏温度。同じ測定値を異なる単位で表します。 |
| `temperature_01c` | `0.1` ℃単位。`temperature_c` と同じ測定値です。 |
| `valid` | 値が使用可能かどうか。 `false` を通常の温度として扱ってはなりません |
| `source` | この測定値の取得元。解釈は API によって異なります。 |
| `active_source` | 実際の取得元。解釈は API によって異なります。 |
| `preferred_source` | 優先する取得元。解釈は API によって異なります。 |
| `timestamp_ms`、`last_update_ms` | Unix 時間ではなく、デバイスの起動からのミリ秒数 |
| `stale`、`age_ms` | データが古いかどうか／更新からの経過時間（ミリ秒）。`null` は一度も更新されていない場合があります |
| `partial_stale`、`valid_count`、`stale_count` | 複数変数のバインドの一部に問題がある状態。平均値だけでなく内訳も確認します |

有効な温度値には範囲の制限があります。入力元にはローカルセンサー、計算リソースのテレメトリ、変数、手動テストがあります。手動で設定した値は、実際の物理温度を確認したものではありません。

## ファン

`fan.status` の応答形式は、`id` の指定によって異なります。

- `id` を指定した場合：1 台のファン。
- `id` を省略した場合：`fans` に加え、`temperature`、`temp_valid`、`temp_source`。

| フィールド | 種類、単位、または意味 |
| --- | --- |
| `id` | ファン番号。 |
| `mode` | 制御モード：`off`、`manual`、`auto`、`curve`。 |
| `duty_valid` | 出力が有効かどうか。 |
| `duty` | 確認できた実際のデューティ比（%）。不明な場合は `null`。 |
| `target_duty` | 目標出力（%）。実際のデューティ比と異なる場合があります |
| `rpm` | 1 分間の回転数。回転数の取得機能や故障の有無と併せて判断します |
| `enabled` | ファンが有効かどうか。 |
| `running` | ファンが稼働中かどうか。不明な場合は `null` になることがあります。 |
| `fault` | 故障の状態。 |
| `temperature` | 関連する制御温度、摂氏 |
| `control_temperature` | 制御温度（℃）。 |
| `guard_temperature` | 保護温度（℃）。 |
| `predicted_temperature` | 予測温度（℃）。 |
| `slope_c_per_min` | 1 分あたりの温度勾配 (摂氏) |
| `auto_state` | 自動制御の段階。 |
| `guard_active` | 保護機能が作動中かどうか。 |
| `temp_stale` | 温度データが古いかどうか。 |
| `controller_gain`、`cooling_response` | RPM や温度ではなく、診断値 |

`applied` は適用、`persisted` は保存の結果を示します。`50`% を要求しただけでは、実際の出力が有効な `50`% になったことを確認できません。

## 電源

`power.status` は電圧、チップの測定値、保護状態、統計をまとめて返します。詳細は、電圧・チップ・`protection.status` の各 API を使用してください。

| フィールド | 単位または意味 |
| --- | --- |
| `voltage_v` | 電圧（V）。 |
| `current_a` | 電流（A）。 |
| `power_w` | 電力（W）。 |
| `voltage_mv` | mV; V と比較する前に変換する |
| `valid` | データの有効性。チップの測定値では両方を確認してください。 |
| `crc_valid` | 通信の整合性。チップの測定値では両方を確認してください。 |
| `timestamp_ms` | 開始からのミリ秒数 |
| `state` | 保護の段階。 |
| `countdown_remaining_sec` | カウントダウンの残り時間（秒）。 |
| `initialized` | 初期化が完了しているかどうか。 |
| `running` | 保護機能が動作中かどうか。 |

`device.power.status` は、電源系統ごとの測定値を返します。

| フィールド | 意味 |
| --- | --- |
| `voltage_mv` | 各系統の電圧（mV）。 |
| `current_ma` | 各系統の電流（mA）。 |
| `power_mw` | 各系統の電力（mW）。 |
| `total_power_mw` | 合計電力（mW）。 |

計算リソースのテレメトリでも mW が使われる場合があります。各フィールドの単位に従ってください。

## 設定の結果

設定の書き込みとソースの選択は、状態フラグのセットを返します。すべての応答にそれらがすべて含まれているわけではありません。

| フィールド | 意味 |
| --- | --- |
| `active_version` | 現在の設定バージョン。次の書き込みには新しい戻り値を使用します |
| `source` | アクティブな設定ソース |
| `loaded` | 読み込み済みかどうか。他の状態フラグとは別です。 |
| `configured` | 設定済みかどうか。他の状態フラグとは別です。 |
| `enabled` | 有効かどうか。他の状態フラグとは別です。 |
| `paused` | 一時停止中かどうか。他の状態フラグとは別です。 |
| `saved` | 保存が完了したかどうか。 |
| `uncertain` | 結果が不確かであること。 |
| `load_error` | 使用中の設定のエラー。 |
| `internal_error` | 内部バックアップのエラー。 |
| `sd_available` | SD が利用可能かどうか。 |
| `internal_exists` | 内部バックアップが存在するかどうか。 |
| `internal_valid` | 内部バックアップが有効かどうか。 |
| `comparison_known` | 比較できるかどうか。 |
| `backup_matches` | バックアップが一致するかどうか。不明を一致として扱ってはいけません。 |
| `awaiting_sd_choice` | SDの選択が必要です |
| `internal_saved_at` | 内部バックアップ保存時間情報 |
| `collection` | コレクションの場所。 |
| `id` | オブジェクトの場所。 |
| `dependency` | 依存関係の場所。 |
| `impact` | 削除・置き換えの影響を受ける参照と実行 |

プレビューで返される `package_digest` と `credential_generation` は適用時の前提条件であり、繰り返し使える共通の認可情報ではありません。`restart_required:false` だけでは、`loaded`/`enabled` や実行中の状態の確認を省略できません。

## 変数

変数には `name` と `type`/`value_type` が含まれます。次のフィールドが含まれる場合もあります。

| フィールド | 意味 |
| --- | --- |
| `value` | 変数の値。 |
| `source_id` | 取得元の識別子。 |
| `persistent` | 永続保存に関する情報。 |
| `readonly` | 読み取り専用かどうか。 |
| `flags` | 変数のフラグ。 |
| `last_change_ms`、`last_update_ms` | 変更・更新時刻のフィールド。 |
| `age_ms`、`stale` | 経過時間と、データが古いかどうか。 |

`variables.list` では、値の取得に `include_value`、メタデータの取得に `include_meta` を使います。`value` フィールドがないことと、値が `null` であることは別です。

## 証明書

`cert.status` は、次の情報をそれぞれ返します。

| フィールド | 意味 |
| --- | --- |
| `has_private_key` | 秘密鍵の有無。 |
| `has_certificate` | 証明書の有無。 |
| `has_ca_chain` | CA チェーンの有無。 |
| 証明書情報 | 証明書に関する情報。 |
| HTTPS 診断サービスの状態 | 独立した診断サービスの稼働状態。 |

証明書の有効性の判定には `time_ready` が影響する場合があります。未判定を有効として扱ってはいけません。

インストール済みの識別用証明書、HTTPS 診断サービスが実際に読み込んだ証明書、診断クライアント側の信頼設定は、それぞれ別に確認します。インストール後にサービスの状態を確認してください。管理 API は HTTP のままです。その Bearer ロールと mTLS 証明書のロールは別の体系です。

## カラー

RGB の各成分の範囲は `0`～`255` です。直接呼び出すカラー API は、次の形式に対応します。

- 対応する色の文字列。
- `r`、`g`、`b` を持つオブジェクト。
- `0xRRGGBB` に相当する 10 進整数。

JSON では 16 進数値リテラルを使用できません。`led.color.hsv` の範囲は次のとおりです。

| フィールド | 意味 |
| --- | --- |
| `h` | `0`～`359` 度。 |
| `s`、`v` | `0`～`255`。百分率ではありません。 |

色補正は、次の構造を持つオブジェクトで指定します。

| フィールド | 意味 |
| --- | --- |
| `enabled` | 色補正全体の有効・無効。 |
| `white_point` | 入れ子の `enabled`、`red_scale`、`green_scale`、`blue_scale`。各スケールの範囲は `0`～`2`。 |
| `gamma` | 入れ子の `enabled` と `gamma`。ガンマ値の範囲は `0.1`～`4`。 |
| `brightness`、`saturation` | それぞれ入れ子の `enabled` と `factor`。 |

変更する項目の入れ子のオブジェクトを送信してください。機器の明るさ（`0`～`255`）と補正係数は別の単位です。

## OTA

URL または SD から更新を開始した後は、`ota.progress` を読み取ります。返されるのは機器全体の状態で、ログインごとの個別の操作受付情報はありません。

| フィールド | 意味 |
| --- | --- |
| APP の進捗 | `state`、`percent`、`total_size`、`received_size`、`message`。 |
| WWW の進捗 | `state`、`percent`、`total`、`received`、`message`、`running`。 |

- APP：`pending_reboot` は再起動が必要な状態です。
- WWW：`state=completed` かつ `running=false` で完了を確認します。

`100`% という表示だけでは、新しいバージョンが動作中とは判断できません。

パーティション情報には、次の項目が含まれます。

| フィールド | 意味 |
| --- | --- |
| `label`、`address`、`size` | パーティションのラベル、アドレス、サイズ。 |
| 起動可否 | そのパーティションから起動できるかどうか。 |
| `version`、`project` | 取得可能なバージョン・プロジェクト情報。 |
| `can_rollback` | 現時点でロールバックできるかどうか。 |

`aborted` はキャンセル要求を受け付けたことを示します。引き続き進捗と実際の状態を確認してください。

バイナリアップロードでは専用の応答を使います。次の組み合わせは、フラッシュへの書き込みは済んだものの、SD 上の復旧キャッシュは完全に保存されていないことを示します。

- HTTP `409`。
- `status=partial`。
- `error=recovery_cache_failed`。
- `flash_written=true`。

再試行する前に、パーティションと復旧用ファイルを確認してください。

## ネットワーク

Ethernet では、インターフェースと設定の状態をそれぞれ確認します。

| フィールド | 意味 |
| --- | --- |
| `interface_present` | インターフェースが存在するかどうか。 |
| `link_up` | 物理リンクの状態。 |
| `config_error`、`config_error_name` | 設定適用時のエラー。 |

ケーブルが接続されているだけでは、IP 設定の成功は確認できません。

実際の状態、要求された状態、エラーが起きた段階を区別します。

| フィールド | 意味 |
| --- | --- |
| DHCP の `running` | 実際の状態。 |
| Ethernet の `want_running` | 要求された状態。 |
| `restore_error` | 設定の復元時のエラー。 |
| `apply_error` | 設定の適用時のエラー。 |
| `resume_error` | サービスの再開時のエラー。 |

`0` は、その段階でエラーが報告されなかったことを示します。サービスが動作すべき状態かを判断する前に、インターフェースとリンクを確認してください。
