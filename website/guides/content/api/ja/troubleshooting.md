# トラブルシューティング

メソッド、パス、HTTP ステータス、処理コード、理由、および操作受付情報を記録します。パスワード、トークン、秘密鍵、および完全な認証ヘッダーをサポート チケットに含めないようにしてください。

## 接続できません

現在の機器の HTTP アドレス（例：http://10.10.99.97）を使用します。既定のポートは 80 のため、通常は明記する必要はありません。アドレス、ネットワークの到達性、WebUI サービスの状態を確認してください。

443 の mTLS 診断ページにアクセスできても、管理 API が動作しているとは限りません。公開 API の system.info が応答することを確認した後、ログインと目的の機能を調べます。

## 認証・認可に失敗する

HTTP401 は通常、セッションが見つからない、無効である、または期限切れであることを意味し、403 は通常、権限が不十分であることを意味します。一部のハンドラーは、認証エラーを HTTP200 内のビジネス エラーとして報告します。

再ログインし、data.level を確認します。admin は ADMIN の設定・保守 API を使用できますが、SSH の直接実行、自動化定義の書き込み、一部のアカウント管理には ROOT が必要です。初期パスワードは rm01 です。変更済みの場合は現在のパスワードを使用してください。パスワードを変更すると、対象のセッションが無効になります。ログインがロックされた場合は解除を待ち、同時に何度も再試行しないでください。

## 温度またはテレメトリがありません

temp.sources の有効性、更新日時、経過時間、取得元を確認します。変数から取得する温度には一部だけ古い値が含まれる場合があるため、有効な重みや件数も確認してください。monitor.data は計算ホスト上の監視サービスに依存します。監視接続とアドレス設定を調べます。ハードウェアの電源が入っていても、テレメトリが届いているとは限りません。

## 受理されたが完了しない

操作受付情報または実行履歴を保存し、状態を照会します。SSH では最終状態、終了コード、出力が欠けていないかを確認します。管理対象サービスでは検証済みの状態を、OTA では機器全体の進捗、パーティションの状態、再起動後の実行バージョンを確認してください。started、cancel_requested、過去の履歴だけでは完了を判断できません。

## 設定が変更された

configuration_changed またはバージョンの競合が返された場合は、現在の状態と対象オブジェクトを読み直します。新しいバージョンを送信する前に、未保存の入力と比較して変更を統合してください。バージョントークンだけを置き換え、削除・インポート・上書きを再実行してはいけません。

## 保存に失敗したか、結果が不明です

applied、persisted、saved、uncertain、result_unknown と理由を確認します。保存が失敗していても、実行中の状態は変わっている場合があります。状態を読み直してから、必要に応じて保存済みの起動設定やバックアップを確認してください。通信が失敗しても、リクエストが何も変更しなかったとは限りません。

## SSH フィンガープリントが変更されました

自動再試行を停止し、サーバー管理者から現在のフィンガープリントを取得します。再インストール、交換、またはアドレスの再割り当てを確認してください。文書化された確認フィールドは、検証後にのみ使用してください。同一アドレスは同一ホストであることを保証しません。

## 処理中・利用枠の上限に達した

同時実行数を減らし、セッションを再利用し、不要な購読や端末を閉じます。進行中の処理を確認してください。クライアントが再試行を繰り返しても、タスクを無制限に待ち行列へ追加することはできません。自分のタスクの停止処理を待ち、別の接続の処理を引き継がないでください。

## アップロードまたは更新に失敗しました

ロール、リクエスト全体の送信、パス、SD の状態、空き容量、対象パーティションの容量、ハードウェアとパーティション構成に対応する完全なイメージを確認します。アップロードの成功は、パッケージの検証やインストールの成功を意味しません。SSH は保存した操作受付情報で結果を照会します。OTA は、再試行、ロールバック、復旧用ファイルの削除を行う前に、機器全体の進捗とパーティションの状態を確認してください。
