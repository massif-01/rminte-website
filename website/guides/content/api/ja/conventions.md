# API 呼び出しの共通ルール

## パスとメソッド

管理 API の URL は `http://10.10.99.97/api/v1/...` の形式です。論理名のドットをパスの区切りに置き換えます。たとえば fan.status は /api/v1/fan/status に対応します。key.exportPrivate や log.setLevel など、大文字と小文字を正確に記述してください。

各 API に記載されたメソッドのみを使用します。読み取りは通常 GET/POST、書き込みは通常 POST/PUT/DELETE に対応しますが、POST のみの API もあります。本ガイドでは、単純な照会には主に GET、操作には POST を使います。許可されていないメソッドでは HTTP405 が返されます。

実行内容はインターフェース名とパラメーターで決まります。DELETE が必ず削除、POST が必ず作成を意味するわけではありません。

## セッションとロール

認証が必要なリクエストには `Authorization: Bearer <token>` を付けます。トークンを URL に入れてはいけません。通常のリクエスト JSON にロールや session_id を指定しても、その利用者として認証されるわけではありません。

| アクセスラベル | 意味 |
| --- | --- |
| 公開 | この機能はログインせずにアクセスできます。リソース条件は引き続き適用されます |
| READ | 最低でも読み取り権限が必要です。認可済みの admin/root セッションは通常この条件を満たします |
| ADMIN | 日常的なデバイス操作。 admin または root が必要です |
| ROOT | コマンドの直接実行、自動化定義の書き込み、一部のアカウント管理。root が必要です |
| ボディトークン | 認証 API は JSON の token フィールドを検証します。未認証の利用者にアカウントの変更を許可するものではありません |

初期アカウントは admin/root で、どちらの初期パスワードも rm01 です。権限体系は READ/WRITE/ADMIN/ROOT を区別しますが、各レベルのアカウントを自由に作成できる API があるという意味ではありません。このバージョンでは、最低権限が WRITE の登録 API はありません。

リソースやパラメーターによっては追加の権限確認があります。通常のファイル読み取りは READ で可能な場合がありますが、機密性の高いパスには ADMIN が必要です。config.get は言語設定だけを未認証で公開し、他のキーには ADMIN を要求します。SSH ホスト・コマンド、ルール、アクションの全情報の読み取りには通常 ADMIN が必要で、automation.sources.list の秘密情報には ROOT が必要です。temp.bind は照会には ADMIN、バインドの変更には ROOT を要求します。automation.proxy.fetch はローカル API では呼び出し先の権限を適用し、外部サービスへのアクセスには ROOT を要求します。restricted:true はフィールドが除外されたことを示します。省略されたフィールドを空の値として保存し直してはいけません。

## パラメータ

Content-Type: application/json を指定し、リクエスト本文には JSON オブジェクトを送信します。配列はオブジェクトのフィールドに入れます。キーの重複や、クエリと本文で同じパラメーター名を使うことは避けてください。競合する指定は拒否されます。

クエリ値は一度デコードされ、整数またはブール値として解釈される場合があります。オブジェクト、配列、浮動小数点値、null、および先頭のゼロを保持する必要がある識別子には JSON を優先します。 URL エンコードを 2 回行わないでください。

Optional は、省略が許可されることを意味します。通常、null は省略と同等ではありません。一部のバインディング API では、明示的に null を使用してバインディングをクリアします。時間単位はフィールド固有です (ミリ秒、秒、または Unix 時間)。

## 結果の確認

通常の成功:

```json
{"code":0,"data":{"example":"value"}}
```

処理エラーでも HTTP200 が返される場合があります。

```json
{"code":1,"error":"invalid_request"}
```

説明は error または message に含まれる場合があります。data はオブジェクト、配列、または省略となる場合があります。成功した応答でも message があるとは限りません。

1. 成功以外の HTTP ステータスは、通信、権限、形式、またはサービスのエラーとして処理します。
2. code が存在し、その値が 0 以外なら、操作の処理エラーとして扱います。
3. 各 API の valid、success、exit_code、persisted、操作状態を確認します。最上位の成功だけでは、これらの確認を省略できません。
4. 非同期処理は、各 API が定める完了確認の手順に従います。操作受付情報が返された場合は保存してください。切断や result_unknown の後は、再試行する前に現在の状態を確認します。

ログイン、ログアウト、バイナリのアップロード、ダウンロードには専用の形式があります。正常にダウンロードされた本文には、JSON ではなくファイル バイトが含まれています。

## エラーコード

| コード | 名前 | 推奨される応答 |
| --- | --- | --- |
| 0 | OK | エンドポイントの完了条件を確認する |
| 1 | INVALID_ARG | フィールド、タイプ、範囲、およびバージョン条件を確認します |
| 2 | NOT_FOUND | オブジェクトや操作の情報を読み直します。ID を作り出したり、古い ID を再利用したりしてはいけません |
| 3 | NO_PERMISSION | ロール、機密リソース、およびエクスポート条件を確認する |
| 4 | BUSY | アクティブな作業を検査し、再試行する前に待機します |
| 5 | TIMEOUT | 書き込みを繰り返す前に結果が存在するかどうかを確認します |
| 6 | NO_MEM | リクエストのサイズまたは負荷を削減します。既知の結果を保存する |
| 7 | INTERNAL | 理由を保持します。 result_unknown の場合は状態を調査する |
| 8 | NOT_SUPPORTED | サポートされているエントリ ポイントを使用する |
| 9 | HARDWARE | デバイス、センサー、構成を検査する |
| 10 | CONNECTION | ネットワーク、リモート ホスト、フィンガープリント、サービスを確認します |
| 11 | AUTH | 再認証するか、必要な検証を完了します |

SSH の信頼確認では、未知のホストとフィンガープリントが変わったホストを示す 1001/1002 も使用し、フィンガープリントの詳細が返されます。信頼できる経路で本人性を確認してから承認してください。信頼記録を削除するだけでは、接続先を確認したことにはなりません。

## 適用と永続保存

applied は設定の適用、persisted または saved は保存の成功を示します。両者の結果は異なる場合があります。先の段階で変更が有効になった後にエラーが起きることもあるため、エラーの詳細を保存し、現在の状態を読み直してください。

切り替え操作、ルールの実行、リモートコマンド、更新は、繰り返しても安全とは限りません。読み取り専用の照会は、負荷を制御しながら再試行できます。書き込みがタイムアウトした場合は、まず状態や操作受付情報を照会してください。

## 制限

接続数、リクエスト本文のサイズ、受信時間、タスクの利用枠には上限があります。識別情報やサイズの検査で、本文をすべて受信する前にリクエストが拒否されることがあります。継続的な購読の代わりに、大量の照会を同時実行しないでください。

このバージョンの汎用 JSON ルートは、本文が最大 1 MiB、受信時間が最大 30 秒です。認証リクエストは 16 KiB・10 秒、設定パッケージ自体は 64 KiB に制限されます。各 API がさらに小さい上限を設けている場合もあります。バイナリ転送用のルートは [転送](transfers.md) を参照してください。

JSON の入れ子は最大 32 段です。埋め込まれた NUL、JSON の後ろに付いた不要なデータ、重複キーは拒否されます。HTTP413 の場合はリクエストを小さくするか、その機能で指定されたアップロード用ルートを使用してください。
