# 通用调用规则

## 路径和方法

业务入口形如 `http://设备地址/api/v1/…`。接口名称中的点对应路径分段，例如 `fan.status` 对应 `/api/v1/fan/status`。保留大小写：`key.exportPrivate`、`log.setLevel` 不能任意改写。

每个接口页列出允许方法。读取型通常允许 GET、POST；写入型通常允许 POST、PUT、DELETE，但有仅允许 POST 的接口。本文示例统一优先用 GET 查询、POST 执行，仍以各页为准。方法不允许会返回 HTTP 405。

这里使用名称式操作，不应推断“同一个路径 DELETE 必定删除对象”或“POST 必定创建对象”。动作由接口名称及参数定义。

## 会话和权限

需要登录的 HTTP 请求带 `Authorization: Bearer <token>`。不要把 Token 放入 URL；普通请求 JSON 中自报角色或 session_id 不会赋予该身份。

| 接口标注 | 含义 |
| --- | --- |
| 无需登录 | 可以匿名访问该项公开能力；资源相关条件仍适用 |
| READ | 至少读取权限；已获授权的 admin/root 通常满足 |
| ADMIN | 设备日常操作权限；需要 admin 或 root |
| ROOT | 原始命令执行、自动化定义写入及特定账户管理等权限；需要 root |
| 参数 Token | 认证类接口在 JSON 中校验 `token`，不等于匿名可以更改账户 |

默认账户为 admin/root，初始默认密码均为 rm01。接口策略仍区分 READ、WRITE、ADMIN、ROOT；这不表示设备提供创建任意这些级别账户的 API。本版本没有最低 WRITE 的注册项。

部分资源或参数还有额外权限：普通文件读取可允许READ，敏感路径需要ADMIN；config.get仅语言偏好公开，其他键需要ADMIN。SSH主机、命令、规则及动作等完整读取通常需要ADMIN；automation.sources.list的秘密字段仍需要ROOT。temp.bind查询可用ADMIN，修改绑定需要ROOT；automation.proxy.fetch转发本机API沿用目标权限，访问外部服务需要ROOT。restricted:true表示内容按角色裁剪；省略字段不能当作空值保存回去。

## 请求参数

普通带 body 的请求使用 `Content-Type: application/json`，body 必须是 JSON 对象。数组放在对象字段内。不要传重复键，也不要让 query 和 body 使用同名参数；冲突会被拒绝。

查询字符串会解码一次，并尝试解析整数和布尔。复杂对象、数组、浮点、空值及带前导零的标识建议放在 JSON body，明确保留类型。不要重复 URL 编码。

参数表的“可选”表示可以省略，不能推断 `null` 与省略相同。个别接口将 `null` 用于解除绑定，具体见接口说明。时间单位随字段区分 `ms`、`sec` 或 Unix 秒；没有单位的业务字段在各页注明。

## 判断请求结果

常规响应示例：

```json
{"code":0,"data":{"example":"value"}}
```

业务失败可能仍为 HTTP 200：

```json
{"code":1,"error":"invalid_request"}
```

`message` 与 `error` 都可能承载解释；客户端首先检查 `code`，再读取可用文字。`data` 可以是对象、数组，也可以不存在。不要要求每个成功响应都有 `message`。

处理顺序：

1. HTTP 非成功状态先处理传输、认证、权限、格式或服务状态。
2. 若存在 `code` 且非 0，按业务失败处理。
3. 按本接口检查 `valid`、`success`、`exit_code`、`persisted` 或任务状态；顶层成功不会替代这些判断。
4. 异步操作按对应接口的流程确认完成；返回回执时保存并用于查询。连接中断或 `result_unknown` 时先核验现状，再决定是否重试。

登录、退出、二进制上传和文件下载有专用响应，见对应页面；下载的响应体是文件内容，不能按 JSON 统一解析。

## 错误分类

| code | 名称 | 常见处理 |
| ---: | --- | --- |
| 0 | OK | 继续检查本接口业务完成条件 |
| 1 | INVALID_ARG | 检查字段、类型、范围和版本条件 |
| 2 | NOT_FOUND | 重新读取对象或任务，不要凭空复用旧 ID |
| 3 | NO_PERMISSION | 核对角色、文件敏感性、密钥导出条件 |
| 4 | BUSY | 查看当前操作状态，等待后重试 |
| 5 | TIMEOUT | 查询是否已有结果；写操作不要直接重放 |
| 6 | NO_MEM | 降低负载或请求大小，保留已知结果 |
| 7 | INTERNAL | 记录原因；若提示 result_unknown，先检查现状 |
| 8 | NOT_SUPPORTED | 使用受支持入口，不能反复重试解决 |
| 9 | HARDWARE | 检查设备/传感器状态和配置 |
| 10 | CONNECTION | 检查网络、远端地址、指纹与服务 |
| 11 | AUTH | 重新登录或完成所需身份验证 |

部分 SSH 信任流程还使用 1001/1002 表示未知或变化的主机指纹，并附带指纹信息。核对可信来源后再确认，不能通过清空信任记录自动消除风险。

## 副作用与保存

`applied` 表示本次设置已应用；`persisted` 或 `saved` 表示实现报告的保存结果。两者可能不同。设置失败也可能已经完成前半段操作，应保留返回的细节。

开关切换、规则触发、远端执行和升级不保证重复提交无副作用。常规查询可以按负载适当重试；控制请求超时先查询对象或操作回执。每个场景给出具体完成条件。

## 请求大小和服务资源

服务具有连接数、body 大小、读取期限和任务槽限制。身份检查与请求大小限制可能在读取完整 body 前拒绝请求。不要使用大量并发查询代替实时订阅，也不要把 `Content-Length` 当成服务器承诺接收的容量。

通用JSON路由上限1 MiB、接收期限30秒；认证请求另限16 KiB、10秒；配置包本身上限64 KiB。具体对象可另有更小限制，大文件与镜像见[文件和升级](transfers.md)。JSON 深度最多 32，不能发送内含 NUL、尾随垃圾或重复键的对象。收到 413 时缩小请求或使用该功能规定的专用上传流程。
