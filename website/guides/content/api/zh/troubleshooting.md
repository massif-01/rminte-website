# 故障处理

先记录请求方法、路径、HTTP 状态、业务 code、原因文字与操作回执；不要把密码、Token、私钥和完整认证头写入工单。

## 无法连接设备

确认使用设备当前的 HTTP 地址，例如 http://10.10.99.97。默认端口为80，无需额外填写端口号。检查客户端与设备网络可达、地址是否正确，以及WebUI服务是否运行。

能打开 443 的权限诊断页不能证明业务 API 已运行。能取得公开 `system.info` 后，再排查登录与具体功能。

## 登录失效或权限不足

HTTP 401 通常表示会话缺失/无效/过期；403 通常表示身份有效但等级不够。部分处理器也以 HTTP 200 加业务错误报告认证失败，要一起检查。

重新登录并检查 `data.level`。admin可执行标注ADMIN的配置与维护；原始SSH执行、自动化定义写入及特定账户管理仍要求ROOT。默认账户初始密码为 rm01；已改密时使用现有密码。改密码会撤销受影响账户的会话，旧 Token 与绑定它的连接不能继续当作有效授权。登录连续失败达到锁定条件时等待，不要由多个任务持续重试。

## 没有温度或监控数据

查看 `temp.sources` 的来源、有效性、更新时间和过期状态。变量来源还应检查部分失效与有效权重。`monitor.data` 依赖算力主机上的监控服务；确认监控连接和服务端配置。不要把“设备电源已开”当作“监控数据已到达”。

## 请求已接受但操作未完成

保留回执，查询操作或运行记录。SSH 看最终状态、退出码及输出是否完整；受管服务看核验后的运行状态；OTA 看操作结果与升级后的运行版本。只见 `started:true`、`cancel_requested:true` 或历史记录不代表目标已经达到。

## 配置已经变化

遇到 `configuration_changed` 或版本冲突，重新读取配置状态和相关对象，将未提交输入与现状对比，再用新的版本提交。不能直接替换版本号后自动重放删除、导入或覆盖请求。

## 保存失败或结果不明

检查 `applied`、`persisted`、`saved`、`uncertain`、`result_unknown` 及对应原因。有的操作运行态已改变但保存失败。先回读现状；涉及启动配置或备份时再核对保存状态。网络失败不能证明请求未执行。

## SSH 主机指纹变化

停止自动重试，从服务器管理方获得当前指纹，核对是否重装、换机或地址变化。按接口规定携带已确认指纹完成一次信任操作。先前信任的主机与现在相同地址上的主机不一定相同。

## 设备忙或连接已满

减少并发，复用连接，关闭闲置订阅或终端，查询正在运行的任务。HTTP/WS 及远端任务共享设备资源；任务不能因客户端重试而无限排队。退出自己的操作前确认其停止流程，避免接管其他连接的任务。

## 升级或文件传输失败

检查角色、请求完整性、文件路径、SD 状态、空间、分区尺寸以及适合当前硬件和分区的完整镜像。普通上传成功不等于包验证或升级成功。SSH结果丢失时用完整回执查询；OTA读取全局进度和分区状态；不要盲目再次刷写、回滚或删除恢复素材。
