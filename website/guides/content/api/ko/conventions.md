# API 호출 공통 규칙

## 경로 및 방법

장치 관리 API의 URL 형식은 `http://10.10.99.97/api/v1/...`입니다. 논리 이름의 점은 경로 구분자로 바뀝니다. 예를 들어 fan.status는 /api/v1/fan/status에 해당합니다. key.exportPrivate와 log.setLevel을 포함해 대소문자를 구분하세요.

각 API에 명시된 메서드만 사용하세요. 읽기는 일반적으로 GET/POST, 쓰기는 POST/PUT/DELETE를 허용하지만 POST만 허용하는 API도 있습니다. 이 가이드는 단순 조회에 주로 GET, 동작 실행에 POST를 사용합니다. 허용되지 않은 메서드는 HTTP405를 반환합니다.

실행되는 동작은 인터페이스 이름과 매개변수로 결정됩니다. DELETE가 항상 삭제를, POST가 항상 생성을 의미한다고 가정하지 마세요.

## 세션 및 역할

보호된 요청은 `Authorization: Bearer <token>` 를 전달합니다. URL에 토큰을 배치하지 마십시오. 일반 요청 JSON에 제공된 역할 또는 session_id는 해당 ID를 설정하지 않습니다.

| 액세스 라벨 | 의미 |
| --- | --- |
| 공개 | 이 기능은 로그인 없이 액세스할 수 있습니다. 자원 조건은 여전히 적용됩니다 |
| READ | 최소 읽기 권한이 필요합니다. 권한이 있는 admin/root 세션은 보통 이 조건을 충족합니다. |
| ADMIN | 일상적인 장치 작업이며 admin 또는 root가 필요합니다. |
| ROOT | 원시 명령 실행, 자동화 정의 쓰기, 일부 계정 관리 작업이며 root가 필요합니다. |
| 요청 본문 토큰 | 인증 API는 JSON의 token 필드를 검증합니다. 로그인 없이 계정을 변경해도 된다는 뜻이 아닙니다. |

기본 계정은 admin/root이며 두 계정의 초기 비밀번호는 rm01입니다. 정책은 READ/WRITE/ADMIN/ROOT를 구분하지만 각 수준의 계정을 자유롭게 만드는 API가 있다는 뜻은 아닙니다. 이 버전에는 최소 권한이 WRITE인 등록 인터페이스가 없습니다.

일부 리소스나 매개변수는 추가 권한을 확인합니다. 일반 파일 읽기는 READ를 허용할 수 있지만 민감한 경로는 ADMIN이 필요합니다. config.get은 언어 설정만 공개하며 다른 키에는 ADMIN이 필요합니다. SSH 호스트·명령, 규칙, 동작의 전체 내용 조회에는 보통 ADMIN이 필요하지만 automation.sources.list의 비밀 정보에는 여전히 ROOT가 필요합니다. temp.bind 조회는 ADMIN을 허용하고 바인딩 변경은 ROOT가 필요합니다. automation.proxy.fetch는 로컬 API 호출 시 대상 API 권한을 따르고 외부 서비스에는 ROOT가 필요합니다. restricted:true는 필드가 필터링되었다는 뜻이므로 생략된 필드를 빈 값으로 저장하지 마세요.

## 매개변수

Content-Type: application/json과 JSON 객체 본문을 사용하세요. 배열은 객체 내부의 필드에 넣어야 합니다. 중복 키나 쿼리·본문에 겹치는 매개변수 이름을 사용하지 마세요. 충돌하는 요청은 거부됩니다.

쿼리 값은 한 번 디코딩되며 정수 또는 부울로 해석될 수 있습니다. 개체, 배열, 부동 소수점 값, null 및 선행 0을 유지해야 하는 식별자에는 JSON을 선호합니다. URL을 두 번 인코딩하지 마세요.

선택사항은 생략이 허용됨을 의미합니다. null은 일반적으로 생략과 동일하지 않습니다. 일부 바인딩 API는 바인딩을 지우기 위해 명시적으로 null을 사용합니다. 시간 단위는 필드별로 다릅니다(밀리초, 초 또는 Unix 시간).

## 결과 결정

일반적인 성공:

```json
{"code":0,"data":{"example":"value"}}
```

요청 처리 중 오류가 발생해도 HTTP200이 반환될 수 있습니다.

```json
{"code":1,"error":"invalid_request"}
```

설명은 error 또는 message에 포함될 수 있습니다. data는 객체나 배열이거나 생략될 수 있습니다. 성공 응답에도 message가 없을 수 있습니다.

1. 비성공 HTTP 상태를 전송, 인증, 형식 또는 서비스 실패로 처리합니다.
2. 코드가 존재하고 0이 아닌 경우 API 처리 오류를 처리합니다.
3. 해당 인터페이스의 valid, success, exit_code, persisted 또는 작업 상태를 확인하세요. 최상위 성공 응답만으로 이 확인을 대신할 수 없습니다.
4. 비동기 작업은 해당 API에서 정한 완료 확인 절차를 따르세요. 작업 접수 정보가 반환되면 보관하세요. 연결이 끊기거나 result_unknown이 반환되면 재시도 전에 현재 상태를 확인하세요.

로그인, 로그아웃, 바이너리 업로드 및 다운로드에는 전용 형식이 있습니다. 성공적인 다운로드 본문에는 JSON이 아닌 파일 바이트가 포함됩니다.

## 오류 코드

| code | 이름 | 제안된 응답 |
| --- | --- | --- |
| 0 | OK | 엔드포인트의 완료 조건을 확인합니다. |
| 1 | INVALID_ARG | 필드, 유형, 범위 및 버전 조건 확인 |
| 2 | NOT_FOUND | 객체·작업 정보를 새로 조회하세요. ID를 임의로 만들거나 오래된 ID를 재사용하지 마세요. |
| 3 | NO_PERMISSION | 역할, 민감한 리소스, 내보내기 조건 확인 |
| 4 | BUSY | 활성 작업을 검사하고 재시도하기 전에 기다립니다. |
| 5 | TIMEOUT | 쓰기를 반복하기 전에 결과가 존재하는지 확인 |
| 6 | NO_MEM | 요청 크기 또는 로드를 줄입니다. 알려진 결과 보존 |
| 7 | INTERNAL | reason을 보관하고 result_unknown이면 현재 상태를 확인하세요. |
| 8 | NOT_SUPPORTED | 지원되는 진입점 사용 |
| 9 | HARDWARE | 장치, 센서 및 구성 검사 |
| 10 | CONNECTION | 네트워크, 원격 호스트, 지문 및 서비스 확인 |
| 11 | AUTH | 재인증하거나 필요한 확인을 완료하세요. |

SSH 신뢰 확인 과정에서는 처음 보는 호스트 지문과 변경된 지문에 1001/1002도 사용하며 지문 세부 정보를 제공합니다. 확인 처리 전에 신뢰할 수 있는 경로로 검증하세요. 신뢰 기록 삭제는 호스트 신원 확인을 대신하지 못합니다.

## 효과 및 지속성

applied는 설정 적용을, persisted 또는 saved는 저장 성공을 나타냅니다. 두 결과는 다를 수 있습니다. 앞 단계의 변경이 이미 적용된 후에도 오류가 발생할 수 있으므로 오류 세부 정보를 보관하고 현재 상태를 다시 조회하세요.

토글, 규칙 트리거, 원격 실행 및 업데이트는 안전한 반복이 보장되지 않습니다. 적절한 로드 제어를 통해 읽기 전용 쿼리를 다시 시도할 수 있습니다. 쓰기 시간 초과 후에는 상태나 작업 접수 정보를 먼저 쿼리하세요.

## 제한

연결, 본체, 수신 시간 및 작업 슬롯은 제한되어 있습니다. 신원 및 크기 확인은 전체 본문을 사용하기 전에 요청을 거부할 수 있습니다. 실시간 구독을 다수의 동시 폴링으로 대체하지 마세요.

이 버전은 30초 수신 예산으로 일반 JSON 경로에 대해 최대 1MiB를 허용합니다. 인증 요청은 16KiB/10초로 제한됩니다. 구성 패키지 자체는 64KiB로 제한됩니다. 개별 API는 더 작은 제한을 적용할 수 있습니다. 바이너리 경로는 [전송](transfers.md)을 참조하세요.

JSON 중첩은 32개로 제한됩니다. 포함된 NUL, 후행 가비지 및 중복 키는 거부됩니다. HTTP413의 경우 요청을 줄이거나 해당 기능에 지정된 업로드 경로를 사용하세요.
