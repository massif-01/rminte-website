# 버전 및 호환성

이 가이드는 **TianshanOS 0.6.4**를 기반으로 합니다. 이후 버전에서도 인터페이스와 절차가 동일하다면 이 가이드를 참고할 수 있습니다. 매개변수나 결과가 다른 경우 설치된 버전에 대한 설명서를 따르십시오.

## 연결 및 계정

| 항목 | 사용법 |
| --- | --- |
| 장치 관리 API | HTTP, 기본 포트 80, 접두사 /api/v1을 사용합니다. 예: http://10.10.99.97 |
| 라이브 메시지 | 웹소켓, ws://device-address/ws |
| 기본 계정 | admin/root, 처음 둘 다 rm01; 변경되는 경우에 현재 암호를 사용하십시오 |
| 세션 인증 | 로그인 토큰을 Authorization: Bearer로 전달 |
| 액세스 제어 | 인터페이스별 최소 역할과 추가 리소스·버전·소유권 검사 |

## 기능 전제 조건

사용 가능한 엔드포인트는 모든 런타임 종속성이 준비되었는지 확인하지 않습니다. 사용하기 전에 해당 상태를 점검하십시오.

| 기능 | 전제 조건 |
| --- | --- |
| 온도, 팬, 전원, 컴퓨터 | 초기화된 드라이버, 기존 대상, 유효한 측정 |
| 컴퓨팅 원격 측정 | 실행 중인 모니터, 도달 가능한 호스트 서비스, 새로운 유효한 데이터 |
| 파일 및 SD 업데이트 | 필요한 스토리지 마운트, 파일 존재, 충분한 용량. 직접 업로드에는 별도의 흐름이 있습니다 |
| SSH/SFTP 및 관리형 서비스 | 네트워크, 자격 증명, 호스트 지문, 키, 저장된 구성, 작업 용량 |
| 자동화 | 로드·활성화된 설정, 올바른 엔진 상태, 유효한 참조, 일치하는 쓰기 버전 |
| 구성 패키지 | 장치·수신자 ID와 배포자에 대한 신뢰가 필요합니다. 내보내기에는 Developer 기능도 필요합니다. |
| 장치 PKI 및 업데이트 | 진단에는 유효한 PKI 자료와 시간이, 업데이트에는 호환되는 완전한 APP/WWW 이미지가 필요합니다. |
| 매트릭스 콘텐츠 | 지원되는 대상과 사용할 수 있는 글꼴·이미지 파일이 필요합니다. |

## 별칭 및 지원되지 않는 항목

config.pack.apply는 유지되지만 일반 구성을 적용하지 않습니다. 객체별 가져오기를 사용하세요. led.set는 픽셀 범위를 씁니다. ota.upload_begin/end/abort는 업로드를 제어하지만 공개 upload_write 데이터 API는 제공되지 않습니다. 일반 통합에서는 전체 이미지 바이너리 업로드를 사용해야 합니다.

OTA는 upgrade_url/start_url 및 upgrade_file/start_file 별칭을 유지합니다. 새 연동에는 start_url/start_file을 사용하세요.

## mTLS 진단 서비스

이 서비스는 인증서로 인증하며 기본 포트는 443입니다. /api/v1을 다른 포트로 제공하는 서비스가 아닙니다. 사용 가능 여부는 PKI 자료, 설정, 서비스 상태에 따라 달라집니다. Bearer 토큰은 클라이언트 인증서를 대신하지 못합니다.

| 메서드·경로 | 최소 인증서 역할 | 목적 |
| --- | --- | --- |
| GET / | anonymous | 정상 상태 확인 |
| GET /api/auth/whoami | viewer | 인증서 ID |
| GET /api/test/viewer | viewer | 읽기 역할 테스트 |
| GET /api/test/operator | operator | operator 역할 테스트 |
| GET /api/test/admin | admin | admin 읽기 테스트 |
| POST /api/test/admin-action | admin | admin 쓰기 테스트 |

이러한 엔드포인트는 장치 사업 활동을 수행하는 것보다 건강, 정체성 및 권한이 진단됩니다. 인증서 뷰어/operator/admin 및 사업 READ/ADMIN/ROOT 별도의 정체성 시스템에 속하며 상호 교환할 수 없습니다.
