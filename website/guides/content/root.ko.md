# TianshanOS root 운영 가이드

root 계정으로 TianshanOS를 관리하는 운영 담당자를 위한 문서입니다. 1부는 admin과 root의 공통 일상 기능을, 2부는 root 전용 터미널(‘终端’), 명령(‘指令’), 자동화(‘自动化’)를 설명합니다. 보안 관리는 『TianshanOS 보안 가이드』를 참고하세요.

<!-- operational-note -->

root는 장치, 원격 호스트, 자동화 흐름에 큰 영향을 주는 작업을 수행할 수 있습니다. 현재 장치, 대상 호스트, 실행 중인 작업을 확인한 뒤 시작하세요.

장치 화면에 실제 표시되는 기능에 따라 조작하세요. 하드웨어 연결이나 설정 후에 나타나는 버튼도 있습니다.

이 가이드는 조작 이름의 번역과 장치 화면의 중국어 이름을 함께 표기합니다. 장치 WebUI는 중국어와 영어를 지원하며 웹사이트의 언어 전환이 장치 지원 언어를 늘리지는 않습니다.

## 1부: admin과 root의 공통 일상 기능

## 1. 시작하기

### WebUI 열기

1. 관리자가 안내한 장치 웹 주소(WebUI)를 브라우저에서 엽니다.
2. 오른쪽 위의 로그인(‘登录’)을 선택합니다.
3. `root`와 장치에서 제공한 root 비밀번호를 입력합니다.
4. 로그인(‘登录’)을 선택합니다. 로그인하면 오른쪽 위에 현재 사용자 이름이 표시됩니다.

초기 비밀번호로 처음 로그인하면 보안 알림(‘安全提醒’)이 나타납니다. 현재 비밀번호와 새 비밀번호를 입력한 뒤 지금 변경(‘立即修改’)을 선택할 수 있습니다. 새 비밀번호는 확인란까지 두 번 동일하게 입력해야 합니다. 나중에 변경(‘稍后修改’)을 선택하면 알림이 닫힙니다.

사용을 마치면 오른쪽 위의 로그아웃(‘退出登录’)을 선택합니다. 장치를 다시 조작하려면 로그인해야 합니다.

### 언어 전환

화면 위쪽의 언어 버튼을 누르고 메뉴에서 中文 또는 English를 선택합니다. 화면 내용과 버튼 이름이 선택한 언어로 바뀝니다.

### 페이지 이동

root가 사용할 수 있는 페이지는 다음과 같습니다.

- 시스템(‘系统’): 장치 상태 확인, 모듈·팬·LED 제어, OTA 업데이트 진입.
- 네트워크(‘网络’): 이더넷과 DHCP 상태 확인, WiFi 및 NAT 전달 설정.
- 파일(‘文件’): SD 카드와 SPIFFS의 파일 관리.
- 터미널(‘终端’): 장치 콘솔과 시스템 로그 사용.
- 자동화(‘自动化’): 데이터 소스, 변수, 동작 템플릿, 규칙 관리.
- 명령(‘指令’): 원격 SSH 명령 관리 및 실행.
- 보안(‘安全’): 별도의 보안 관리 페이지로 이동. 자세한 절차는 보안 가이드를 참고하세요.

## 2. 시스템 상태와 기본 작업

위쪽 탐색 메뉴에서 시스템(‘系统’)을 선택합니다.

### 리소스와 서비스 상태 확인

리소스 모니터(‘资源监控’)는 CPU, DRAM, PSRAM 사용량을 보여 줍니다. DRAM과 PSRAM은 장치에서 프로그램을 실행할 때 쓰는 메모리입니다.

- 상세 정보(‘详情’)에서 메모리 총량, 사용량, 여유 공간, 단편화율을 확인합니다.
- 서비스(‘服务’) 버튼 옆에는 실행 중인 서비스 수와 전체 서비스 수가 표시됩니다.
- 서비스(‘服务’)에서 각 서비스의 상태, 단계, 정상 동작 여부를 확인합니다.

서비스가 실패(‘失败’) 상태이거나 정상 동작 상태에 이상이 있다면, 먼저 페이지를 새로고침하여 현재 상태를 확인하세요.

### 시스템 및 전원 정보 확인

시스템 개요(‘系统总览’)에는 칩, 펌웨어 버전, 가동 시간, 빌드 시각이 표시됩니다. 전원 상태(‘电源状态’)에는 입력 전압, 내부 전압, 전류, 전력, 보호 상태가 표시됩니다.

보호 상태 옆 스위치로 저전압 보호를 켜거나 끕니다. 켜면 입력 전압이 너무 낮아질 때 설정된 종료 및 복구 절차를 실행합니다.

### 네트워크와 시간 확인

네트워크 및 시간(‘网络与时间’)에는 이더넷, WiFi, IP 주소, 현재 시각, 동기화 상태, 시간 소스, 시간대가 표시됩니다.

- 시간 동기화(‘同步时间’)로 브라우저의 현재 시각을 장치에 반영합니다.
- 시간대(‘时区’)에서 사전 설정을 선택하거나 화면에서 지원하는 시간대 설정을 입력한 뒤 저장합니다.
- OTA 업데이트(‘OTA 升级’)로 펌웨어 업데이트 페이지를 엽니다.

### 고급 작업

#### TianshanOS 재시작

재시작하는 동안 WebUI, 터미널, 자동화, 장치 관리 기능이 잠시 중단됩니다. 진행 중인 작업을 마친 뒤 재시작(‘重启’)을 선택하고 확인합니다. 재시작 안내가 나타나며, 장치가 복구되면 WebUI를 다시 열 수 있습니다.

#### 개별 서비스 재시작

서비스를 재시작하면 해당 기능이 잠시 중단됩니다. 서비스 상태(‘服务状态’)에서 문제가 있는 서비스를 찾아 해당 행의 재시작(‘重启’)을 선택합니다. 완료 후 상태와 정상 동작 여부를 다시 확인하세요.

#### 종료 설정 변경

전압이 낮아졌을 때 장치를 언제 종료하고, 전원이 회복되었을 때 언제 다시 시작할지 정하는 설정입니다. 장치의 전원 요구 사항에 맞춰 전압과 대기 시간을 입력하세요.

종료 설정(‘关机设置’)에서 다음 항목을 조정합니다.

- 저전압 임계값(‘低电压阈值’): 이 전압보다 낮아지면 종료 카운트다운을 시작합니다.
- 복구 전압 임계값(‘恢复电压阈值’): 이 전압보다 높아지면 복구 절차를 시작합니다.
- 종료 카운트다운(‘关机倒计时’): 저전압 감지 후 종료까지 기다리는 시간입니다.
- 복구 안정화 대기(‘恢复稳定等待’): 전압 회복 후 전원이 안정적인지 확인하는 대기 시간입니다.
- 팬 정지 지연(‘风扇关闭延迟’): 장치 종료 후 팬을 멈출 때까지의 시간입니다.

저장하면 새 보호 설정이 적용됩니다.

#### 상단 USB 연결 대상 전환

<!-- operational-note -->

USB 대상을 바꾸면 연결된 주변 기기가 잠시 끊길 수 있습니다. 대상 장치와 진행 중인 작업을 확인한 뒤 조작하세요.

USB 전환 기능이 표시되는 경우 ‘USB’ 버튼을 누를 때마다 상단 USB 포트의 연결 대상이 ESP, AGX, LPMU 순서로 바뀝니다. 버튼에는 현재 대상이 표시되며, 전환에 성공하면 화면에서 알려 줍니다.

## 3. 장치 패널

시스템(‘系统’) 페이지의 장치 패널(‘设备面板’)에는 모듈 전원 제어, 빠른 작업, 데이터 위젯이 있습니다.

### AGX와 LPMU 제어

AGX와 LPMU 버튼은 현재 상태를 나타냅니다. 녹색은 실행 중, 빨간색은 전원 꺼짐을 뜻하며, 감지 중에는 대기 상태가 표시됩니다.

<!-- operational-note -->

전원을 강제로 차단하면 저장하지 않은 데이터가 손실될 수 있습니다. 모듈의 작업을 저장하고 정상 종료 절차를 마친 뒤 전원을 끄세요.

- AGX 상태 버튼으로 AGX 전원을 켜거나 끕니다. 화면에 최종 결과가 표시될 때까지 기다립니다.
- LPMU 상태 버튼은 물리 전원 버튼을 한 번 누르는 것과 같은 동작을 수행합니다. 이후에도 LPMU 상태를 계속 확인합니다. 감지 시간이 초과되면 화면 안내에 따르고 반복해서 누르지 마세요.

### 빠른 작업 사용

빠른 작업(‘快捷操作’)에는 수동 트리거 전용(‘仅手动触发’)으로 설정된 자동화 규칙이 표시됩니다.

1. 카드를 선택하여 해당 작업을 실행합니다.
2. 처리 중일 때는 완료될 때까지 기다립니다.
3. 백그라운드 실행을 지원하는 카드는 실행 상태와 로그(‘日志’), 중지(‘停止’)를 표시합니다.
4. 로그(‘日志’)로 현재 출력을 확인하고, 중지(‘停止’)로 실행 중인 작업을 종료합니다.

실행 중인 작업을 다시 시작하려면 먼저 중지해야 합니다. 한 작업을 시작한 뒤에는 몇 초 기다렸다가 다른 작업을 시작하세요. 카드를 길게 누르고 정렬 표시가 나타나면 드래그하여 순서를 바꿀 수 있습니다. 빠른 작업 없음(‘暂无快捷操作’)은 현재 설정된 수동 규칙이 없다는 뜻입니다. 설정 방법은 2부 자동화 관리를 참고하세요.

### 데이터 위젯 관리

데이터 위젯은 장치 패널(‘设备面板’)에 장치 데이터를 지속해서 표시합니다.

1. 위젯 관리(‘组件管理’)를 선택합니다.
2. 새로고침 간격을 선택하거나 자동 새로고침을 끕니다.
3. 사전 설정 위젯을 추가하거나 화면에서 제공하는 표시 형식과 데이터 소스를 선택합니다.
4. 필요에 따라 이름, 표시 방식, 단위를 수정한 뒤 저장합니다.

기존 위젯은 편집, 삭제, 순서 변경이 가능합니다. 위젯 카드를 직접 눌러 편집할 수도 있습니다. 길게 누른 뒤 드래그하면 패널 내 위치를 바꿀 수 있습니다.

## 4. 팬 관리

시스템(‘系统’) 페이지의 팬 제어(‘风扇控制’)에는 현재 장치에서 제공하는 팬만 표시됩니다.

### 팬 상태 확인

위쪽 상태 표시줄에는 유효 온도(‘有效温度’)와 목표 속도(‘目标转速’)가 표시됩니다. 팬 카드의 백분율은 자동·곡선 모드에서는 목표 제어값, 수동 모드에서는 현재 설정값입니다. RPM은 측정된 분당 회전수이며 유효한 측정값이 있을 때만 표시됩니다. 백분율과 RPM은 서로 다른 값입니다.

자동 모드에서는 곡선에 따라 작동(‘按曲线运行’), 적응형 속도 제어(‘自适应调速’), 보호 작동(‘保护介入’), 온도 무효(‘温度失效’) 상태와 안전 기준 온도, 45초 뒤 예측 온도, 온도 상승률도 표시될 수 있습니다. 예측 온도는 온도가 오르기 전에 속도를 조정하는 데 쓰입니다. 온도 무효(‘温度失效’)가 표시되면 온도 소스가 계속 갱신되는지 먼저 확인하세요. 장치는 보호용 속도 설정을 사용합니다. 카드의 정보 버튼에서 자동 모드 설명을 볼 수 있습니다.

오른쪽 위 새로고침 버튼으로 현재 상태를 다시 불러옵니다.

### 작동 모드 선택

| 모드 | 기능 |
| --- | --- |
| 끄기(‘关闭’) | 팬을 멈춥니다. |
| 수동(‘手动’) | 고정된 제어 백분율을 사용합니다. 슬라이더로 0-100%를 설정합니다. |
| 자동(‘自动’) | 팬 곡선을 바탕으로 온도 변화 추세와 보호 상태에 따라 속도를 조정합니다. |
| 곡선(‘曲线’) | 설정된 온도와 속도의 대응 관계에 따라 작동합니다. |

<!-- operational-note -->

팬을 끄거나 수동 속도를 너무 낮추면 냉각 성능이 떨어집니다. 변경 전에 부하와 온도를 확인하고 이후에도 온도 변화를 지켜보세요.

수동(‘手动’) 모드에서 속도 조정(‘转速调节’) 슬라이더를 움직여 설정합니다. 다른 모드에서는 슬라이더를 사용할 수 없습니다.

### 팬 곡선 설정

팬 제어(‘风扇控制’) 영역 제목 옆의 곡선(‘曲线’)을 선택하면 팬 곡선 관리(‘风扇曲线管理’)가 열립니다. 팬 카드 안의 곡선(‘曲线’) 버튼은 작동 모드만 바꿉니다.

1. 팬 선택(‘选择风扇’)에서 대상 번호를 고르고 시스템 페이지의 팬 카드와 대조합니다.
2. 온도 변수 연결(‘绑定温度变量’)에서 온도 소스를 하나 이상 추가하고 가중치를 지정합니다.
3. 모두 연결(‘绑定全部’)을 선택하여 적용합니다. 이 온도 소스는 자동·곡선 모드의 팬이 공유하므로 변경하면 해당 소스를 사용하는 모든 팬에 영향을 줍니다.
4. 온도-속도 곡선(‘温度-转速曲线’)에서 점을 추가하거나 수정합니다. 곡선마다 최소 2개, 최대 10개의 점을 설정할 수 있습니다.
5. 최소 듀티 사이클(‘最小占空比’)과 최대 듀티 사이클(‘最大占空比’)을 설정합니다. 최솟값은 최댓값보다 클 수 없습니다.
6. 필요에 따라 온도 히스테리시스(‘温度迟滞’)와 최소 간격(‘最小间隔’)을 설정합니다. 범위는 각각 0-20°C와 500-30000 ms입니다.
7. 곡선 적용(‘应用曲线’)을 선택합니다. 설정이 저장되고 선택한 팬이 곡선(‘曲线’) 모드로 전환됩니다.

최소 듀티 사이클(‘最小占空比’)과 최대 듀티 사이클(‘最大占空比’)은 제어 백분율의 범위를 정합니다. 온도 히스테리시스(‘温度迟滞’)는 작은 온도 변화로 속도가 자주 바뀌는 것을 줄입니다. 최소 간격(‘最小间隔’)은 연속된 두 속도 조정 사이의 최소 시간입니다. 1000 ms는 1초입니다.

곡선을 적용하면 곡선 모드로 바뀝니다. 자동 제어를 계속 사용하려면 팬 카드로 돌아가 자동(‘自动’)을 선택하세요.

### 곡선 가져오기 및 내보내기

- 설정 가져오기(‘导入配置’)에서 유효한 곡선 JSON 파일을 선택합니다. 불러온 곡선과 매개변수를 확인한 뒤 곡선 적용(‘应用曲线’)을 선택합니다.
- 설정 내보내기(‘导出配置’)는 현재 곡선을 브라우저로 다운로드하면서 SD 카드의 `/sdcard/config`에도 복사본 저장을 시도합니다. SD 카드 저장 결과는 화면에 표시됩니다.

### 테스트 온도 사용

<!-- operational-note -->

테스트 온도는 정상 온도 소스를 임시로 대체하여 자동·곡선 제어에 영향을 줍니다. 테스트 중에는 팬과 장치 상태를 계속 확인하세요.

1. 테스트 온도(‘测试温度’)에 0-100°C 범위의 값을 입력합니다.
2. 테스트(‘测试’)를 선택하여 목표 속도와 팬 반응을 확인합니다.
3. 테스트가 끝나면 즉시 테스트 해제(‘清除测试’)를 선택하여 정상 온도 소스로 되돌립니다.

## 5. LED 관리

시스템(‘系统’) 페이지의 LED 제어(‘LED 控制’)에는 현재 장치에서 제공하는 LED만 표시됩니다.

### 기본 제어

- 장치 카드의 스위치로 해당 LED를 켜거나 끕니다.
- 밝기(‘亮度’)로 현재 장치의 밝기를 조절합니다.
- 색상 제어를 지원하는 장치에서는 색상 또는 사전 설정 색상을 선택합니다.
- 애니메이션 효과(‘动画特效’)의 항목을 선택해 실행하고 애니메이션 중지(‘停止动画’)로 종료합니다.
- 설정 저장(‘保存配置’)으로 현재 장치의 LED 설정을 저장합니다.
- 모두 끄기(‘全部关闭’)로 화면에 표시된 모든 LED를 끕니다.

LED마다 색상, 밝기, 애니메이션 옵션이 다를 수 있습니다. 현재 장치 카드와 설정 창에 표시된 항목을 기준으로 조작하세요.

### LED 매트릭스 고급 기능

LED 매트릭스가 있는 장치의 설정 창에는 다음 기능도 표시될 수 있습니다.

- 이미지 표시(‘显示图像’): SD 카드에서 이미지를 선택하여 표시합니다.
- QR 코드 생성(‘生成 QR 码’): 내용, 색상, 오류 정정 수준을 지정하여 생성합니다.
- 텍스트 표시(‘显示文本’): 문구를 입력하고 글꼴, 정렬, 스크롤 속도, 전경색, 배경을 설정합니다.
- 후처리 필터(‘后处理滤镜’): 화면에 있는 필터를 적용하고 중지 버튼으로 해제합니다.
- 색상 보정(‘色彩校正’): 매트릭스 출력을 조정하고 화면의 버튼으로 보정 설정을 초기화하거나 가져오고 내보냅니다.

매트릭스 크기, 애니메이션, 필터는 장치에 따라 다릅니다. 실제 WebUI에 표시된 기능을 기준으로 조작하세요.

## 6. 네트워크 관리

<!-- operational-note -->

위쪽 탐색 메뉴에서 네트워크(‘网络’)를 선택하여 네트워크 설정(‘网络设置’)을 엽니다. 네트워크 모드, 핫스폿, NAT를 변경하면 현재 WebUI, 터미널, 자동화 연결이 끊길 수 있습니다. 저장 전에 새 네트워크 주소로 다시 접속할 수 있는지 확인하세요.

### 네트워크 상태 확인

페이지 위쪽에는 이더넷, WiFi 클라이언트, WiFi 핫스폿의 연결 상태가 표시됩니다. 각 패널에서 IP 주소, 서브넷 마스크, 게이트웨이, DNS, MAC 주소, SSID, 신호, 접속 장치 수 등을 확인할 수 있습니다.

이더넷 패널에서는 현재 링크와 주소 정보를 확인할 수 있으며 주소를 수정할 수는 없습니다.

### WiFi 모드 선택

| 모드 | 기능 |
| --- | --- |
| 끄기(‘关闭’) | WiFi를 끕니다. |
| 스테이션(STA)(‘站点 (STA)’) | 기존 WiFi 네트워크에 연결합니다. |
| 액세스 포인트(AP)(‘热点 (AP)’) | 장치가 WiFi 핫스폿을 제공합니다. |
| ‘STA+AP’ | 기존 WiFi에 연결하면서 장치 핫스폿도 유지합니다. |

<!-- operational-note -->

모드를 선택하면 상태가 갱신될 때까지 기다립니다. 전환 중에는 무선 연결이 잠시 끊길 수 있습니다.

### WiFi 연결

1. WiFi 모드를 스테이션(STA)(‘站点 (STA)’) 또는 ‘STA+AP’로 설정합니다.
2. 스테이션 연결(‘站点连接’)에서 검색(‘扫描’)을 선택합니다.
3. 목록에서 네트워크를 선택합니다. SSID, 신호 강도, 채널, 인증 방식이 표시됩니다.
4. 비밀번호를 입력하고 확인합니다. 개방형 네트워크는 비밀번호를 비워 둘 수 있습니다.
5. 연결됨(‘已连接’) 상태가 될 때까지 기다린 뒤 새 IP 주소를 확인합니다.

연결 해제(‘断开’)로 현재 WiFi 클라이언트 연결을 종료합니다.

### WiFi 핫스폿 설정

1. WiFi 모드를 액세스 포인트(AP)(‘热点 (AP)’) 또는 ‘STA+AP’로 설정합니다.
2. 핫스폿(‘热点’)에서 설정(‘配置’)을 선택합니다.
3. SSID를 입력합니다. 비밀번호를 비워 두면 개방형 핫스폿이 됩니다. 설정하려면 최소 8자가 필요합니다.
4. 채널을 선택하고 필요하면 SSID 숨기기(‘隐藏 SSID’)를 켭니다.
5. 적용(‘应用’)을 선택한 뒤 핫스폿 상태가 갱신될 때까지 기다립니다.

장치(‘设备’)에서 현재 핫스폿에 연결된 장치를 확인할 수 있습니다.

### 호스트 이름 설정

네트워크 서비스(‘网络服务’)의 호스트 이름(‘主机名’)에 새 이름을 입력하고 설정(‘设置’)을 선택합니다. 변경 후 현재 호스트 이름이 표시됩니다.

### DHCP 클라이언트 확인

DHCP는 접속 장치에 네트워크 주소를 자동으로 할당합니다. 클라이언트(‘客户端’)에서 ‘WiFi AP’ 또는 ‘Ethernet’을 선택하여 현재 할당 기록을 확인합니다. 새로고침 버튼으로 목록을 다시 불러올 수 있습니다.

### 고급 네트워크 작업

#### NAT 게이트웨이 설정

NAT는 장치의 네트워크 인터페이스 사이에서 트래픽을 전달합니다. NAT를 켜거나 끈 뒤 저장(‘保存’)으로 설정을 유지합니다. 작업 후 WiFi와 Ethernet 상태를 확인하세요.

#### LPMU를 통한 상위 네트워크 접속

상위 네트워크 접속(‘接入上层网络’)이 표시되면 LPMU를 통해 접속(‘通过LPMU接入’)을 선택합니다. 처리 중(‘处理中’)에서 성공(‘成功’) 또는 실패(‘失败’)로 바뀔 때까지 기다리세요. 처리 중에 다시 실행하지 마세요. 실패하면 화면의 오류와 출력을 확인합니다.

## 7. 파일 관리

위쪽 탐색 메뉴에서 파일(‘文件’)을 선택하여 파일 관리자(‘文件管理’)를 엽니다.

SD 카드는 이동식 저장 장치이고 SPIFFS는 장치 내부 파일 저장소입니다. SD 카드(‘SD 卡’) 또는 ‘SPIFFS’를 선택하여 위치를 바꿉니다. 위쪽에는 현재 폴더 경로가 표시됩니다. 경로의 폴더 이름을 누르면 해당 상위 폴더로 돌아갑니다.

### 파일 탐색 및 관리

- 폴더 이름을 눌러 해당 디렉터리를 엽니다.
- 파일 오른쪽의 다운로드 버튼으로 브라우저의 다운로드 위치에 저장합니다.
- 이름 변경 버튼을 누르고 새 이름을 입력한 뒤 확인합니다.
- 새 폴더(‘新建文件夹’)에서 이름을 입력하여 만듭니다.
- 새로고침 버튼으로 현재 디렉터리와 저장소 상태를 다시 불러옵니다.

### 파일 업로드

1. 대상 디렉터리를 엽니다.
2. 파일 업로드(‘上传文件’)를 선택합니다.
3. 업로드 영역을 눌러 파일을 하나 이상 선택하거나 파일을 끌어 놓습니다.
4. 업로드 목록을 확인하고 불필요한 파일을 제외합니다.
5. 업로드(‘上传’)를 선택하고 각 파일이 완료될 때까지 기다립니다. `.tscfg` 설정 패키지를 업로드하면 검증 및 적용 절차가 시작됩니다. 패키지 출처, 서명, 적용 조건은 보안 가이드를 참고하세요.

### 일괄 작업

파일이나 폴더를 선택하면 일괄 작업 도구 모음이 나타납니다.

- 일괄 다운로드(‘批量下载’)는 선택한 파일을 다운로드합니다. 폴더는 포함되지 않습니다.
- 일괄 삭제(‘批量删除’)는 선택한 파일과 폴더를 삭제합니다.
- 선택 해제(‘取消选择’)는 현재 선택을 모두 해제합니다.

### 파일 또는 폴더 삭제

삭제는 WebUI에서 취소할 수 없습니다. 폴더를 삭제하면 안의 모든 내용도 삭제됩니다. 이름과 경로를 확인한 뒤 삭제(‘删除’) 또는 일괄 삭제(‘批量删除’)를 선택하고 확인하세요.

### SD 카드 마운트 및 마운트 해제

SD 카드의 마운트를 해제하면 카드의 파일에 잠시 접근할 수 없습니다. 업로드, 다운로드 등 파일 작업이 진행 중이지 않은지 확인한 뒤 SD 마운트 해제(‘卸载 SD’)를 선택하세요.

마운트되지 않은 상태에서는 SD 마운트(‘挂载 SD’)가 표시됩니다. 버튼을 누르고 마운트됨(‘已挂载’) 상태가 될 때까지 기다린 뒤 SD 카드 디렉터리를 다시 엽니다.

## 8. OTA 업데이트

시스템(‘系统’) 페이지의 네트워크 및 시간(‘网络与时间’)에서 OTA 업데이트(‘OTA 升级’)를 선택하여 펌웨어 업데이트(‘固件升级’)를 엽니다.

업데이트 도중 장치가 재시작되며 WebUI, 터미널, 자동화가 잠시 끊깁니다. 작업을 저장하고 안정적인 전원을 확보한 뒤 시작하세요. 업데이트가 끝나기 전에는 장치 전원을 끄지 마세요.

### OTA 서버에서 업데이트 확인

1. 현재 버전(‘当前版本’)을 확인합니다.
2. OTA 서버(‘OTA 服务器’)에 관리자나 배포자가 제공한 서버 주소를 입력합니다.
3. 저장(‘保存’)을 누른 뒤 업데이트 확인(‘检查更新’)을 선택합니다.
4. 새 버전 발견, 최신 버전 사용 중, 서버 버전이 더 오래됨 또는 오류가 표시됩니다.
5. 대상 버전을 확인한 뒤 지금 업데이트(‘立即升级’) 또는 화면의 업데이트 버튼을 선택합니다.
6. 다운로드, 설치, 재시작이 끝날 때까지 기다립니다. 중단 버튼이 표시되면 중단을 지원하는 단계에서 작업을 멈출 수 있습니다.
7. 장치가 온라인으로 돌아오면 WebUI에 다시 접속하여 현재 버전(‘当前版本’)을 확인합니다. WebUI를 포함하면 펌웨어와 WebUI가 순서대로 업데이트됩니다. 두 파일은 같은 릴리스의 것이어야 합니다.

### 수동 업데이트

수동 업데이트(‘手动升级’)를 펼쳐 다음 방식 중 하나를 선택합니다.

- URL에서 업데이트(‘从 URL 升级’): 펌웨어 URL을 입력하고 릴리스 안내에 따라 WebUI 포함(‘包含 WebUI’)을 설정한 뒤 업데이트(‘升级’)를 선택합니다.
- SD 카드에서 업데이트(‘从 SD 卡升级’): `/sdcard/firmware.bin` 같은 펌웨어 경로를 입력합니다. WebUI 포함(‘包含 WebUI’)을 선택하면 같은 디렉터리의 WebUI 파일도 처리합니다.

URL 업데이트의 검증 건너뛰기(‘跳过验证’)는 HTTPS 서버 인증서 검증을 생략합니다. 선택하면 인증서로 다운로드 서버의 신원을 확인할 수 없습니다. 일반적인 업데이트에서는 선택하지 마세요. 인증서 오류가 발생하면 관리자에게 서버 주소와 인증서 확인을 요청하세요.

### 파티션 관리 및 롤백

파티션 관리(‘分区管理’)에는 현재 실행 중인 파티션과 사용 가능한 다른 파티션이 표시됩니다.

- 유효 표시(‘标记有效’)는 현재 버전을 승인하고 해당 버전의 자동 롤백 보호를 해제합니다. 정상 동작을 확인한 뒤 실행하세요.
- 이 버전으로 롤백(‘回滚到此版本’)은 부팅 가능한 다른 버전을 선택하고 재시작하여 전환합니다. 현재 서비스가 중단되므로 대상 버전과 데이터 호환성을 먼저 확인하세요.

작업과 재시작이 끝나면 WebUI를 다시 열어 현재 버전과 장치 상태를 확인합니다.

## 9. 보안 관리 진입

위쪽 탐색 메뉴의 보안(‘安全’)으로 보안 관리 페이지를 엽니다. SSH 키, 원격 호스트, 호스트 지문, HTTPS 인증서, 설정 패키지, 계정 관리는 『TianshanOS 보안 가이드』를 참고하세요. 이 가이드에서는 해당 절차를 반복하지 않습니다.

## 10. 터미널과 시스템 로그

터미널(‘终端’)은 root에게만 표시됩니다. 장치 콘솔 명령을 직접 실행하고 로그를 확인할 수 있습니다. 명령이 장치 상태를 즉시 바꿀 수 있으므로 입력 전에 출처, 매개변수, 영향을 확인하세요.

### 터미널 연결 및 사용

1. 위쪽 탐색 메뉴에서 터미널(‘终端’)을 선택합니다.
2. 장치 연결 완료(‘已连接到设备’)와 `tianshan>` 프롬프트가 나타날 때까지 기다립니다.
3. `help`를 입력하여 현재 펌웨어의 명령을 확인합니다.
4. 명령을 입력하고 Enter를 누른 뒤 출력이 끝나고 프롬프트가 돌아올 때까지 기다립니다.

연결되지 않음(‘未连接到设备’) 상태에서는 입력이 실행되지 않습니다. 연결이 끊기면 재연결 안내가 나타납니다. 복구 후 명령을 제출하여 중복 실행을 피하세요.

다음 키보드 조작을 지원합니다.

| 조작 | 기능 |
| --- | --- |
| Ctrl+C | 현재 입력을 지우고 명령 중단을 요청합니다. 실제 중단 여부는 명령의 지원에 따라 다릅니다. |
| Ctrl+L | 화면을 지웁니다. |
| ↑ / ↓ | 현재 페이지 세션의 명령 기록을 탐색합니다. |
| ← / → | 현재 입력 안에서 커서를 이동합니다. |

위쪽 화면 지우기(‘清屏’)는 표시만 지우며 실행한 명령을 취소하지 않습니다. 연결 해제(‘断开’)는 터미널 연결을 종료합니다.

### 원격 SSH Shell 진입

SSH Shell에서는 이후 키 입력이 원격 호스트로 전송됩니다. 주소, 사용자, 인증 방식을 확인하고 보안 가이드의 SSH 준비를 마친 뒤 연결하세요.

1. `ssh --help`로 명령 설명을 확인합니다.
2. `ssh --host <主机地址> --user <用户名> --shell` 형식으로 실제 호스트 주소와 사용자 이름을 입력합니다. 꺾쇠괄호와 안의 글자를 모두 바꾸세요. 포트가 필요하면 --shell 앞에 `--port <端口>`를 추가하고 포트 번호로 바꿉니다.
3. 원격 연결 성공 표시를 기다린 뒤 명령을 입력합니다.
4. Ctrl+\로 SSH Shell을 종료하고 tianshan>로 돌아갑니다.

화면 공유, 녹화 중이거나 다른 사람이 볼 수 있는 터미널에 평문 인증 정보를 입력하지 마세요.

### 시스템 로그 확인

터미널 위쪽의 시스템 로그(‘系统日志’)로 로그 창을 엽니다.

- 수준(‘级别’): 최소 표시 수준입니다. ERROR, WARN+, INFO+, DEBUG+로 범위를 좁힙니다.
- ‘TAG’: 로그 출처로 필터링합니다.
- 검색(‘搜索’): 현재 로그를 키워드로 필터링합니다.
- 자동 스크롤(‘自动滚动’): 최신 로그를 따라갑니다.
- 새로고침 버튼: 과거 로그를 다시 읽습니다.
- 지우기 버튼: 현재 창의 로그 표시만 지웁니다.

내용이 없으면 TAG와 키워드를 비우고 수준을 조정하세요. 창을 닫아도 장치 서비스는 멈추지 않습니다.

## 11. 원격 명령 관리 및 실행

명령(‘指令’)은 재사용할 SSH 명령을 저장하고 선택한 원격 호스트에서 실행하는 기능입니다. 호스트와 인증 정보는 보안(‘安全’)에서 관리합니다. 절차는 보안 가이드를 참고하세요.

### 호스트 선택 및 명령 확인

1. 위쪽 탐색 메뉴에서 명령(‘指令’)을 선택합니다.
2. 호스트 선택(‘选择主机’)에서 대상을 고릅니다.
3. 명령 목록(‘命令列表’)에서 등록된 명령을 확인합니다.

고아 명령(‘孤儿命令’)은 참조 호스트가 없어져 실행할 수 없는 명령입니다. 삭제하거나 가져오기 시 호스트 연결 기능으로 유효한 호스트에 다시 연결할 수 있습니다.

### 명령 생성 및 편집

저장한 명령은 원격 호스트에서 실행됩니다. 먼저 대상 호스트에서 명령과 권한을 직접 확인하세요. 삭제, 종료, 재시작, 파일 덮어쓰기 등을 실수로 실행하기 쉬운 형태로 등록하지 마세요.

1. 호스트를 고르고 새 명령(‘新建指令’)을 선택합니다. 기존 명령은 편집 버튼을 누릅니다.
2. 명령 ID(‘指令 ID’)를 입력합니다. 고유해야 하며 영문자, 숫자, 밑줄, 하이픈만 사용할 수 있습니다. 밑줄이나 하이픈으로 시작하거나 끝낼 수 없습니다.
3. 명령 이름(‘指令名称’)과 ‘SSH 命令’을 입력합니다. 여러 줄이면 한 줄에 명령 하나씩 입력합니다.
4. 필요하면 설명과 아이콘 또는 SD 카드 이미지를 선택합니다.
5. 고급 옵션을 확인하고 저장(‘保存’)합니다.

이름은 명령 식별용이고 ID는 자동화 참조용입니다. 기존 ID는 읽기 전용입니다. 새 ID가 필요하면 명령을 새로 만들고 동작 템플릿과 데이터 소스의 참조도 확인하세요.

### 실행 및 결과 확인

1. 명령 카드의 실행 버튼을 누릅니다.
2. 실행 결과(‘执行结果’)에서 출력과 상태를 확인합니다.
3. 취소(‘取消’)가 표시되면 아직 실행 중인 세션을 종료할 수 있습니다.
4. 지우기(‘清除’)는 현재 결과 표시만 제거합니다.

표시를 지워도 원격 호스트에서 완료한 작업은 취소되지 않습니다. 성공·실패, 추출 내용, 최종 상태는 명령의 일치 조건 설정에 따라 결정됩니다.

### 결과 일치 조건 설정

원격 출력을 판단하기 쉬운 상태로 변환합니다.

- 성공 패턴(‘成功匹配模式’): 지정 텍스트가 포함되면 성공으로 표시합니다.
- 실패 패턴(‘失败匹配模式’): 지정 텍스트가 포함되면 실패로 표시합니다.
- 추출 패턴(‘提取模式’): `(.*)` 캡처 그룹 하나로 대상 내용을 저장합니다.
- 일치 후 자동 중지(‘匹配后自动停止’): 일치하면 계속 실행 중인 명령을 종료합니다.
- 시간 제한(‘超时’): 지정 시간 안에 일치 결과가 없으면 대기를 끝냅니다. 성공·실패 패턴을 설정하거나 자동 중지를 켠 경우에만 적용됩니다.
- 저장 변수 이름(‘存储变量名’): 상태와 추출 결과를 저장하여 자동화에서 선택하게 합니다.

성공·실패 텍스트는 안정적이고 명확한 출력을 고르세요. 너무 포괄적이면 잘못 판단할 수 있습니다. 저장 후 한 번 실행하여 일치 결과(‘匹配结果’)를 확인한 뒤 변수에 의존하는 규칙을 만드세요.

### 백그라운드 실행 및 서비스 모드

nohup은 SSH 연결이 끊겨도 원격 명령을 백그라운드에서 계속 실행하게 합니다. WebUI를 닫아도 자동 종료되지 않습니다. 백그라운드 실행(‘后台执行（nohup）’)을 켜면 다음 기능을 사용할 수 있습니다.

- 로그 보기(‘查看日志’): 현재 로그를 읽습니다.
- 실시간 추적(‘实时跟踪’): 로그를 계속 갱신합니다.
- 추적 중지(‘停止跟踪’): 화면 갱신만 멈추고 원격 작업은 유지합니다.
- 프로세스 확인(‘检查进程’): 아직 실행 중인지 확인합니다.
- 프로세스 중지(‘停止进程’): 해당 백그라운드 작업을 종료합니다.

서비스 모드(‘服务模式（监测就绪状态）’)는 작업이 사용 가능한 상태가 되는지 감시합니다. 준비 완료 패턴과 저장 변수 이름은 필수이며 실패 패턴과 대기 설정은 필요에 따라 조정합니다.

- 준비 완료 패턴(‘就绪匹配模式’): 로그에 나타나면 준비 완료로 표시합니다. 여러 패턴은 `|`로 구분합니다.
- 실패 패턴(‘失败匹配模式’): 로그에 나타나면 실패로 표시합니다.
- 시간 제한(‘超时’): 준비 완료를 기다리는 최대 시간입니다.
- 검사 간격(‘检测间隔’): 로그를 확인하는 주기입니다.
- 저장 변수 이름(‘存储变量名’): checking, ready, timeout 등의 상태를 저장합니다.

추적 중지와 프로세스 중지는 다릅니다. 보기를 끝낼 때는 추적만 중지하고, 작업을 종료해도 되는지 확인한 뒤 프로세스를 중지하세요.

### 명령 가져오기 및 내보내기

- 명령의 내보내기 버튼으로 해당 명령을 내보내며 화면 옵션에 따라 종속 호스트 설정도 포함할 수 있습니다.
- 명령 가져오기(‘导入指令’)에서 `.tscfg`를 고르고 미리본 뒤 필요하면 기존 설정을 덮어쓰거나 표시된 호스트에 연결합니다.

동일한 이름의 설정을 덮어쓸 수 있고 원격 호스트 정보가 포함될 수 있습니다. 서명, 인증서 신뢰, 출처는 보안 가이드에 따라 확인하세요. 재시작이 필요하면 터미널과 자동화 작업을 먼저 종료합니다.

삭제 전에 데이터 소스나 동작 템플릿이 참조하지 않는지 확인하세요. 명령 페이지에서 삭제를 취소할 수는 없습니다.

## 12. 자동화 관리

자동화(‘自动化’)는 장치 데이터와 조작을 반복 실행 가능한 흐름으로 연결합니다.

```text
자동 실행: 데이터 소스 → 변수 → 규칙 판단 → 동작 실행
수동 실행: 시스템 페이지 빠른 작업 → 동작 실행
```

- 데이터 소스는 외부 또는 장치 데이터를 읽습니다.
- 변수는 판단에 쓸 값을 저장합니다.
- 규칙은 실행 시점을 결정합니다.
- 동작 템플릿은 수행할 작업을 정의합니다.
- 수동 전용 규칙은 시스템 페이지의 빠른 작업에 표시됩니다.

### 자동화 엔진 확인 및 제어

위쪽에는 엔진 상태, 규칙 수, 변수 수, 데이터 소스 수, 트리거 횟수, 실행 시간이 표시됩니다.

| 조작 | 영향 |
| --- | --- |
| 시작(‘启动’) | 정지한 엔진을 시작하고 활성 규칙을 처리합니다. |
| 일시 중지(‘暂停’) | 이후 자동 판단을 멈추고 설정을 유지합니다. 시작된 동작은 계속될 수 있습니다. 재개하려면 ‘停止’ 후 ‘启动’을 선택합니다. |
| 중지(‘停止’) | 규칙 처리와 데이터 소스 읽기를 멈춥니다. 설정은 지우지 않습니다. |
| 다시 로드(‘重新加载’) | 저장된 엔진 설정을 다시 읽습니다. 실행 중이었다면 로드 후 재개합니다. 편집 내용을 먼저 저장하세요. |

냉각, 경보 등 지속 작업이 자동화에 의존하는지 먼저 확인하세요. 일시 중지나 중지로 이미 제출한 비동기 동작이나 원격 백그라운드 프로세스가 끝난다고 보장할 수 없습니다. 해당 작업 페이지에서 확인하고 조작 후 상태를 새로고침하세요.

### 최소 자동화 흐름 구성

다음 순서를 권장합니다.

1. 데이터 소스를 만들고 화면의 시험 기능으로 연결을 확인합니다.
2. 소스를 켠 뒤 변수 영역에 필요한 값이 나타나는지와 갱신 시각을 확인합니다.
3. 동작 템플릿을 만들고 매개변수를 확인한 뒤 시험(‘测试’)합니다. 즉시 실행되므로 장치와 원격 호스트에서 허용되는 작업인지 먼저 확인하세요.
4. 규칙을 만들되 즉시 활성화(‘立即启用’)는 아직 선택하지 않습니다.
5. 조건, 재실행 대기 시간, 동작 순서, 지연, 반복 설정을 확인합니다.
6. 저장 후 활성화하여 변수, 트리거 횟수, 실제 결과를 관찰합니다.

### 데이터 소스 관리

데이터 소스(‘数据源’)의 추가(‘添加’)에서 지원 유형을 선택합니다.

| 유형 | 용도 |
| --- | --- |
| ‘REST API’ | HTTP 주소의 데이터를 주기적으로 읽습니다. |
| ‘WebSocket’ | 지속 연결로 전달되는 데이터를 받습니다. |
| ‘Socket.IO’ | Socket.IO 서비스의 이벤트 데이터를 받습니다. |
| 명령 변수(‘指令变量’) | 명령 페이지에 저장된 실행 결과를 읽습니다. |

REST API는 URL로 데이터를 요청하는 방식이며 WebSocket과 Socket.IO는 갱신을 지속해서 받는 방식입니다. 명령 변수는 설정한 SSH 명령의 결과입니다.

1. ID, 표시 라벨, 유형에 필요한 연결 정보를 입력합니다.
2. 연결 시험(‘测试连接’) 또는 해당 시험 버튼을 사용합니다.
3. REST API, WebSocket, Socket.IO는 시험 결과에서 저장할 필드를 선택합니다. Socket.IO 이벤트 이름을 비우면 시험 기능이 서버의 이벤트 발견을 시도합니다.
4. 명령 변수는 호스트와 저장 변수 이름이 설정된 명령을 고른 뒤 검사 간격을 설정합니다.
5. 저장하고 켠 뒤 변수 영역에서 결과를 확인합니다.

목록에는 유형, 상태, 갱신 간격이 표시됩니다. 켜기·끄기, 변수 확인, 내보내기, 삭제가 가능합니다. 끄거나 삭제하면 종속 규칙이 판단하지 못할 수 있으므로 먼저 참조를 확인하세요.

가져오기와 내보내기는 설정 패키지를 사용합니다. ID, 유형, 대상 설정을 미리보고 동일 이름을 덮어쓰기 전에 기존 규칙의 의존 관계를 확인하세요. 신뢰 판단은 보안 가이드를 참고합니다.

### 변수 확인

변수(‘变量’)에는 현재 자동화가 사용할 수 있는 데이터가 표시됩니다. 검색창으로 이름을 필터링합니다.

다음 항목을 확인하세요.

- 이름과 데이터 소스가 예상과 일치하는지.
- 현재 값과 데이터 유형이 규칙 비교에 적합한지.
- 갱신 시각이 계속 바뀌는지.
- 데이터 만료 또는 유효 데이터 없음이 표시되는지.

갱신되지 않으면 소스가 켜져 있는지 확인하고 시험 기능으로 연결과 필드 선택을 점검합니다.

### 동작 템플릿 생성 및 시험

규칙이 트리거되면 실행할 작업을 정의합니다. 동작 템플릿(‘动作模板’)의 추가(‘添加’)에서 유형을 고릅니다.

| 유형 | 기능 |
| --- | --- |
| CLI 명령(‘CLI 命令’) | TianshanOS 로컬 콘솔 명령 실행. |
| SSH 명령(‘SSH 命令’) | 명령 페이지에 등록된 원격 명령 실행. |
| LED 제어(‘LED 控制’) | 지원 LED와 표시 기능 제어. |
| 로그 기록(‘日志记录’) | 지정 수준으로 로그 한 건 기록. |
| 변수 설정(‘设置变量’) | 지정 값을 자동화 변수에 기록. |
| ‘Webhook’ | 지정 HTTP 주소로 요청 전송. |

CLI는 장치 로컬에서, SSH는 원격에서 실행합니다. Webhook은 외부 서비스 알림이나 호출에 사용합니다.

모든 템플릿에는 고유 ID가 필요합니다. 표시 이름, 설명, 실행 지연을 지정하고 필요하면 비동기 실행(‘异步执行’)을 켭니다. 비동기 동작은 제출 후 백그라운드에서 계속되므로 로그, 변수, 대상 장치로 상태를 확인해야 합니다.

유형별 추가 항목은 다음과 같습니다.

- CLI: 명령줄, 선택적인 결과 변수와 시간 제한.
- SSH: 화면의 호스트·명령 선택 및 미리보기 확인.
- LED: 장치와 지원되는 색상, 애니메이션, 밝기, 텍스트, 이미지, QR 코드, 필터 조작.
- 로그: 수준과 메시지. 변수 참조가 가능합니다.
- 변수 설정: 변수 이름과 값.
- Webhook: 요청 방식, URL, 요구되는 요청 내용. JSON은 구조화된 요청 내용을 쓰는 텍스트 형식입니다.

시험은 즉시 동작을 실행합니다. 전원 차단, 재시작, 원격 명령, LED 표시, 외부 요청의 영향을 먼저 확인하고 시험 성공 후 규칙에 추가하세요.

삭제 전에 규칙의 참조를 확인하세요. 가져오기는 같은 이름의 동작을 덮어쓸 수 있습니다. 패키지 신뢰 요건은 보안 가이드를 참고하세요.

### 규칙 생성

규칙은 변수 조건과 동작 템플릿을 연결합니다.

1. 규칙(‘规则’)의 추가(‘添加’)를 선택합니다.
2. 고유 규칙 ID(‘规则 ID’), 이름, 아이콘을 입력합니다.
3. 조건 논리(‘条件逻辑’)를 선택합니다.
- AND: 모든 조건을 만족하면 트리거합니다.
- OR: 하나라도 만족하면 트리거합니다.
4. 재실행 대기 시간(‘冷却时间’)으로 연속 트리거 빈도를 제한합니다.
5. 조건의 변수, 비교 방식, 값을 설정합니다.
6. 템플릿을 하나 이상 추가하고 실행 순서에 필요한 지연을 설정합니다.
7. 확인 후 저장하고 실행이 필요할 때 켭니다.

비교 방식은 같음, 같지 않음, 큼, 크거나 같음, 작음, 작거나 같음, 값 변경, 포함입니다. 비교값은 변수 유형과 맞아야 합니다.

### 동작 반복 및 실행 조건 설정

각 동작에서 다음을 선택할 수 있습니다.

- 한 번(‘单次’): 규칙 트리거마다 한 번 실행합니다.
- 조건 지속 시 반복(‘条件持续时重复’): 개별 실행 조건을 판단하고 간격마다 계속합니다. 한 실행 주기에서 최대 100회입니다.
- 횟수 지정(‘指定次数’): 지정 횟수와 간격으로 반복합니다.

개별 동작 조건과 규칙 전체의 트리거 조건은 별도로 설정합니다. 조건 지속 반복을 쓰기 전에 해당 동작의 실행 조건을 지정하세요. 비워 두면 회차 상한까지 반복합니다. 상한 후에도 규칙이 다시 트리거될 수 있습니다.

규칙을 꺼도 이후 자동 트리거만 막고 시작된 반복은 계속될 수 있습니다. 끈 뒤 실행 중인 동작을 확인하세요. 원격 작업은 명령 페이지에서 해당 프로세스를 중지하고 종료 여부를 확인합니다.

### 빠른 작업 생성

수동 트리거 전용(‘仅手动触发’)을 선택하면 트리거 조건 없이 시스템 페이지에 카드로 표시됩니다.

1. 규칙 ID, 이름, 아이콘을 입력합니다.
2. 수동 트리거 전용(‘仅手动触发’)을 선택합니다.
3. 필요한 동작 템플릿을 추가합니다.
4. 저장하고 켜야 시스템 페이지에 표시됩니다.
5. 시스템의 빠른 작업에서 카드를 확인하고 한 번 실행하여 결과를 확인합니다.

수동 규칙도 모든 동작, 지연, 반복 설정을 실행합니다. admin에게 제공하기 전에 이름이 명확하고 위험을 예상할 수 있으며 로그나 중지 수단이 있는지 확인하세요.

### 규칙과 설정 유지보수

목록에서 켜기·끄기, 수동 트리거, 편집, 내보내기, 삭제가 가능합니다.

- 수동 트리거는 활성 상태나 재실행 대기 시간과 관계없이 동작을 실행합니다. 꺼진 규칙도 읽기 전용 점검처럼 취급하지 마세요.
- 끄기는 이후 자동 트리거를 막으며 완료된 동작을 취소하지 않습니다.
- 삭제는 페이지에서 취소할 수 없습니다.
- 편집 전에 변수와 템플릿이 여전히 있는지 확인합니다.
- 가져오기 전에 ID, 조건, 동작 참조를 미리보고 동일 이름 덮어쓰기의 영향을 확인합니다.

데이터 소스, 동작, 규칙을 가져오거나 수정한 뒤 엔진과 목록의 활성 상태를 확인하세요. 다시 로드하거나 재시작해야 한다면 실행 중인 원격 작업을 먼저 종료한 뒤 진행합니다.
