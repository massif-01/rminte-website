# TianshanOS 루트 작업 가이드

<!-- operational-note -->
이 가이드에서는 파트 I의 루틴 기능과 파트 II의 터미널 액세스, 원격 명령, 자동화 및 구성 백업을 다룹니다. Root 작업은 장치와 원격 호스트에 영향을 미칠 수 있습니다. 계속하기 전에 대상 및 활성 작업을 확인하십시오. 보안 관리는 별도의 보안 가이드를 참조하세요.

대상 버전: 0.6.4. 개정일: 2026년 11월 3일.

장치에 표시된 컨트롤을 사용하십시오. 일부는 특정 하드웨어나 구성이 필요합니다. 컴퓨터에서는 아이콘 버튼 위로 마우스를 가져가면 해당 이름을 볼 수 있습니다. 휴대전화에서는 넓은 표 내에서 스와이프하여 다른 열을 볼 수 있습니다.

## 1부: 일상 기능

### 1. 시작하기

#### WebUI를 엽니다.

1. 관리자가 제공한 주소를 사용하여 장치의 웹 인터페이스(WebUI)를 엽니다.
2. 오른쪽 상단에서 "로그인"을 선택합니다.
3. 장치와 함께 제공된 `root` 및 root 비밀번호를 입력합니다.
4. "로그인"을 선택합니다. 로그인에 성공하면 현재 사용자 이름이 오른쪽 상단에 나타납니다.

기본 비밀번호로 로그인하면 "보안 알림"이 열립니다. 현재 비밀번호를 입력한 후 새 비밀번호를 두 번 입력하고 '지금 변경'을 선택하세요. 두 새 비밀번호 항목이 모두 일치해야 합니다. 알림을 닫으려면 “나중에”를 선택하세요.

작업이 끝나면 오른쪽 상단에 있는 “로그아웃”을 선택하세요. 기기를 사용하려면 다시 로그인해야 합니다.

권한이 거부된 경우 계정을 확인하세요. 로그인이 만료된 경우 다시 로그인하세요. 그런 다음 이전 작업의 결과를 확인합니다. 로그인해도 이전 작업이 반복되지 않습니다. 즉시 업로드하거나 삭제하거나 다시 업그레이드하지 마세요.

#### 언어 전환

페이지 상단의 언어 버튼을 선택한 다음 중국어 또는 영어를 선택하세요. 페이지 콘텐츠와 컨트롤 레이블이 즉시 전환됩니다.

#### 페이지 탐색

루트 사용자는 다음 페이지에 액세스할 수 있습니다.

- “System”: 장치 상태, 제어 모듈, 팬 및 LED를 보고 OTA 업데이트를 엽니다.
- “Network”: 이더넷 상태 및 DHCP 클라이언트를 확인하고, WiFi를 구성하고, NAT 전달을 관리합니다.
- “Files”: SD 카드 및 SPIFFS의 파일을 관리합니다.
- “Terminal”: 장치 명령을 실행하고 시스템 로그를 봅니다.
- “Commands”: 원격 SSH 명령을 관리하고 실행합니다.
- “Automation”: 작업을 구성하고 긴급 백업을 저장합니다.
- “Security”: 별도의 보안 관리 페이지를 엽니다. 지침은 보안 가이드를 참조하세요.

### 2. 시스템 상태 및 일상적인 운영

상단 탐색에서 "시스템"을 선택합니다.

#### 리소스 및 서비스 상태 보기

"관리 칩 리소스"에는 관리 칩의 CPU, DRAM 및 PSRAM 사용량이 표시됩니다. 이러한 판독값에는 추론 컴퓨터 또는 애플리케이션 컴퓨터의 리소스 사용량이 표시되지 않습니다.

- "세부 정보"를 선택하면 전체 메모리, 사용된 메모리, 사용 가능한 메모리 및 기타 메모리 정보를 볼 수 있습니다.
- 메모리 세부 정보에서 "추정"이라고 표시된 값은 단지 참고용입니다. 경고가 나타나면 페이지 정보를 유지하고 안내에 따르세요.
- “서비스”는 실행 중인 서비스 수와 총계를 보여줍니다. 각 서비스의 상태와 시작 단계를 보려면 선택하세요.
- 서비스에서 문제를 보고하면 해당 상태를 새로 고칩니다. 다시 시작하려면 아래 "One Service 다시 시작"을 따르세요.

#### 시스템 및 전원 정보 보기

“시스템 개요”에는 칩, 펌웨어 버전, ESP-IDF 버전 및 가동 시간이 표시됩니다. 일상적으로 사용하려면 펌웨어 버전을 확인하세요. ESP-IDF는 장치에서 사용되는 시스템 프레임워크 버전입니다.

카드 오른쪽에는 입력 전압, 내부 전압, 전류, 전력 및 보호 상태가 표시됩니다.

네트워킹, 팬, 온도, 조명 등의 시스템 설정은 장치 내부에 저장됩니다. 기존 SD 카드를 삽입해도 복원되지 않습니다. 자동화 구성은 별도로 관리됩니다. 긴급 백업은 전체 장치 백업이 아닙니다.

보호 상태 옆의 스위치는 저전압 보호를 활성화하거나 비활성화합니다. 활성화되면 장치는 저장된 전압과 지연을 사용하여 저전압에서 종료되고 전원이 복구된 후 다시 시작됩니다.

#### 네트워크 및 시간 보기

“네트워크 및 시간”에는 이더넷, WiFi, IP 주소, 현재 시간, 동기화 상태, 시간 소스 및 시간대가 표시됩니다.

- 브라우저의 현재 시간을 장치에 복사하려면 “동기화 시간”을 선택하세요.
- "시간대"를 선택하고 사전 설정을 선택하거나 지원되는 시간대 설정을 입력한 다음 저장합니다.
- "OTA 업데이트"를 선택하여 펌웨어 업데이트 페이지를 엽니다.

#### 고급 운영

##### TianshanOS 재부팅

재부팅하면 WebUI 및 장치 관리가 일시적으로 중단됩니다. 활성 작업을 마친 다음 "재부팅"을 선택하고 확인합니다. 장치가 복구될 때까지 기다린 다음 WebUI를 다시 엽니다.

##### 서비스 하나 다시 시작

서비스를 다시 시작하면 해당 서비스가 제공하는 기능이 일시적으로 중단됩니다. "서비스 상태"를 열고 영향을 받는 서비스를 찾은 다음 해당 행에서 "재부팅"을 선택하십시오. 작업이 완료되면 상태를 다시 확인하세요.

##### 종료 설정 변경

이 설정은 전압 강하 후 장치가 종료되는 시기와 전원이 복구된 후 다시 시작되는 시기를 제어합니다. 장치의 전원 요구 사항과 일치하는 값을 사용하십시오.

변경하려면 "종료 설정"을 선택하십시오.

- "저전압 임계값": 이 전압 아래에서 종료 카운트다운을 시작합니다.
- “복구 전압 임계값”: 전압이 이 값보다 높아지면 복구를 시작합니다.
- “종료 카운트다운”: 저전압을 감지한 후 종료까지 기다리는 시간을 설정합니다.
- “복구 유지 시간”: 전원이 안정적으로 복구되었는지 확인하기 위해 기다리는 시간을 설정합니다.
- “팬 정지 지연”: 종료 후 팬이 멈출 때까지 기다리는 시간을 설정합니다.

변경한 보호 설정을 적용하려면 양식을 저장하세요.

"종료 설정"을 연 후 현재 설정이 로드될 때까지 기다립니다. 페이지에 기본값이 표시되어 있다고 표시되면 이를 장치의 현재 설정으로 취급하지 마십시오. 저장하기 전에 전압과 대기 시간을 검토하십시오. 로딩 중에 취소할 수 있습니다.

##### 상단 USB 대상 전환

<!-- operational-note -->
USB 연결 대상을 바꾸면 연결된 장치가 일시적으로 끊길 수 있습니다. 진행하기 전에 대상을 확인하고 진행 중인 작업을 마치세요.

USB 전환을 지원하는 장치에는 "USB" 버튼이 표시됩니다. 클릭할 때마다 상단 USB 포트가 다음 대상인 ESP, 추론 컴퓨터, 애플리케이션 컴퓨터로 전환됩니다. "연결 끊김"은 연결된 대상이 없음을 의미합니다. 버튼에 표시된 대상과 페이지 메시지를 확인하여 결과를 확인하세요.

### 3. 장치 패널

“장치 패널”은 “시스템” 페이지에 있습니다. 모듈 전원 제어, 빠른 작업, 데이터 위젯을 제공합니다.

#### 추론 컴퓨터 및 애플리케이션 컴퓨터 제어

"추론 컴퓨터"는 이전 AGX 레이블입니다. "애플리케이션 컴퓨터"는 이전 LPMU 레이블입니다. 장치 식별자와 명령은 계속해서 `agx` 및 `lpmu` 를 사용할 수 있습니다. 해당 식별자의 이름을 직접 바꾸지 마십시오.

<!-- operational-note -->
모듈의 전원을 끄기 전에 작업을 저장하고 정상 종료를 완료하세요. 강제 전원 차단으로 저장하지 않은 데이터가 사라질 수 있습니다.

- 「추론 컴퓨터 전원」은 전원 제어 상태를 표시합니다. 버튼으로 전원을 켜거나 끈 뒤 확인 결과를 기다리세요.
- 「애플리케이션 컴퓨터 전원」의 「네트워크 연결 가능／불가」는 네트워크로 접근할 수 있는지를 뜻합니다. 확인에 실패하면 전원 상태는 알 수 없는 상태로 남습니다. 이 결과만으로 컴퓨터 전원이 켜졌는지 꺼졌는지 판단하지 마세요.
- 애플리케이션 컴퓨터 버튼을 선택하면 물리적 전원 버튼을 누르는 것과 동일한 동작이 트리거됩니다. 검사와 표시된 결과를 기다립니다. 결과를 알 수 없는 경우 버튼을 다시 누르기 전에 컴퓨터와 네트워크를 확인하세요.

#### 빠른 작업 사용

빠른 작업 카드는 root 사용자가 설정합니다. 카드 표시와 수동 실행 허용은 별도의 설정입니다. 카드가 보여도 작업을 실행할 수 없는 경우가 있습니다.

1. 카드 이름과 설명을 읽고 작업을 식별하세요.
2. "시작" 또는 카드를 선택하고 결과를 읽습니다. 처리하는 동안 다시 시작하지 마십시오.
3. 실행되거나 대기 중인 메시지에는 여전히 대상 장치 또는 작업에 대한 실제 결과 확인이 필요합니다. 서비스 상태가 표시되면 "프로세스 실행 중"과 "준비"를 구분합니다. 여러 작업이 포함된 카드에는 '일부 작업이 준비되지 않았습니다.'라고 표시될 수 있습니다.

원격 백그라운드 작업이 포함된 카드는 '로그 보기' 및 '중지'도 제공합니다. 로그를 열어 관련 작업을 검토하세요. 여러 레코드가 나타나면 작업 이름과 원래 호스트를 기준으로 선택하세요. 중지하기 전에 대상을 확인하고 결과를 기다린 다음 중지되었는지 확인하십시오. 로그를 닫거나 로그 업데이트를 중지해도 작업이 중지되지 않습니다.

「실행 기록」에는 이전에 시작한 작업도 남아 있습니다. 기록만으로 현재 실행 중이라고 판단하면 안 됩니다. 필요하면 「원격 상태 확인」을 선택하세요. 관련 카드, 「시스템」, 「자동화」에서 기록을 열 수 있습니다(11장). 조작할 수 없거나 결과가 불분명하면 실행 기록과 시스템 로그를 확인하세요.

시작할 수 없으면 표시된 이유에 따라 처리하세요. 시작 버튼을 반복해서 누르지 마세요:

- 규칙 비활성화 또는 수동 트리거링이 허용되지 않음: “Automation”(12장)의 규칙 설정을 확인하세요. 눈에 보이는 카드는 실행 권한이 없습니다.
- 작업 또는 백그라운드 작업이 진행 중입니다. 결과를 기다립니다. 다시 시작하지 마십시오.
- 작업에 대한 실행 기록이 이미 존재합니다. 다시 시작하는 대신 원래 작업의 상태와 로그를 확인하세요. 종료해야 하는 경우 중지하고 확인하세요. 해결할 수 없는 경우 "실행 기록" 및 시스템 로그를 확인하십시오.
- 구성이 로드되지 않았거나 필수 항목이 누락되었거나 자동화가 일시 중지되었습니다. “Automation”의 구성 및 활성화 상태를 확인하십시오(12장 및 13장).

자동 시작 중이거나 재시도를 기다린다는 안내가 나오면 기다리세요. 일시적인 시작 실패는 30초마다, 최대 6분 동안 재시도합니다. 시작 결과가 불분명하면 다시 시작하기 전에 상태를 확인합니다. 수동 실행 실패는 자동으로 반복하지 않습니다. 대기 시간이 끝나면 안내에 따라 장치와 네트워크를 확인한 뒤 「시작」 여부를 결정하세요.

하나의 작업을 실행한 후 다른 작업을 시작하기 전에 몇 초 정도 기다리십시오. 페이지를 닫거나, 카드를 삭제하거나, TianshanOS를 다시 시작해도 원격 호스트의 백그라운드 서비스가 중지되지 않습니다. 서비스를 중지된 상태로 유지하려면 자동화에서 다시 시작할 수 있는 자동 규칙을 비활성화하세요.

재정렬 표시가 나타날 때까지 카드를 길게 누른 다음 끌어서 표시 순서를 변경합니다.

카드가 나타나지 않으면 설명을 읽어보세요. 구성이 로드되는 동안 기다리십시오. 로딩에 실패한 경우 원인을 유지하고 터미널에서 “System Logs”를 확인하세요. 빠른 작업이 구성되지 않은 경우 “Open Automation”를 선택하고 규칙의 “Show on panel” 설정을 확인하세요.

규칙을 편집하거나 가져오면 현재 구성이 업데이트됩니다. 규칙을 전환하기 위해 다시 시작할 필요는 없습니다. 카드의 작업이 변경된 경우 실행하기 전에 조건, 작업 및 대상을 검토하세요.

단지 카드를 복원하기 위해 활성 서비스를 제공하는 장치를 다시 시작하지 마십시오.

#### 데이터 위젯 관리

데이터 위젯은 "장치 패널"에 장치 데이터를 지속적으로 표시합니다.

1. "위젯 관리자"를 선택합니다.
2. 새로 고침 간격을 선택하거나 자동 새로 고침을 비활성화합니다.
3. 사전 설정된 위젯을 추가하거나 페이지에서 제공하는 구성요소 스타일 및 데이터 소스를 선택하세요.
4. 필요에 따라 레이블, 표시 스타일 및 단위를 편집한 다음 저장합니다.

기존 위젯을 편집, 삭제 및 재정렬할 수 있습니다. 위젯 카드를 선택하여 편집할 수도 있습니다. 위젯을 길게 누른 다음 새 위치로 드래그하세요.

"Small", "Medium" 및 "Large"는 1개, 2개, 3개 열을 사용합니다. 더 좁은 화면에 맞습니다. 아이콘을 편집할 때 페이지의 예시를 사용하여 이름을 입력하세요. 이중 값 위젯의 각 값에는 고유한 데이터 설정이 있습니다. 두 소스가 모두 올바른지, 데이터가 업데이트되는지 확인하세요.

"데이터 위젯을 로드하지 못했습니다"라고 해서 구성이 존재하지 않는다는 의미는 아닙니다. 원인을 해결하고 다시 읽어보세요. 저장에 실패하거나 결과가 확인되지 않는 경우 현재 내용을 유지하고 메시지를 확인하세요. 페이지에서 변경 사항을 확인한다고 해서 저장되었는지 확인할 수는 없습니다.

### 4. 팬 관리

"팬 제어"는 "시스템" 페이지에 있습니다. 팬 카드에는 장치에서 제공하는 팬이 표시됩니다. 곡선을 변경하기 전에 팬 수를 확인하십시오.

#### 팬 상태 보기

상태 표시줄에는 “유효 온도”와 “현재 출력”이 표시됩니다. 큰 백분율은 장치가 설정을 확인한 팬 조절값이며, 측정된 회전수가 아닙니다. RPM은 1분 동안의 실제 회전수입니다. 유효한 측정값이 없으면 표시되지 않습니다. 큰 표시가 `--`이면 현재 출력이 확인되지 않은 상태입니다.

수동 슬라이더를 움직이면 옆에 설정하려는 값이 표시됩니다. 큰 백분율은 현재 출력을 계속 보여줍니다. 슬라이더를 놓은 뒤 메시지와 갱신된 값을 확인하세요. 요청한 값과 현재 출력이 다르면 설정이 적용됐다고 판단하지 마세요.

스마트 모드는 “스마트 모드”, “곡선에 따라 작동”, 보호 상태, 유효하지 않은 온도 등의 상태를 표시합니다. 안전 기준 온도, 45초 후 예상 온도, 온도 변화 속도도 확인할 수 있습니다.

온도가 유효하지 않게 되면 소스가 계속 업데이트되고 있는지 확인하세요. 장치는 온도 손실에 대한 보호 제어로 전환됩니다. 스마트 열 제어에 대한 설명을 보려면 “TTI”를 선택하세요.

현재 상태를 가져오려면 섹션 헤더의 새로 고침 버튼을 사용하세요. 조정이 실패하거나 출력이 확인되지 않는 경우, 재시도 여부를 결정하기 전에 장치를 확인하십시오.

#### 작동 모드 선택

| 모드 | 목적 |
| --- | --- |
| "끄기" | 팬을 중지합니다. |
| "수동" | 0-100% 슬라이더로 설정된 고정 제어 비율을 사용합니다. |
| “곡선” | 구성된 온도-제어 백분율 곡선을 따릅니다. |
| “스마트” | 기본 곡선, 온도 추세 및 과거 조정을 사용하여 냉각을 제어합니다. 필요할 때 보호 제어를 사용합니다. |

팬을 중지하거나 수동 값을 낮게 설정하면 냉각 성능이 저하됩니다. 부하와 온도를 먼저 확인하고 계속 모니터링하세요. 슬라이더는 현재 출력이 확인된 경우 수동 모드에서만 사용할 수 있습니다.

#### 팬 곡선 구성

팬 제어 섹션 헤더에서 "곡선"을 선택하여 "팬 곡선 관리"를 엽니다. 카드 내부의 "곡선" 버튼은 작동 모드만 변경합니다.

1. "Fan"에서 조정할 숫자를 선택하고 시스템 페이지에서 확인합니다.
2. '온도 변수 바인딩'에서 온도 변수를 추가하고 가중치를 할당합니다.
3. "바인딩"을 선택합니다. 온도 소스는 곡선 및 스마트 모드의 팬이 공유하므로 온도 소스를 변경하면 해당 소스를 사용하는 팬에 영향을 줍니다.
4. "곡선 노드"를 추가하거나 편집합니다. 각 곡선에는 최소 2 노드가 필요하며 최대 10를 지원합니다.
5. "최소 속도"와 "최대 속도"를 제어 비율로 설정합니다. 최소값은 최대값을 초과하면 안 됩니다.
6. “온도 히스테리시스”와 “최소 간격”을 설정하세요. 히스테리시스 범위는 0-20°C이며, 작은 온도 변화로 팬이 자주 조절되는 것을 줄입니다. 최소 간격은 500-30000 ms입니다. 1000 ms는 1초입니다.
7. "곡선 저장"을 선택합니다. 성공적으로 저장되면 선택한 팬이 곡선 모드로 전환됩니다. 스마트 열 제어를 사용하려면 카드로 돌아가서 '스마트'를 선택하세요.

저장에 실패하면 메시지를 읽고 현재 상태를 확인한 후 다시 시도하세요. 온도 변수 바인딩을 해제한 후 유효 온도와 팬 상태도 확인하세요.

설정을 열거나 다른 팬을 선택한 후 현재 설정이 로드될 때까지 기다립니다. 페이지에 기본값이나 이전 초안이 표시되고 있다고 표시되면 해당 값은 장치의 현재 설정을 확인하지 않는 것입니다. 저장하기 전에 검토하세요. 온도 바인딩에 대한 읽기 및 저장 결과도 확인하세요.

팬 설정이 적용되었지만 완전히 저장되지 않았다는 메시지가 나타나면 현재 조정이 이미 적용되었을 수 있습니다. 다시 시작하면 이전 설정이 복원될 수 있습니다. 실제 팬 상태를 확인하고 기기 저장 공간이 사용 가능한지 확인한 후 다시 저장하세요. 저장이 작동했는지 테스트하기 위해 장치를 다시 시작하지 마십시오.

#### 곡선 가져오기 및 내보내기

- "Import Config"를 선택하고 곡선 JSON 파일을 선택합니다. JSON는 곡선 데이터를 저장하는 데 사용되는 파일 형식입니다. 노드, 제한 및 팬 수를 검토한 다음 "곡선 저장"을 선택하여 적용합니다.
- 현재 곡선을 다운로드하려면 "구성 내보내기"를 선택하십시오. 또한 페이지는 SD 카드의 `/sdcard/config` 아래에 복사본을 저장하려고 시도합니다. 브라우저 다운로드와 보고된 SD 카드 결과를 별도로 확인하세요.

#### 테스트 온도 사용

테스트 온도는 일시적으로 일반 소스를 대체하고 곡선 또는 스마트 제어에 영향을 미칩니다. 테스트 전반에 걸쳐 팬과 장치를 모니터링합니다.

1. "테스트 온도" 아래에 0-100°C를 입력합니다.
2. "테스트"를 선택하고 현재 출력, 상태 및 팬 응답을 관찰합니다.
3. 테스트를 마치면 “테스트 지우기”를 선택하세요. 유효 온도가 원래의 온도 데이터에서 다시 읽히는지 확인하세요.

### 5. LED 관리

"LED 제어"는 "시스템" 페이지에 있으며 장치에서 제공하는 LED를 표시합니다. 사용 가능한 기능은 LED에 따라 다릅니다.

#### 일상적인 제어

- 카드 하단에 있는 전구 버튼을 사용하여 LED를 켜거나 끌 수 있습니다.
- 밝기, 색조 및 채도 슬라이더를 사용하십시오. 밝기는 빛의 밝기를 제어합니다. 색조는 색상을 선택합니다. 채도는 흰색과 색상 사이를 이동합니다. 0의 채도는 백색광을 제공합니다. 슬라이더를 놓으면 색조 및 채도 변경 사항이 적용됩니다.
- 애니메이션 버튼을 사용하여 "LED 설정"을 엽니다. "프로그래밍 방식 애니메이션"에서 애니메이션을 선택한 다음 해당 애니메이션의 재생 또는 중지 제어를 사용합니다.
- 현재 LED 구성을 저장하려면 카드 오른쪽 하단에 있는 저장 아이콘을 선택하세요.
- "All Off"를 선택하면 모든 LED가 꺼지고 보고된 결과를 확인할 수 있습니다. 일부가 실패하면 해당 장치를 확인하십시오.

#### 고급 LED 매트릭스 기능

매트릭스 카드는 사용 가능한 기능에 대한 아이콘을 제공합니다. 하나를 연 다음 "LED 설정"에서 다음 그룹 간에 전환하세요.

- “프로그래밍 방식 애니메이션”: 애니메이션을 선택하고 실행합니다.
- "이미지/QR 코드": 카드의 "유형"에서 이미지 또는 QR 코드를 선택한 다음 SD 카드 이미지를 선택하거나 QR 콘텐츠를 입력합니다.
- "텍스트 표시": 텍스트, 글꼴, 정렬, 스크롤, 전경 및 배경을 설정합니다.
- "사후 처리 필터": 필터와 매개변수를 선택한 다음 적용하거나 중지합니다.
- "색상 교정": 디스플레이를 조정하고 사용 가능한 재설정, 가져오기 또는 내보내기 컨트롤을 사용합니다.

변경 사항을 적용한 후 실제 조명 또는 매트릭스 디스플레이를 확인하십시오. 표시된 기능만 사용하세요. 설정에 실패할 경우 메시지에 따라 파일, 입력, 기기 상태를 확인하세요.

### 6. 네트워크 관리

<!-- operational-note -->
상단 탐색 메뉴에서 "네트워크"를 선택하여 "네트워크 설정"을 엽니다. 네트워크 모드, 핫스팟 또는 NAT 설정을 변경하면 현재 WebUI 연결이 중단될 수 있습니다. 저장하기 전에 새 네트워크 주소를 통해 다시 연결할 수 있는지 확인하세요.

#### 네트워크 상태 보기

페이지 상단에는 이더넷, WiFi 클라이언트 및 WiFi AP의 상태가 표시됩니다. 관련 패널을 열어 IP 주소, 서브넷 마스크, 게이트웨이, DNS, MAC 주소, SSID, 신호 및 연결된 장치 수(사용 가능한 경우)를 확인하세요.

이더넷 패널에는 현재 링크 및 주소 정보가 표시됩니다. 주소 편집 제어 기능은 제공하지 않습니다.

#### WiFi 모드 선택

| 모드 | 목적 |
| --- | --- |
| "끄기" | WiFi를 끕니다. |
| “역(STA)” | 장치를 기존 WiFi 네트워크에 연결합니다. |
| “액세스 포인트(AP)” | 장치가 WiFi 핫스팟을 제공하도록 합니다. |
| “STA+AP” | 장치 핫스팟을 사용 가능한 상태로 유지하면서 기존 WiFi 네트워크에 연결합니다. |

<!-- operational-note -->
모드를 선택한 후 페이지가 상태를 새로 고칠 때까지 기다립니다. 전환하는 동안 현재 무선 연결이 중단될 수 있습니다.

#### WiFi에 연결

1. WiFi 모드를 "스테이션(STA)" 또는 "STA+AP"로 설정합니다.
2. "스테이션"에서 "스캔"을 선택합니다.
3. 목록에서 네트워크를 선택합니다. 목록에는 SSID, 신호 강도, 채널 및 인증 유형이 표시됩니다.
4. 비밀번호를 입력하고 확인하세요. 개방형 네트워크의 경우 비밀번호를 비워 두세요.
5. 상태가 "연결됨"으로 변경될 때까지 기다린 다음 새 IP 주소를 확인합니다.

현재 WiFi 클라이언트 연결을 종료하려면 "연결 끊기"를 선택하십시오.

#### WiFi AP 구성

1. WiFi 모드를 "액세스 포인트(AP)" 또는 "STA+AP"로 설정합니다.
2. "핫스팟"에서 "구성"을 선택합니다.
3. SSID를 입력합니다. 빈 비밀번호는 공개 핫스팟을 생성합니다. 보호된 핫스팟에는 최소한 8 문자가 필요합니다.
4. 채널을 선택하고 필요한 경우 "SSID 숨기기"를 활성화합니다.
5. "적용"을 선택하고 핫스팟 상태가 업데이트될 때까지 기다립니다.

현재 핫스팟에 연결된 클라이언트를 보려면 "장치"를 선택합니다.

#### 호스트 이름 설정

"네트워크 서비스" 아래의 "호스트 이름" 섹션에 새 이름을 입력한 다음 "설정"을 선택합니다. 페이지에는 업데이트 후 현재 호스트 이름이 표시됩니다.

#### DHCP 클라이언트 보기

DHCP는 연결된 장치에 네트워크 주소를 자동으로 할당합니다. "클라이언트"를 선택하고 "WiFi AP" 또는 "이더넷"을 선택한 다음 현재 임대를 확인하세요. 목록을 다시 로드하려면 새로고침 버튼을 사용하세요.

#### 고급 네트워크 운영

##### NAT 게이트웨이 구성

NAT는 장치의 네트워크 인터페이스 간에 네트워크 트래픽을 전달합니다. NAT를 활성화 또는 비활성화한 다음 "저장"을 선택하여 설정을 유지합니다. 이후에는 WiFi 및 이더넷 상태를 확인하세요.

##### 애플리케이션 컴퓨터를 통해 업스트림 네트워크에 액세스

이 작업은 구성된 애플리케이션 컴퓨터를 사용하여 네트워크 액세스를 설정합니다. 시스템에서 먼저 USB를 "애플리케이션 컴퓨터"로 전환하고 네트워크 케이블을 확인하십시오. 해당 SSH 호스트는 키 인증을 사용해야 하며 확인된 호스트 지문이 있어야 합니다. 보안 가이드를 통해 호스트, 키, 지문 설정을 확인하세요.

해당 호스트의 SSH 계정에 대한 sudo 비밀번호를 얻습니다. 이 비밀번호는 시스템 변경을 승인하며 WebUI 비밀번호와 다를 수 있습니다.

1. "업스트림 네트워크 액세스"에서 "애플리케이션 컴퓨터를 통한 액세스"를 선택합니다.
2. 애플리케이션 컴퓨터 sudo 비밀번호를 입력하고 접속 버튼을 선택하세요. 비밀번호는 이 실행에만 사용되며 저장되지 않습니다. 나중에 실행하려면 다시 입력하세요.
3. 작업이 완료될 때까지 기다립니다. 처리하는 동안 다시 시작하지 마십시오.
4. 결과가 인터넷 연결과 완료된 네트워크 구성을 모두 보고하는 경우에만 액세스가 확인됩니다.
5. 결과 창을 닫은 후, “결과 보기”를 선택하면 다시 열립니다. 실패하거나 결과가 확인되지 않은 경우 이유와 실패 단계를 읽어보세요. 자세한 내용을 보려면 "실행 로그"를 확장하세요. 비밀번호 오류가 있는 경우 비밀번호를 확인하고, 인터넷에 연결되지 않은 경우 케이블링 및 업스트림 네트워크를 확인하세요.

호스트 지문이 확인되지 않았거나 변경된 경우 먼저 보안에서 호스트의 ID를 확인하세요. 계속해서 접속을 재시도하거나 인증을 건너뛰지 마세요. 원격 스크립트 출력은 원래 언어로 유지될 수 있습니다. 필요한 경우 조사를 위해 보관하십시오.

실패한 상태 요청은 스크립트가 중지되었음을 의미하지 않습니다. 다시 시도할지 여부를 결정하기 전에 사용 가능한 "새로 고침 상태" 컨트롤을 사용하여 현재 실행을 확인하십시오.

### 7. 파일 관리

상단 탐색 메뉴에서 "파일"을 선택하여 "파일 관리자"를 엽니다.

SD 카드는 이동식 저장소이고 SPIFFS는 내부 장치 파일 저장소입니다. 위치를 전환하려면 “SD 카드” 또는 “SPIFFS”를 선택하세요. 상단의 경로에는 현재 폴더가 표시됩니다. 경로에서 폴더 이름을 선택하면 해당 폴더로 돌아갑니다.

#### 파일 탐색 및 관리

- 폴더 이름을 선택하여 엽니다.
- 파일 옆에 있는 다운로드 버튼을 선택하여 브라우저의 다운로드 위치에 저장합니다.
- 이름 바꾸기 버튼을 선택하고 새 이름을 입력한 후 확인합니다.
- “새 폴더”를 선택하고 폴더 이름을 입력한 후 생성합니다.
- 현재 디렉터리와 저장소 상태를 다시 로드하려면 새로 고침 버튼을 선택하세요.

파일 업로드, 삭제, 이름 변경, 폴더 생성, SD 카드 마운트와 해제에는 유효한 로그인이 필요합니다. 보호된 자동화 파일의 읽기와 다운로드에는 root 권한도 필요합니다. root 로그인이 유효한지 확인하고 설정 페이지를 사용하세요. 경로나 진입점을 바꿔 권한 검사를 우회하지 마세요.

#### 파일 업로드

파일은 SD 카드에만 업로드할 수 있습니다. SPIFFS에는 업로드할 수 없습니다. 먼저 SD 카드가 마운트되어 있는지 확인하세요.

1. “SD 카드”를 선택하고 파일을 업로드할 폴더를 여세요.
2. "파일 업로드"를 선택합니다.
3. 하나 이상의 파일을 선택하거나 파일을 업로드 영역으로 끌어다 놓습니다.
4. 업로드 목록을 검토하고 원하지 않는 파일을 제거합니다.
5. "업로드"를 선택하고 각 파일이 완료될 때까지 기다립니다.

`.tscfg` 패키지를 업로드하면 검증과 적용 화면이 열립니다. 하지만 현재 파일 업로드 페이지는 패키지의 설정을 적용하지 않습니다. 업로드나 검증에 성공해도 설정이 적용된 것은 아닙니다.

12 장에 설명된 대로 자동화에서 규칙 패키지를 가져옵니다. 일반 파일 업로드는 규칙 가져오기를 대체할 수 없습니다. 다른 패키지에 대한 소스 및 서명 지침은 보안 가이드를 참조하세요.

#### 일괄 작업

파일이나 폴더를 선택하면 일괄 도구 모음이 나타납니다.

- "일괄 다운로드"는 선택한 파일을 다운로드합니다. 폴더는 포함되지 않습니다.
- "일괄 삭제"는 선택한 파일과 폴더를 삭제합니다.
- "선택 지우기"는 현재 선택을 지웁니다.

#### 파일 또는 폴더 삭제

삭제는 WebUI에서 취소할 수 없습니다. 폴더를 삭제하면 해당 내용도 모두 삭제됩니다. "삭제" 또는 "일괄 삭제"를 선택하고 프롬프트를 승인하기 전에 이름과 경로를 확인하세요.

자동화로 관리되는 파일은 보호됩니다.`/sdcard/config/automation`에 파일을 업로드하거나 덮어쓰거나 해당 폴더 또는 해당 폴더가 포함된 상위 폴더를 삭제하거나 이름을 바꾸는 것은 거부될 수 있습니다. 자동화가 파일을 관리한다는 메시지가 나타나면 자동화의 “Configuration & backup” 또는 관련 목록을 사용하십시오. 제한을 우회하기 위해 터미널을 사용하지 마십시오.

#### SD 카드 마운트 및 마운트 해제

마운트 해제하면 SD 파일을 일시적으로 사용할 수 없게 됩니다. 업로드, 다운로드 및 기타 파일 작업을 마친 다음 “SD 마운트 해제”를 선택하세요.

카드를 마운트 해제하거나 교체하면 자동화가 내부 비상 구성으로 전환될 수 있습니다. 해당 복사본은 오래되었을 수 있으며 활성화된 자동 규칙이 계속 실행될 수 있습니다. 사용 가능한 사본이 없으면 자동화를 사용할 수 없습니다. 마운트 해제하기 전에 비상 구성 및 작업을 검토하십시오(13장). 카드 기반 이미지, 글꼴, 로그를 사용할 수 없게 됩니다.

SD 카드가 장착되지 않은 경우 페이지에 "SD 장착"이 표시됩니다. 이를 선택하고 상태가 "Mounted"로 변경될 때까지 기다린 다음 SD 카드 디렉터리를 다시 엽니다.

카드를 장착한다고 해서 자동화가 해당 구성으로 전환되었다는 의미는 아닙니다. 카드를 다시 삽입한 후 13장에 설명된 대로 사용할 구성을 선택하십시오. 아무것도 자동으로 덮어쓰거나 병합되지 않습니다.

### 8. OTA 업데이트

"시스템" 페이지의 "네트워크 및 시간" 섹션에서 "OTA 업데이트"를 선택하여 "펌웨어 업그레이드"를 엽니다.

업데이트 중에 장치가 재부팅되어 WebUI 연결이 일시적으로 끊어집니다. 시작하기 전에 활성 작업을 저장하고 장치 전원을 안정적으로 유지하세요. 업데이트 진행이 완료되지 않은 동안 장치의 전원을 끄지 마십시오.

#### 이전 버전에서 0.6.3으로 처음 업그레이드

0.6.2와 같은 이전 스토리지 레이아웃의 첫 번째 업그레이드에는 배포자가 승인한 호환 USB/시리얼 패키지가 필요합니다. 펌웨어 또는 WebUI만 업로드하면 이 업그레이드를 완료할 수 없습니다. 장치 관리자나 공급자에게 패키지 지침을 따르도록 요청하세요. 전체 플래시를 지우거나 오래된 파티션 테이블을 사용하지 마십시오.

업그레이드하기 전에 중요한 파일을 저장하세요. 일치하는 도구는 키와 SD 카드를 보존합니다. 카드의 구성은 지워지지 않습니다. 처음 시작할 때 기존 구성을 읽거나 마이그레이션할 수 있습니다. 고객 배송은 "이전 구성을 지우고 다시 구성" 절차를 따릅니다. 장치 관리자 또는 공급자는 배송 지침을 따라야 합니다. 전체 플래시를 직접 삭제하거나 보존된 파일을 완료된 구성으로 취급하지 마십시오.

업그레이드 및 처음 시작하는 동안 전원을 연결된 상태로 유지하세요. 그런 다음 로그인, 네트워킹, 팬, 조명, SSH 호스트 및 자동화 규칙을 확인하세요. 전원을 제어하거나 장치를 다시 시작하거나 원격 명령을 실행하는 작업을 테스트하기 전에 규칙을 검토하세요.

일치하는 패키지는 두 애플리케이션 슬롯을 모두 업데이트합니다. 다른 슬롯에 여전히 이전 버전이 포함되어 있다고 가정하지 마십시오. root 비밀번호를 분실한 경우 0.6.3 레이아웃과 일치하도록 공급자가 확인한 복구 방법만 사용하세요. 이전 비밀번호 재설정 이미지를 플래시하지 마세요.

아래 웹 업데이트 방법은 게시자가 OTA에 대해 승인한 버전에만 적용됩니다. 첫 번째 레이아웃 업그레이드를 대체하지 않습니다.

#### OTA 서버에서 업데이트 확인

1. "현재 버전"을 검토하십시오. 두 개의 0.6.3 설치는 서로 다른 개정 빌드일 수 있습니다. 처음 세 숫자만 확인하기보다는 정식 버전, 빌드 시간, 게시자의 지침을 확인하세요.
2. 관리자나 게시자가 제공한 OTA 서버 주소를 입력하세요.
3. “Save”를 선택한 다음 “Check Update”를 선택합니다.
4. 페이지에서는 “Update Available” “Already up to date” 이전 서버 버전 또는 오류를 보고합니다.
5. 대상 버전을 확인한 다음 “Upgrade Now” 또는 페이지에 표시된 업그레이드 제어를 선택하십시오.
6. 다운로드, 설치, 재부팅이 완료될 때까지 기다립니다. 취소하려면 사용 가능한 경우 “Abort” 버튼을 사용하십시오. 모든 단계에서 취소가 지원되는 것은 아닙니다.
7. 업그레이드 후 펌웨어를 확인하는 페이지를 기다립니다. WebUI에 다시 연결하여 “Current Version” 및 장치 상태를 확인하세요.

“Upgrade Progress”는 자체 섹션에 현재 단계를 표시합니다.100% 읽거나 파일이 작성되었다는 메시지는 재시작 및 버전 확인이 완료되었음을 확인하지 않습니다. 결과가 확인되지 않거나 실행 중인 펌웨어가 대상과 다른 경우 메시지를 유지하고 현재 버전을 확인하십시오. 확인하지 않고 업그레이드를 반복하지 마십시오. 시스템 로그를 확인하고 필요한 경우 공급자에게 문의하세요.

“Also upgrade www”가 활성화되면 펌웨어와 WebUI가 순차적으로 업데이트됩니다. 동일한 릴리스의 일치하는 펌웨어 및 WebUI 리소스를 사용하십시오. 업그레이드 후에도 이전 인터페이스가 남아 있는 경우 브라우저를 강제 새로 고침한 후 버전과 페이지를 다시 확인하세요.

#### 수동 업그레이드

"수동 업그레이드"를 확장하고 다음 방법 중 하나를 선택합니다.

- "URL에서 업그레이드": 펌웨어 URL을 입력하고 릴리스 지침에 따라 "www도 업그레이드"를 설정한 다음 "업그레이드"를 선택합니다. 여기서 www는 장치의 웹 인터페이스 리소스를 나타냅니다.
- "SD 카드에서 업그레이드": `/sdcard/firmware.bin`와 같은 펌웨어 경로를 입력합니다. "www도 업그레이드"가 활성화된 경우 동일한 릴리스의 `www.bin`가 해당 디렉터리에 있는지 확인하십시오.

URL에서 업그레이드하는 경우 "인증서 확인 건너뛰기"는 HTTPS 서버 인증서 확인을 건너뜁니다. 그러면 다운로드 서버의 신원을 확인하는 데 사용되는 인증서 검사가 제거됩니다. 정기적인 업데이트를 위해서는 선택하지 않은 상태로 두세요. 인증서 오류가 표시되면 관리자에게 서버 주소와 인증서를 확인하도록 요청하세요.

#### 파티션 관리 및 롤백

"파티션 관리"는 실행 중인 파티션과 기타 사용 가능한 파티션을 보여줍니다.

- "유효 표시"는 실행 중인 버전을 확인하고 해당 버전에 대한 자동 롤백 보호를 비활성화합니다. 현재 버전이 정상적으로 동작하는지 확인 후 사용하세요.
- "이 버전으로 롤백"은 부팅 가능한 다른 버전을 선택하고 재부팅을 통해 전환합니다. 롤백은 현재 서비스를 중단시킵니다. 먼저 대상 버전과 데이터 호환성을 확인하세요.

작업 및 재부팅이 완료된 후 WebUI를 다시 열고 현재 버전과 장치 상태를 확인합니다.

버전 0.6.3에서는 구성 저장소와 장치 파티션 레이아웃이 변경되었습니다. 호환되지 않는 이전 펌웨어로 직접 돌아가지 마십시오. 다운그레이드가 필요한 경우 장치 제공업체에 전체 펌웨어, 레이아웃 및 구성 복구 절차를 확인하도록 요청하세요.

롤백은 이전 구성 형식을 복원하거나 이전 규칙의 작동을 보장하지 않습니다.

### 9. 보안관리 항목

상단 탐색에서 "보안"을 선택하여 보안 관리를 엽니다. SSH 키, 원격 호스트, 알려진 호스트 지문, HTTPS 인증서, 구성 패키지 및 계정 관리에 대해서는 TianshanOS 보안 가이드를 사용하세요. 이러한 절차는 여기서 반복되지 않습니다.

#### 실패했거나 확인되지 않은 작업

빨간색 필드 오류는 수정해야 할 사항을 알려줍니다. 수정한 후 저장하세요. 오류 표시가 지워졌다고 해서 성공적으로 저장되었다는 의미는 아닙니다. 메시지와 목록을 확인하세요.

어떤 작업이 실패했는지 확인한 뒤 이유와 다음 조치를 읽으세요. 이유가 표시되지 않으면 추측하지 마세요.

사용 가능한 경우 “Details”를 선택합니다. 세부정보를 숨기려면 “Hide”를 선택하세요. × 버튼이 표시되면 이를 선택하여 메시지를 닫습니다. 추가 확인을 위해 메시지와 세부 정보를 기록해 둔 다음 터미널에서 “System Logs”를 열어 조사하세요.

메시지나 세부정보가 긴 경우 다음에 수행할 작업을 결정하기 전에 해당 영역 내에서 스크롤하여 전체 내용을 읽어보세요.

결과가 확인되지 않으면 새로고침하고 장치·파일·작업 상태를 확인하세요. 시간 초과나 연결 끊김은 작업이 실행되지 않았다는 뜻이 아닙니다. 전원 제어·삭제·작업 시작·업그레이드를 곧바로 반복하지 마세요. 계속 확인할 수 없으면 “터미널”의 “시스템 로그”에서 원인을 확인하세요.

성공, 실패, 미확인 배치 결과를 별도로 확인하세요. 브라우저의 다운로드 목록에서 저장된 파일을 확인하세요.

### 10. 터미널 및 시스템 로그

"터미널"은 root에만 표시됩니다. 장치 콘솔 명령을 직접 실행하고 장치 로그를 표시할 수 있습니다. 명령으로 장치 상태가 즉시 변경될 수 있습니다. 입력하기 전에 소스, 매개변수 및 영향을 확인하세요.

#### 터미널 연결 및 사용

1. 상단 탐색에서 "터미널"을 선택합니다.
2. "장치에 연결됨" 및 `tianshan>` 프롬프트를 기다립니다.
3. 현재 펌웨어에서 제공하는 명령을 보려면 `help`를 입력합니다.
4. 명령을 입력하고 Enter를 누르십시오. 출력이 완료되고 프롬프트가 반환될 때까지 기다립니다.

페이지에 "장치에 연결되지 않음"이 표시되는 동안 입력이 실행되지 않습니다. 연결을 끊은 후 중복 실행을 피하기 위해 명령을 다시 제출하기 전에 다시 연결 메시지를 기다리십시오.

다른 터미널 세션을 사용 중인 경우 먼저 원래 터미널을 닫습니다. 연결이 가득 찬 경우 더 많은 탭을 열지 말고 다시 연결될 때까지 기다리세요. 로그인이 만료된 후 다시 로그인하고 터미널이 연결을 확인할 때까지 기다립니다.

명령이 활성 상태인 동안 완료될 때까지 기다리거나 중지를 요청하십시오. 페이지에 작업이 안전하게 종료되기를 기다리고 있다고 표시되면 중지가 아직 진행 중인 것입니다. 다른 명령을 입력하기 전에 프롬프트를 기다리십시오. 출력이 불완전한 경우 작업 결과와 시스템 로그를 별도로 확인하세요. 출력 누락이 명령을 다시 실행하는 이유는 아닙니다.

터미널은 다음 키보드 컨트롤을 지원합니다.

| 제어 | 목적 |
| --- | --- |
| Ctrl+C | 현재 입력을 지우고 인터럽트를 요청합니다. 명령을 중지하려면 중단을 지원해야 합니다. |
| Ctrl+L | 화면을 지웁니다. |
| ↑ / ↓ | 현재 페이지 세션에서 명령 기록을 찾아봅니다. |
| ← / → | 현재 입력 내에서 커서를 이동합니다. |

페이지 상단의 "Clear"는 디스플레이만 지웁니다. 이미 실행된 명령은 실행 취소되지 않습니다. "연결 끊기"는 현재 터미널 연결을 종료합니다.

#### 원격 SSH 쉘 열기

SSH 셸은 후속 키보드 입력을 원격 호스트로 보냅니다. 대상 주소, 사용자, 인증 방법을 확인하고 보안 가이드에 설명된 SSH 준비를 완료한 후 연결하세요. 웹단말기에서 호스트 인증이 필요한 경우에는 보안에서 지문을 확인 후 재접속하시기 바랍니다. 직렬 콘솔이나 다른 사람의 터미널에서 확인에 응답하지 마세요.

1. SSH 명령 옵션을 보려면 `ssh --help`를 입력합니다.
2. `ssh --host <host> --user <user> --shell`를 입력하여 꺾쇠 괄호를 포함한 각 자리 표시자를 실제 값으로 바꿉니다. 포트를 지정하려면 --shell 앞에 `--port <port>`를 추가하세요.
3. 원격 명령을 입력하기 전에 원격 연결 확인을 기다리십시오.
4. Ctrl+\를 눌러 SSH 쉘을 종료하고 tianshan> 프롬프트로 돌아갑니다.

다른 사람이 터미널을 공유, 녹화 또는 보고 있는 동안 일반 텍스트 자격 증명을 입력하지 마십시오.

#### 시스템 로그 보기

터미널 상단의 “시스템 로그”를 선택하여 로그 창을 엽니다.

- "레벨"은 표시되는 최소 레벨을 설정합니다. ERROR, WARN+, INFO+ 또는 DEBUG+를 사용하여 출력 범위를 좁힙니다.
- "TAG"는 로그 소스별로 필터링합니다.
- "검색"은 현재 로그를 키워드로 필터링합니다.
- "자동 스크롤"은 활성화되면 새로운 로그 항목을 따릅니다.
- 새로 고침 버튼은 기록 로그를 다시 로드합니다.
- 지우기 버튼은 현재 창에 표시된 로그만 지웁니다.

필터링으로 출력이 생성되지 않으면 먼저 TAG 및 검색을 지우고 레벨을 변경하십시오. 로그 창을 닫아도 장치 서비스는 중지되지 않습니다.

#### 자동화가 저장되는 위치 확인

명령줄 확인의 경우 `auto --config status`를 입력하여 현재 구성 위치와 백업 상태를 확인합니다. 사용 가능한 옵션은 `auto --help`를 사용하세요. 이전 `config --sync` 옵션이 제거되었습니다. 일상적인 백업 및 복구를 위해서는 13장의 웹 단계를 사용하십시오.

### 11. 원격 명령 관리 및 실행

"명령"은 재사용 가능한 SSH 명령을 저장하고 선택한 원격 호스트에서 실행합니다. 원격 호스트와 해당 인증 정보는 "보안" 페이지에서 관리됩니다. 해당 절차는 보안 가이드를 참조하세요.

#### 연결하기 전에 호스트 지문을 확인하세요

지문은 연결 대상 호스트를 확인하는 데 쓰입니다. 이 절차는 웹 “보안” 페이지의 SSH 호스트 테스트에 해당하며, 터미널 SSH Shell의 확인 절차가 아닙니다. 지문이 등록되지 않았거나 바뀌었다는 메시지가 나오면 명령을 반복 실행하지 마세요. “보안”에서 대상 SSH 호스트를 찾아 “테스트”를 선택하세요.

처음 연결할 때 확인 창에 호스트 주소와 지문이 표시됩니다. 신뢰할 수 있는 경로로 호스트 관리자에게 확인하세요. 일치하는 것을 확인한 뒤에만 “신뢰하고 연결”을 선택하세요.

지문이 바뀌면 저장된 지문과 현재 지문이 함께 표시되며, 기본으로 “취소”가 선택됩니다. 호스트를 재설치하면 지문이 바뀔 수 있지만, 다른 호스트에 연결됐거나 누군가 호스트를 사칭하는 경우도 있습니다.

주소를 확인하고 신뢰할 수 있는 경로로 변경 이유를 확인하세요. 확인할 수 없으면 “취소”를 선택하세요. 확인을 건너뛰려고 기존 지문을 삭제하지 마세요. 새 지문을 신뢰할 수 있다고 확인한 뒤에만 “호스트 키 업데이트”를 선택하세요.

#### 호스트 선택 및 명령 보기

1. 상단 탐색에서 "명령"을 선택합니다.
2. 현재 "호스트 선택" 아래에 표시된 호스트를 선택합니다.
3. "명령 목록"에서 저장된 항목을 검토합니다.

명령 텍스트는 기본적으로 축소되어 있습니다. 모든 줄을 보려면 "명령 표시"를 선택하고 축소하려면 "명령 숨기기"를 선택하세요. 텍스트를 확장해도 실행되지 않습니다.

"고아 명령"에는 사용 가능한 호스트가 없으며 실행할 수 없습니다. 유효한 호스트를 준비하고, 명령을 편집하고, 해당 호스트를 선택하고, 콘텐츠를 검토하세요. 실행이 허용되는 경우에만 활성화하고 저장하세요. 이를 사용하는 템플릿과 규칙을 확인하세요. 호스트에 다시 연결하기 위해 동일한 이름의 새 명령이 필요하지 않습니다.

호스트 주소, 포트, 계정 또는 키를 변경하려면 보안의 SSH 호스트 목록에서 편집을 사용하십시오. 전체 단계는 보안 가이드를 참조하세요. 변경 사항은 이후 연결에 적용됩니다. 기존 작업은 실행 기록의 원래 호스트 세부 정보를 사용하여 관리됩니다. 키를 삭제하기 전에 관련 호스트 및 실행 기록을 검토하세요. 키를 삭제해도 원격 작업이 중지되지는 않지만 이 장치에서 원격 작업을 확인하거나 중지하지 못할 수 있습니다.

#### 명령 생성 또는 편집

저장된 명령이 원격 호스트에서 실행됩니다. 저장하기 전에 해당 호스트에 대한 명령과 필요한 권한을 확인하십시오. 데이터 삭제, 호스트 종료 또는 다시 시작, 파일 덮어쓰기 등의 명령을 사용할 때는 각별히 주의하십시오.

1. 호스트를 선택한 다음 "새 명령"을 선택합니다. 이를 변경하려면 기존 명령의 편집 버튼을 사용하십시오.
2. `model.v1` 와 같은 고유한 "명령 ID"를 입력합니다. 줄바꿈, 제어 문자, 슬래시를 사용하지 말고 `.` 또는 `..` 만 사용하세요. 최대 31개의 영문자 또는 숫자를 입력할 수 있습니다. 중국어 및 기타 일부 문자는 더 많은 공간을 사용합니다. 필드의 길이 메시지를 따르십시오.
3. "명령 이름"과 "명령"을 입력합니다. 여러 줄을 사용하는 경우 각 명령을 별도의 줄에 입력하세요.
4. 설명을 추가하고 필요한 경우 SD 카드에서 아이콘이나 이미지를 선택합니다.
5. 호스트, 활성화 여부, 실행 모드, 출력 일치 옵션을 확인한 뒤 「저장」을 선택하세요. 같은 ID로 새로 만들면 기존 명령을 덮어쓰지 않고 오류가 표시됩니다. 변경할 때는 기존 명령의 편집 버튼을 사용하세요.

이름은 명령을 인식하는 데 도움이 됩니다. 자동화는 해당 ID를 사용하여 이를 찾습니다. 기존 명령의 ID는 변경할 수 없습니다. 새 ID를 사용하려면 명령을 생성하고 이를 사용하는 템플릿과 소스를 업데이트하세요.

#### 명령 실행 및 결과 검토

1. 명령 카드에서 실행 컨트롤을 선택합니다.
2. "실행 결과"에서 출력 및 상태를 확인하세요.
3. "취소"가 표시되면 이를 사용하여 현재 세션 중단을 요청합니다. 상태와 출력을 확인하여 중지되었는지 확인합니다. 완료된 원격 작업은 실행 취소되지 않습니다.
4. 현재 결과 표시를 제거하려면 "지우기"를 선택하십시오.

“지우기”는 원격 호스트에서 이미 끝난 작업을 되돌리지 않습니다. 성공·실패 판정, 출력 추출, 최종 상태는 해당 명령의 판정·추출 설정에 따라 달라집니다.

페이지는 명령을 다시 실행하지 않고 이 실행 결과를 확인합니다. 자동 결과 확인이 일시 중지되면 동일한 브라우저 탭에서 명령을 다시 열어 확인을 계속하세요. 로그아웃하거나 장치를 다시 시작하거나 결과가 더 이상 유지되지 않으면 복구가 불가능할 수 있습니다. 재실행 여부를 결정하기 전에 실제 원격 상태를 확인하십시오.

명령의 종료 결과, 조건 일치 및 로그 완전성을 구별합니다. “확인된 종료 코드 0으로 실행이 완료되었습니다.”는 정상적인 종료를 확인합니다. 수집된 출력이 불완전하면 여전히 일치 및 추출이 확인되지 않은 상태로 남을 수 있습니다. 페이지에 로그 출력이 누락되었다고 해서 원격 명령이 실패했다는 의미는 아닙니다. 메시지에 따라 원본 출력과 대상 호스트를 확인하세요.

#### 결과 일치 구성

결과 매칭은 원격 출력을 사용하기 쉬운 상태로 변환합니다.

- "예상 일치": 출력에 구성된 텍스트가 포함되면 결과를 성공으로 표시합니다.
- "일치 실패": 출력에 구성된 텍스트가 포함된 경우 결과가 실패했음을 표시합니다.
- "정규식 추출": 하나의 `(.*)` 캡처 그룹을 사용하여 선택한 출력을 저장합니다.
- "일치 시 중지": 구성된 결과가 일치한 후 계속되는 명령의 종료를 요청합니다. 최종 상태도 확인해보세요.
- "Timeout (s)": 경기를 기다리는 시간을 초 단위로 설정합니다. 성공 또는 실패 패턴이 설정되어 있거나 '일치 시 중지'가 활성화된 경우에만 적용됩니다.
- "변수 이름": 자동화 페이지에서 사용할 상태 및 추출된 출력을 저장합니다.

안정적이고 구체적인 성공 및 실패 텍스트를 선택하세요. 광범위한 텍스트는 잘못된 일치를 생성할 수 있습니다. 규칙에서 해당 변수를 사용하기 전에 명령을 한 번 실행하고 "일치 결과"를 검토하십시오.

자동화가 이 일반 SSH 명령을 참조할 때 저장된 일치, 추출 및 일치 시 중지 설정도 사용합니다. 실행 마감일에 도달하면 이미 발견된 일치 항목이 유지될 수 있습니다. 일치하거나 시간 초과가 없다고 해서 원격 프로세스가 종료되었음을 증명할 수는 없습니다. 종료 코드와 실제 상태도 확인하세요.

#### 백그라운드 실행 및 서비스 모드 사용

nohup은 SSH 연결이 닫힌 후에도 명령이 원격 호스트의 백그라운드에서 계속 실행됨을 의미합니다. WebUI를 닫아도 백그라운드 작업은 중지되지 않습니다.

백그라운드 실행에는 SSH 키 인증이 필요합니다.“Security”에 공개 키를 배포한 다음 연결된 호스트를 선택합니다. 백그라운드 명령에 일반 텍스트 비밀번호를 저장하지 마세요. 원래 작업을 중지하거나 확인하려면 동일한 키를 계속 사용할 수 있어야 합니다.

「백그라운드에서 실행(nohup)」을 켜고 명령을 실행한 뒤 「명령」의 「실행 기록」을 여세요. 「시스템」의 root 전용 버튼과 「자동화」의 버튼도 같은 목록을 엽니다. 이전 작업도 남아 있으므로 기록이 있다는 것만으로 실행 중이라고 판단하면 안 됩니다. 작업 시작 시에도 관련된 이전 기록을 확인합니다.

1. 이름, 사용자, 호스트 주소 및 포트로 원래 작업을 찾으십시오.
2. 원래 호스트에서 이 실행을 확인하려면 “Verify remote state”를 선택합니다.“Refresh”는 알려진 레코드만 읽습니다. 이는 확인을 대체하지 않습니다.
3. 원래 호스트에서 마지막 100줄을 읽으려면 “View Log”를 선택합니다. 업데이트하려면 “Follow log”를 선택하세요.“Stop following”는 페이지 업데이트만 중지합니다.
4. 작업을 종료하려면 해당 기록에서 “Stop”를 선택하고 확인하세요. 결과를 기다린 후 중지되었는지 확인하십시오. 확인하지 않고 다시 시작하지 마십시오.

장치를 재시작하면 이전 기록에 「확인 안 됨」이 표시됩니다. 「원격 상태 미확인」은 중지됐는지 실행 중인지 아직 확인하지 못했다는 뜻입니다. 「마지막 결과」는 마지막으로 확인한 결과이며, 현재 상태를 보장하지 않습니다.

읽기 실패는 로그가 비어 있거나 프로세스가 종료되었음을 의미하지 않습니다. 원래 호스트 연결, 로그 경로, SSH 키를 확인하세요. 문제를 해결한 후 다시 확인하세요. 상태 확인이 실패했다는 이유만으로 작업을 다시 시작하지 마세요.

로그가 더 이상 원래 호스트에 없으면 호스트가 다시 시작되었거나 임시 파일이 지워졌을 수 있습니다. 이는 빈 로그와 다르며 작업이 실행된 적이 없음을 증명하지 않습니다. 원격 상태를 확인하거나 호스트 관리자에게 확인을 요청하세요.

명령을 삭제하거나 호스트 구성을 변경하거나 자동화 구성을 전환해도 원격 프로세스는 종료되지 않습니다. '실행 기록'에서 원래 작업을 관리하세요. 동일한 이름이나 ID를 사용하여 명령을 다시 생성해도 원래 작업이 이어지지 않습니다. 제어하는 데 필요한 키는 그대로 유지하세요.

"서비스 모드"는 사용 가능해질 때까지 백그라운드 작업을 감시합니다. "Ready match" 및 "Variable Name"을 제공합니다. 필요에 따라 선택적 오류 패턴 및 타이밍 설정을 조정합니다.
- “Ready match”: 구성된 텍스트가 나타날 때 서비스가 준비된 것으로 표시합니다. 여러 패턴을 분리하려면 `|`를 사용하세요.
- "실패 일치": 구성된 텍스트가 나타날 때 서비스가 실패했다고 표시합니다.
- "준비 시간 초과(초)": 준비 상태에 대한 가장 긴 대기 시간(초)을 설정합니다.
- "확인 간격(ms)": 로그 확인 빈도를 밀리초 단위로 설정합니다. 1000 ms는 1초입니다.
- "변수 이름": 확인, 준비 및 시간 초과와 같은 상태를 저장합니다.

서비스 모드 작업은 시작, 확인, 중지 또는 확인되지 않을 수 있습니다. 요청이 수락된 후 최종 결과를 기다립니다. 백그라운드 실행 기록이 이미 존재하는 경우 원래 실행을 확인하고 다시 시작하기 전에 종료되었는지 확인하세요. 활성화된 자동 규칙으로 인해 서비스가 다시 시작될 수 있습니다. 서비스를 중지 상태로 유지해야 하는 경우 먼저 해당 규칙을 비활성화하세요.

#### 가져오기 및 내보내기 명령

- 명령에 내보내기 버튼을 사용하여 내보내고, 선택한 경우 종속 호스트 구성을 포함합니다.
- “Import Command” 선택 `.tscfg` 구성 패키지를 선택하고 해당 내용을 미리 본 후 기존 구성을 덮어쓸지 여부를 결정합니다.

가져오기에는 원격 호스트가 포함될 수 있으며 구성을 동일한 ID로 바꿀 수 있습니다. 확인하기 전에 미리보기에서 명령, 호스트 및 대체 항목을 검토하세요. 저장하면 다시 시작하지 않고도 현재 구성이 업데이트됩니다. 기존 원격 프로세스는 중지되거나 새 호스트로 이동되지 않습니다.

새로운 가져오기는 소스, 서명, 서명 권한 및 대상 장치를 확인합니다. 성공적인 내보내기가 나중에 가져오기를 보장하지는 않습니다. HTTPS 전용 장치 인증서에는 구성 패키지에 서명할 수 있는 권한이 부족할 수 있습니다. 이 문제를 해결하려면 구성 공급자에게 문의하세요. 확인을 비활성화하지 마십시오.

#### 명령을 삭제하기 전에 영향 확인

삭제를 선택한 후 연결된 템플릿과 규칙을 검토하세요. 사용 가능한 대체 명령을 선택하거나 영향을 받는 구성의 링크를 해제하고 해당 규칙을 비활성화하십시오. 단계는 12장을 참조하세요. 삭제하면 사용 중인 구성만 변경됩니다. 다른 응급 복사본은 업데이트되지 않습니다.

구성 삭제와 원격 서비스 중지는 별도의 작업입니다. 삭제해도 서비스가 중지되거나 완료된 작업이 실행 취소되지는 않습니다. 원격 작업을 종료하려면 '실행 기록'에서 중지하고 결과를 확인하세요.

### 12. 자동화 관리

"자동화"는 데이터와 작업을 반복 가능한 워크플로우로 연결합니다. 데이터 소스와 작업 템플릿을 생성한 다음 규칙을 사용하여 실행 시기를 결정합니다.

```text
자동: 데이터 소스 → 변수 → 규칙 평가 → 작업
수동: 시스템 페이지의 빠른 작업 → 작업
```

소스는 데이터를 읽고, 변수는 값을 보유하고, 규칙은 조건을 평가하고, 템플릿은 작업을 정의합니다. 패널에 규칙을 표시하는 것과 수동 실행을 허용하는 것은 별도의 설정입니다. 패널에 자동 규칙이 나타날 수도 있습니다.

#### 자동화 엔진 보기 및 제어

페이지 상단에는 엔진 상태, 규칙, 변수, 소스 수, 트리거 수 및 런타임이 표시됩니다.

| 제어 | 효과 |
| --- | --- |
| “Start” | 정지된 엔진을 시동합니다. 활성화된 규칙은 현재 구성이 실행을 허용하는 경우에만 실행됩니다. |
| “Pause” | 추가 자동 평가를 일시 중지합니다. 기존 작업이 계속될 수 있습니다. 페이지를 계속 진행하려면 엔진을 멈췄다가 다시 시작하세요. |
| “Stop” | 구성을 유지하면서 규칙 확인, 데이터 읽기 및 이후 작업 예약을 중지하려고 시도합니다. 확인을 기다리십시오. 시간 초과가 엔진이 정지했다는 의미는 아닙니다. |
| “Reload” | 사용 중인 위치에서 구성을 다시 읽습니다. 편집 내용을 저장하고 결과를 확인하세요. 기존 구성 일시 중지는 그대로 유지됩니다. |

냉각, 경고 또는 기타 진행 중인 작업이 자동화에 의존하는지 확인하세요. 엔진을 중지해도 원격 백그라운드 프로세스는 중지되지 않습니다. “실행 기록”에서 원격 작업을 중지하고 결과를 확인하세요.

“Configuration & backup” 아래의 “Disable automation”는 엔진의 “Pause” 제어와 별개입니다. 구성이 일시 중지된 경우 “Enable automation”를 선택하기 전에 검토하십시오. 장치를 다시 시작하거나 다시 로드하거나 엔진을 중지하고 시작해도 이 구성 일시 중지가 지워지지 않습니다.13장을 참조하세요.

#### 최소한의 자동화 워크플로 구축

1. 소스를 생성하고 해당 테스트를 사용하여 연결 및 선택한 필드를 확인합니다.
2. 이를 활성화한 다음 행의 "변수 보기" 아이콘을 사용하여 값과 업데이트 시간을 확인합니다.
3. 템플릿을 생성하고 해당 매개변수를 검토한 후 "테스트"를 선택합니다. 테스트는 작업을 즉시 실행합니다. 장치와 호스트가 이를 수락할 수 있는지 확인합니다.
4. "즉시 활성화"를 끄고 규칙을 만듭니다. 조건, 쿨타임, 액션 순서, 딜레이, 반복 등을 설정합니다.
5. 필요에 따라 "패널에 표시" 및 "수동 트리거 허용"을 설정합니다.
6. 저장한 다음 규칙을 활성화합니다. 변수, 트리거 횟수, 실제 결과를 확인하세요.

#### 데이터 소스 관리

"데이터 소스"에서 "추가"를 선택하고 유형을 선택합니다.

| 유형 | 목적 |
| --- | --- |
| "REST API" | HTTP 주소에서 데이터를 주기적으로 읽습니다. |
| “웹소켓” | 영구 연결을 통해 푸시된 데이터를 수신합니다. |
| "Socket. IO" | Socket. IO 서비스로부터 이벤트를 수신합니다. |
| “명령 변수” | 구성된 원격 명령의 결과를 읽습니다. |

1. 고유 ID, 표시 라벨, 필수 연결 정보를 입력하세요.
2. 테스트를 사용하여 연결을 확인하십시오. 데이터 공급자로부터 주소, 인증 세부정보 및 필드 정보를 얻습니다.
3. 처음 세 가지 유형의 경우 테스트 응답에서 필드를 선택합니다. Socket. IO 이벤트 이름을 비워두면 테스트에서 이벤트 검색을 시도할 수 있습니다.
4. 명령 변수의 경우 호스트와 구성된 변수 이름이 있는 명령을 선택한 다음 폴링 간격을 설정합니다.
5. 양식에서 활성화 스위치를 확인하고 저장한 후 해당 행에 “View Variables”를 사용하여 결과를 확인합니다.

소스 행은 활성화 스위치, 변수 뷰어, 편집, 내보내기 및 삭제 컨트롤을 제공합니다. 소스를 비활성화하거나 삭제하기 전에 소스를 사용하는 규칙을 확인하여 작업을 방해하지 않도록 하세요.

기존 소스를 변경하려면 편집 버튼을 선택하세요. 주소, 인증, 수집 간격, 활성화 상태를 검토한 후 저장합니다. 기존 필드 매핑은 그대로 유지됩니다. 나중에 "변수 보기"를 사용하여 소스, 값 및 업데이트 시간을 확인하세요. 편집 창의 간격은 초 단위이며 소수점 이하 3자리까지 가능합니다. 중복 ID를 생성해도 기존 소스를 덮어쓰지 않습니다.

REST는 저장된 GET 또는 POST 방식으로 데이터를 수집합니다. WebSocket은 전송되는 데이터를 받고, Socket.IO는 지정된 이벤트와 주소를 사용합니다. 테스트 성공 후에도 실제 수집 값이 계속 갱신되는지 확인하세요. 「명령 변수」 소스는 기존 상태만 읽으며 명령을 시작하지 않습니다. 새 결과가 필요하면 명령을 따로 실행하세요.

가져오기 및 내보내기는 구성 패키지를 사용합니다. 가져오기 전에 ID, 유형 및 대체 항목을 미리 보고 소스 및 신뢰 요구 사항에 대한 보안 가이드를 따르세요.

#### 변수 보기

소스 행에서 눈 모양의 "변수 보기" 아이콘을 선택합니다. 창에는 이름, 유형, 값 및 업데이트 시간이 표시됩니다. 원격 명령 변수는 명령의 변수 제어에서도 볼 수 있습니다.

- 이름과 소스를 확인하고 값과 유형이 규칙 비교에 적합한지 확인하세요.
- 업데이트 시간이 예상 데이터 빈도와 일치하는지 확인하십시오.
- 사용 가능한 데이터가 없으면 소스가 활성화되어 있는지 확인한 다음 연결과 필드를 테스트하십시오. 명령 변수의 경우 명령의 실행 결과도 확인하세요.

#### 사용자 변수 관리

자동화에서 "사용자 변수"를 선택하면 저장한 변수와 초기 값을 볼 수 있습니다. 이 목록에는 장치의 실시간 수집 데이터가 포함되어 있지 않습니다.

1. 변수를 찾아 해당 삭제 아이콘을 선택합니다.
2. 영향을 받는 소스, 템플릿, 규칙을 검토하세요. 링크를 삭제하거나 처리하려면 페이지를 따르세요.
3. 목록을 확인한 후 다시 읽어보세요. 관련 구성의 활성화 상태와 실행 결과를 확인하세요. 초기 정의를 제거하는 것은 모든 라이브 데이터를 지우는 것과는 다릅니다.

#### 작업 템플릿 생성 및 테스트

"작업 템플릿"에서 "추가"를 선택하고 작업 유형을 선택합니다.

| 유형 | 목적 |
| --- | --- |
| "CLI 명령" | 로컬 장치 콘솔 명령을 실행합니다. |
| "SSH 명령" | 명령 페이지에 저장된 원격 명령을 실행합니다. |

| “Webhook” | 옵션은 계속 표시되지만 작업 실행은 구현되지 않습니다. 현재 요청을 보낼 수 없습니다. |

고유 ID, 이름 및 유형별 매개변수를 입력합니다. 필요한 경우 지연 또는 "비동기 실행"을 설정하십시오. 비동기 작업은 백그라운드에서 계속됩니다. 로그, 변수 또는 대상 장치를 통해 최종 결과를 확인하십시오.

- CLI: 선택적 결과 변수 및 시간 초과와 함께 명령을 입력합니다.
- SSH: 구성된 호스트와 명령을 선택하고 미리보기를 확인합니다.
- LED: 장치와 지원되는 색상, 효과, 밝기, 텍스트, 이미지, QR 코드 또는 필터 작동을 선택합니다.
- 로그: 레벨과 메시지를 선택하세요. 메시지는 변수를 참조할 수 있습니다.
- 변수 설정: 변수 이름과 값을 입력합니다.
- Webhook: 현재 사용할 수 없습니다. 대신 지원되는 작업을 선택하세요. Webhook 작업이 포함된 규칙 패키지도 가져올 수 없습니다.

“Test”가 작업을 실행합니다. 테스트하기 전에 전원, 재부팅, 원격 명령 또는 외부 요청 작업의 효과를 확인하십시오. 대기 중인 메시지는 작업이 성공했다는 의미가 아니라 작업이 수락되었음을 의미합니다. 시스템 로그와 대상 장치도 확인하십시오.

<!-- operational-note -->
편집 후 매개변수를 저장하고 확인합니다. 저장에 실패한 경우 초안을 보관하고 보고된 문제를 수정하세요. 가져오기는 템플릿을 대체할 수 있습니다. 삭제하기 전에 삭제 영향을 검토하세요. 이미지나 글꼴이 누락된 경우 원본 SD 카드를 삽입하거나 사용 가능한 리소스를 선택하세요. 응급 백업은 이러한 파일을 저장하지 않습니다.

#### 구성 삭제 및 해당 링크 처리

<!-- operational-note -->
규칙, 템플릿, SSH 명령, 호스트, 소스 또는 사용자 변수를 삭제하면 다른 구성에 영향을 줄 수 있습니다. 필요할 경우 먼저 응급 백업을 저장하세요. 페이지에서 삭제를 취소할 수 없습니다.

1. 해당 목록에서 삭제를 선택하세요. 대상 이름과 영향을 받는 항목을 검토하세요.
2. 링크가 없으면 삭제를 확인하세요. 그렇지 않으면 사용 가능한 대체품 또는 “Unlink and disable affected rules”를 선택하세요.
3. 나중에 목록을 새로 고치세요. 제거를 확인하고 연결된 템플릿, 규칙 및 활성화 상태를 확인하세요.

삭제된 템플릿의 연결을 해제하면 영향을 받는 규칙에서 해당 작업이 제거되고 해당 규칙이 비활성화됩니다. SSH 명령을 삭제하면 연결된 템플릿이 명령 참조가 지워진 비활성화된 초안으로 남습니다. 영향을 받는 규칙은 연결이 해제되고 비활성화됩니다. 대체품을 선택하기 전에 유사한 이름뿐만 아니라 대상, 동작 및 데이터를 확인하십시오. 교체가 필요한 데이터를 제공할 수 없는 경우 관련 구성이 비활성화되고 편집을 위해 유지될 수 있습니다.

호스트를 삭제할 때 영향을 받는 명령과 소스도 검토하세요. 호스트가 없는 명령은 실행할 수 없습니다. 유효한 호스트를 선택하도록 편집한 다음 활성화하기 전에 관련 템플릿과 규칙을 확인하세요. 로컬 호스트 구성을 삭제하는 것은 원격 공개 키를 취소하는 것과 별개입니다. 보안 가이드를 참조하세요.

삭제 후 페이지에서는 삭제, 비활성화 및 다시 연결된 항목을 별도로 보고합니다. 실제 목록을 확인하세요. 링크를 처리한다고 해서 모든 관련 항목이 삭제되었거나 실행할 준비가 되었다는 의미는 아닙니다.

#### 필요할 때 강제 삭제 사용

일반 삭제를 완료할 수 없으면 “Force delete”를 선택하고 설명을 읽은 후 확인하세요. 대상이 삭제되고 확인 가능한 연결이 해제되며 영향을 받는 규칙이 비활성화됩니다. 원격 백그라운드 서비스는 중지되지 않습니다.

영향 범위 전체를 확인할 수 없으면 “I agree to pause automation and continue deleting”에 동의하도록 요청합니다. 삭제 후에도 자동화는 일시 중지된 상태로 유지됩니다. 남은 설정을 검토하고 복구한 다음 “Configuration & backup”에서 “Enable automation”을 선택하세요. 재시작으로 일시 중지를 해제할 수는 없습니다.

확인하는 동안 설정이 변경되면 “Review deletion impact”를 선택하고 새 목록을 검토한 후 다시 확인하세요. 저장소 쓰기에 실패하면 강제 삭제가 완료된다고 보장할 수 없습니다. 목록을 다시 확인하세요. 카드가 사라졌다고 해서 삭제가 저장된 것은 아닙니다.

#### 규칙 만들기

1. "규칙"에서 "추가"를 선택하고 고유 ID, 이름 및 아이콘을 입력합니다.
2. “Logic”을 선택합니다. AND는 모든 조건을 충족해야 하고, OR는 하나 이상의 조건을 충족하면 됩니다.
3. 자동 트리거의 쿨다운을 설정합니다. 값은 ms 단위입니다. 1000 ms는 1초입니다.
4. 조건을 추가하고 변수, 비교 및 ​​값을 선택합니다. 비교에는 같음, 같지 않음, 초과, 크거나 같음, 미만, 작거나 같음, 변경된 값 및 포함이 포함됩니다. 값 유형을 변수와 일치시킵니다.
5. 템플릿을 추가하고 작업 지연, 반복 및 작업 수준 조건을 설정합니다.
6. "패널에 표시" 및 "수동 트리거 허용"을 설정합니다. 첫 번째는 시스템의 카드 가시성을 제어합니다. 두 번째는 수동 실행을 제어합니다.
7. 규칙을 검토하고 저장한 후 활성화합니다. 처음 구성하는 동안 "즉시 활성화"를 꺼진 상태로 두십시오.

규칙을 저장, 활성화 또는 비활성화하면 다시 시작하지 않고도 현재 구성이 업데이트됩니다. 자동화가 일시 중지되면 저장이 재개되지 않습니다. 목록을 새로 고치고 결과를 확인하세요.13장에 설명된 대로 중요한 변경 후 비상 백업을 업데이트합니다.

임시 자동 시작 실패는 최대 360초 동안 30초마다 다시 시도됩니다. 확인되지 않은 결과는 다음 출시 전에 확인됩니다. 해당 시도의 재시도는 완료되지 않은 백그라운드 시작 단계에서 계속됩니다. 완료된 이전 단계는 반복되지 않습니다. 페이지에 시도가 중지되었거나 대기가 종료되었다고 표시되면 메시지에 따라 수동으로 시작할지 여부를 결정하세요. 수동 실패는 자동으로 재시도되지 않습니다.

관련 구성을 변경하면 실패한 시도를 다시 시도할 수 있습니다. 성공적인 시도는 여전히 일반 재사용 대기시간을 따릅니다. 쿨다운은 자동 트리거를 제한합니다. 실패 후에 확인해야 할 것은 이것뿐만이 아닙니다.

최대 64개의 규칙을 저장할 수 있습니다. 이는 64개의 작업이 동시에 실행될 수 있다는 것을 보장하지 않습니다. 명령 길이와 조건 및 작업의 수 역시 저장 공간과 메모리에 영향을 미칩니다. 용량이 부족할 경우 불필요한 구성을 제거하거나 내용을 줄여 저장하세요.

선택한 유형에 값을 일치시킵니다. 숫자의 경우 무한대나 NaN(잘못된 숫자)이 아닌 특정 값을 입력하세요. 다른 유형의 경우 텍스트, 부울(true 또는 false) 또는 null을 입력하십시오. 전체 JSON 개체나 배열을 입력하지 마세요. 페이지에 오류가 보고되면 다시 저장하기 전에 변수, 비교, 값을 확인하세요.

#### 반복 및 동작 조건 구성

| 모드 | 의미 |
| --- | --- |
| “한 번” | 트리거당 한 번 실행됩니다. |
| “참일 때 반복” | 작업 조건이 유지되는 동안 실행당 최대 100회까지 반복됩니다. |
| “고정 카운트” | 설정된 횟수와 간격만큼 반복하여 실행 전 동작 조건을 확인합니다. |

작업 조건은 규칙 트리거 조건과 별개입니다. 작업 조건이 없으면 "참일 때 반복"은 실행당 한도까지 계속됩니다. 규칙은 나중에 다른 실행을 트리거할 수 있습니다.

규칙을 비활성화하면 새로운 트리거가 방지됩니다. 이미 시작된 실행은 계속될 수 있습니다. 이후 작업 예약을 중지하려면 엔진의 "중지" 컨트롤을 선택하고 확인을 기다립니다. 이미 전송된 작업과 원격 프로세스를 별도로 확인하세요. 완료된 작업은 실행 취소되지 않습니다.

#### 빠른 작업 만들기

"수동 트리거만", "패널에 표시" 및 "수동 트리거 허용"은 규칙이 수동으로만 실행되는지, 해당 카드가 표시되는지, 사용자가 규칙을 실행할 수 있는지 여부를 제어합니다.

1. ID, 이름, 아이콘을 입력한 후 "수동 트리거 전용"을 활성화합니다. 이러한 규칙에는 자동 트리거 조건이 필요하지 않습니다.
2. 템플릿을 추가하고 지연, 반복 및 작업 조건을 검토합니다.
3. "패널에 표시" 및 "수동 트리거 허용"을 활성화한 다음 규칙을 저장하고 활성화합니다.
4. 시스템 장치 패널로 돌아갑니다. 카드의 이름과 상태를 확인하고 한 번 실행한 후 결과를 검토해 보세요.

자동 규칙도 패널에 표시할 수 있습니다. 카드를 표시한다고 수동 전용 규칙이 되는 것은 아닙니다. 비활성 규칙은 보일 수 있어도 시작할 수 없습니다. 작업 효과를 알 수 있는 이름을 붙이세요. 백그라운드 SSH 작업은 admin도 카드에서 로그 확인과 중지를 할 수 있습니다. 설정 변경은 root의 작업입니다. root는 「실행 기록」에서도 로그 확인, 상태 검증, 서비스 중지를 할 수 있습니다.

#### 규칙 구성 패키지 가져오기

Security의 “Verify Only” 또는 파일 업로드를 통하지 않고 자동화에서 규칙 패키지를 가져옵니다. 이 컨트롤은 서명자, 대상 장치 및 필수 구성을 확인합니다. 자체 가져오기 제어를 통해 각 패키지를 확인합니다. 다른 패키지의 결과는 적용되지 않습니다.

가져오기 전에 다음을 준비하십시오.

- SD 카드 또는 내부 비상 구성이 사용 중인지, 저장할 수 있는지 확인하세요.13장을 참조하세요.
- 장치에는 유효한 인증서, 일치하는 개인 키 및 CA 체인이 있습니다. 시간이 확인되었습니다. CA 체인은 인증서 출처를 확인합니다. 설치 단계는 보안 가이드를 참조하세요.
- 배포 관리자가 신뢰할 수 있는 서명자를 선택했습니다. Root 로그인 또는 HTTPS 인증서 설치로는 이 설정이 완료되지 않습니다. 누락된 경우 배포 관리자에게 구성을 요청하세요.
- 규칙의 템플릿, 명령 및 호스트가 준비되었습니다. 가져오기는 이러한 항목을 설치하지 않습니다. 누락된 구성을 먼저 추가하세요. 규칙이 활성화된 경우 규칙이 사용하는 구성의 활성화 상태도 확인하세요.

가져오기를 저장하면 다시 시작하지 않고도 현재 구성이 업데이트됩니다. 확인하기 전에 활성화 상태, 조건, 동작 및 대상을 확인하고 실행이 안전한지 확인하십시오. 기존 구성 일시 중지는 그대로 유지됩니다. 실행을 방지하려면 먼저 자동화를 비활성화하거나 공급자에게 비활성화된 버전을 요청하세요.

1. “Rules” 아래의 가져오기 아이콘을 선택하여 “Import Rule Configuration”를 연 다음 `.tscfg` 파일을 선택합니다. 확인이 시작되고 페이지에 미리보기가 표시됩니다.
2. “Signing trust, target device and rule content verified”를 기다립니다. 이름, 규칙 ID 및 “Rule summary”를 확인합니다. “View rule content”를 확장하여 조건, 작업, 대상 및 활성화 상태를 검토합니다. 파일 이름에 의존하지 마십시오.
3. 동일한 ID가 존재하는 경우 무엇을 대체할지 검토하세요. 교체하려는 경우에만 “Overwrite existing configuration”를 선택하십시오. 미리보기 후 파일, 자격 증명 또는 구성이 변경되면 “Check package again”를 선택하고 페이지에서 메시지가 표시되면 편집기를 다시 열고 다시 확인하세요.
4. “Confirm Import”를 선택하고 저장 결과를 기다립니다. 규칙 목록, 활성화 상태, 필수 변수를 확인하세요. 성공적인 저장이 성공적인 작업 실행을 증명하지는 않습니다.
5. 규칙이 안전한 수동 검사를 허용하는 경우 한 번 실행하고 장치나 호스트를 확인하십시오. 다른 규칙의 경우 일반 트리거 후 로그와 결과를 살펴보세요. 구성 일시 중지를 지우려면 “Enable automation”를 선택하기 전에 구성을 검토하십시오.

가져온 규칙은 편집, 활성화, 비활성화 및 삭제할 수 있습니다. 편집 후 현재 구성을 확인하고 필요한 경우 긴급 백업을 업데이트하세요. 나중에 가져오려면 여전히 서명 확인이 필요합니다. 로컬에서 편집할 수 있는 권한은 이를 우회하지 않습니다.

HTTPS 전용 인증서는 구성 서명을 승인하지 않을 수 있습니다. 성공적인 현지 수출이 수입 시 거부될 수 있습니다. 공급자에게 인증서 목적 문제를 해결하도록 요청하세요. 확인을 비활성화하거나 가져오기를 반복하지 마십시오.

가져오기와 편집은 완료된 동작을 취소하거나 원격 백그라운드 프로세스를 중지하지 않습니다. 필요한 작업은 「실행 기록」에서 따로 종료하고 결과를 확인하세요.

#### 가져오기가 완료되지 않는 경우

##### 확인 실패

| 메시지 또는 문제 | 다음 단계 |
| --- | --- |
| root 서명이 선택되지 않음, 서명자를 신뢰할 수 없거나 서명자가 승인되지 않음 | 배포 관리자 또는 구성 공급자에게 서명 소스 및 인증서 권한을 확인하도록 요청하세요. Security의 “Verify Only”를 대체하거나 검증을 비활성화하지 마십시오. |
| 패키지가 다른 장치를 대상으로 함 | 공급자에게 이 장치의 인증서를 사용하여 내보내도록 요청하세요. 패키지 내부의 이름을 변경하지 마십시오. 이 장치의 인증서도 변경하기 전에 일치하는 교체 패키지를 준비하세요. |
| 기기 시간이 확인되지 않았습니다. | 시스템의 “Network & Time”에서 시간을 확인하고 동기화한 후 파일을 다시 확인하세요. |
| 구성 로딩 | 완료될 때까지 기다린 후 패키지를 다시 확인하십시오. |
| 구성을 로드하지 못했습니다. | 다시 확인하기 전에 시스템 로그를 확인하고 원인을 해결한 후 구성을 복원하십시오. |
| 필수 구성이 누락되었습니다. | 페이지에서 이름이 지정된 템플릿, 명령 또는 호스트를 추가한 후 다시 확인하세요. |
| 필수 구성이 비활성화되었습니다. | 활성화해야 하는지 확인하세요. 실행해도 안전해지면 활성화하고 다시 확인하세요. |
| 지원되지 않는 작업 | 공급자에게 패키지를 수정하도록 요청하십시오. 규칙 패키지 가져오기는 현재 웹훅 작업을 거부합니다. 템플릿 선택기에 해당 항목이 있다고 해서 패키지를 가져올 수 있다는 의미는 아닙니다. |
| 미리보기 후 파일, 자격 증명 또는 구성이 변경됨 | “Check package again”를 선택합니다. 편집기를 다시 열거나 지시에 따라 파일을 선택한 다음 검토하고 확인합니다. |

##### 저장이 완료되지 않았습니다.

| 메시지 또는 문제 | 다음 단계 |
| --- | --- |
| 현재 저장용량을 사용할 수 없거나 가득 참 | “Configuration & backup”에서 위치를 확인하세요. 저장 문제를 해결하거나 불필요한 콘텐츠를 줄인 후 다시 확인해 보세요. |
| 현재 구성 또는 저장 위치가 변경됨 | 초안을 보관하고 복사하세요. 편집기를 다시 열고 최신 구성을 검토한 후 다시 제출하세요. 계속해서 저장을 선택하지 마세요. |
| 확인되지 않은 결과 저장 | 규칙 내용과 활성화 상태를 새로 고치고 확인합니다. 여전히 불분명한 경우 시스템 로그를 검사하세요. 원래 패키지를 유지하고 가져오기를 반복하지 마십시오. |

샘플이 없는 조건 변수가 반드시 구성이 누락된 것은 아닙니다. 언제 업데이트되는지 확인하세요. 구성을 읽을 수 없는 경우 원본 파일을 보관하고 시스템 로그를 확인하십시오. 손상된 콘텐츠를 비어 있는 것처럼 덮어쓰지 마십시오.

#### 규칙 및 구성 유지

- 수동 실행에는 이미 진행 중인 동일한 규칙 실행이 없는 수동 트리거를 허용하는 활성화된 규칙이 필요합니다. 자동 트리거 조건과 쿨다운을 우회하지만 여전히 동작 조건, 지연, 반복을 적용합니다.
- 비활성화해도 완료된 작업은 실행 취소되지 않습니다. 페이지에서 삭제를 취소할 수 없습니다.
- 소스, 템플릿 또는 명령을 편집하기 전에 이를 사용하는 규칙을 확인하세요. 구성 편집은 기존 원격 작업을 중지하지 않습니다. 필요한 경우 해당 작업을 별도로 확인하고 중지하세요.
- 관련 목록을 통해 각 패키지를 가져오고 미리보기를 검토하세요. 전체 서명 및 계정 절차는 보안 가이드를 참조하세요.
- 저장에 실패하면 메시지를 읽고 초안을 보관하세요. 저장에 성공했지만 새로 고침에 실패한 경우, 목록을 새로 고치고 확인한 후 다른 항목을 생성하세요.

### 13. 구성 및 백업

자동화에서 “Configuration & backup”를 선택합니다. 구성을 저장, 복원 또는 선택하기 전에 “Currently using”를 확인하십시오. 먼저 냉각, 경고 또는 원격 작업에 미치는 영향을 검토하십시오.

SD 카드를 사용하는 동안 비상 백업 그룹에서 "현재 구성 저장" 및 "저장된 구성 복원"을 찾으세요. 아래 단계에 따라 "긴급 백업 저장" 또는 "긴급 백업 복원"을 선택하세요. "SD 카드 및 자동화" 그룹에는 카드 확인 및 자동화 활성화 컨트롤이 포함되어 있습니다. 복사본을 저장해도 구성이 전환되지 않습니다.

#### 세 가지 유형의 콘텐츠 구별

| 내용 | 저장 방법 |
| --- | --- |
| 네트워킹, 팬, 온도, 조명 등의 시스템 설정 | 장치 내부에 저장됩니다. 자동화 백업 복원은 이를 변경하지 않습니다. |
| 현재 자동화 구성 | 추가, 편집 및 삭제는 일반적인 SD 사용 중에는 SD 카드로 이동하고 비상 모드에서는 내부 저장소로 이동합니다. |
| 내부 비상 백업 | SD 카드를 사용하는 동안에는 “Save emergency backup”을 선택할 때만 갱신됩니다. 비상 모드에서 편집한 내용은 이 내부 설정에 직접 저장됩니다. |

응급 백업은 규칙, 작업 템플릿, SSH 명령, 관련 호스트, 소스 및 사용자 변수의 초기 정의를 함께 저장합니다. 개인 키, 이미지, 글꼴, 로그 또는 원격 실행 상태는 저장되지 않습니다. 호스트 설정은 사용할 키만 기억합니다. 키 자체는 복사되지 않습니다.

이는 전체 장치 백업이 아닙니다. 자체 백업 방식을 통해 중요한 파일과 키를 보관하세요. 복원이 원격 서비스가 중지되었거나 규칙에 필요한 모든 파일을 사용할 수 있다는 의미는 아닙니다.

#### 응급 백업 저장

1. “Currently using”에 “SD card configuration”가 표시되는지 확인한 다음 현재 규칙과 작업을 검토하세요.
2. “Save emergency backup”를 선택하고 완료될 때까지 기다립니다.
3. “Last internal save”와 “Backup status”를 확인합니다. “Includes the current changes”는 내부 복사본이 현재 설정과 일치한다는 뜻입니다.

저장하면 이전 긴급 백업이 대체됩니다. 나중에 SD 카드 편집으로 업데이트되지 않습니다. 최신 변경 사항이 포함되지 않은 경우 현재 콘텐츠를 검토한 후 다시 저장할지 여부를 결정하세요.

“Internal emergency configuration”를 사용하는 동안 편집 내용은 내부적으로 저장됩니다.“Save emergency backup”를 다시 선택할 필요는 없습니다.

#### 응급 백업 복원

복원은 현재 SD 카드 구성을 내부 복사본(이전 버전일 수 있음)으로 대체합니다. 먼저 필요한 현재 구성과 파일을 내보냅니다. 응급 백업을 먼저 저장하지 마십시오. 복원하려는 이전 복사본을 덮어쓰게 됩니다.

1. SD 카드 구성을 사용하는 동안 “Restore emergency backup”를 선택합니다.
2. 추가, 변경, 제거된 항목을 검토하고 자동화가 일시 중지 상태로 유지되는지 여부를 검토하세요.
3. 확인하고 완료될 때까지 기다립니다. 장치를 다시 시작하지 않고도 목록이 업데이트됩니다.
4. 규칙, 호스트, 변수, 활성화 상태 및 작업 결과를 확인합니다. 여전히 일시 중지된 경우 “Enable automation”를 선택하기 전에 구성을 검토하세요.

복원은 네트워킹, 팬 또는 키를 변경하지 않습니다. 원격 서비스 실행이 종료되지 않습니다. 필요한 경우 "실행 기록"에서 관리하세요.

#### 사용 가능한 SD 카드가 없는 경우

사용 가능한 내부 구성이 있으면 장치가 해당 구성으로 전환됩니다. 활성화된 자동 규칙은 여전히 ​​해당 조건을 따릅니다. 수동 규칙에는 여전히 클릭이 필요합니다. 내부 복사본은 오래되었을 수 있으므로 계획된 전환 전에 어떤 작업이 실행될 수 있는지 확인하세요.

비상 모드에서는 추가, 편집 및 삭제가 허용됩니다. 저장 내용은 내부 저장소로 직접 이동됩니다. 사용 가능한 내부 구성이 없으면 먼저 이유를 읽어보십시오. 유효한 새 구성으로 시작할 수 있지만 손상된 파일이 비어 있는 것처럼 덮어쓰지 마십시오.

네트워킹, 팬 및 기타 시스템 설정은 여전히 내부 저장소에서 로드됩니다. 긴급 구성은 SD 카드 이미지, 글꼴 또는 로그를 복원하지 않습니다. 원본 카드를 삽입하거나 리소스가 누락된 경우 사용 가능한 파일을 선택하세요. 카드가 없어졌다고 해서 모든 기능이 정지되거나 모든 작업이 계속될 수 있다는 의미는 아닙니다.

#### 카드를 다시 삽입한 후 구성 선택

사용 가능한 SD 카드를 삽입하고 “Check SD card”를 선택한 후 아래 두 가지 선택 사항을 검토하세요. 삽입은 구성을 전환하거나 병합하지 않습니다. 내부 구성을 계속 사용하려면 패널을 닫으세요. 다시 시작해도 자동으로 선택되지는 않습니다.

| 버튼 | 무슨 일이 일어나는가 |
| --- | --- |
| “Use SD card configuration” | 카드 구성을 읽고 전환합니다. 내부 구성은 유지되며 카드에 복사되지 않습니다. |
| “Save current configuration to SD card and use it” | 카드의 구성을 현재 내부 구성으로 바꾼 다음 카드로 전환합니다. 기존 카드 구성을 덮어씁니다. |

1. 현재 위치를 확인하고 유지할 구성을 결정하세요.
2. 관련 버튼을 선택하고 교체 및 활성화 상태 알림을 검토하세요. 카드에 쓰기 전 추가, 변경, 삭제된 항목을 확인하세요.
3. 확인하고 기다리세요.“Currently using”에 “SD card configuration”가 표시되는지 확인한 다음 목록과 작업 결과를 검토하세요.

누락되거나 비어 있는 카드 구성은 내부 저장소에서 자동으로 채워지지 않습니다. 선택하기 전에 빈 구성이 원하는 구성인지 확인하세요. 미리보기 후에 카드나 구성이 변경되면 지시에 따라 다시 확인하세요. 이전 확인을 재사용하지 마십시오.

#### 저장, 전환, 실행 결과 구별

| 메시지나 상황 | 다음 단계 |
| --- | --- |
| SD 카드에 저장되었지만 전환되지 않았습니다. | 내부 구성이 아직 사용 중입니다. 전환을 완료하려면 “Use SD card configuration”를 선택하세요. 카드를 다시 덮어쓰지 마십시오. |
| 설정은 저장되었지만 자동화는 여전히 일시 중지됨 | 설정을 검토한 다음 “Enable automation”을 선택하세요. 다시 저장하거나 재시작으로 일시 중지를 해제하려 하지 마세요. |
| 삭제 내용이 저장되지 않았으며 자동화가 일시중지되었습니다. | 대상이 여전히 존재하고 스토리지를 사용할 수 있는지 확인하십시오. 활성화 여부를 결정하기 전에 구성을 복구하고 검토하십시오. |
| 확인되지 않은 결과 저장 | 위치와 내용을 다시 읽어보세요. 필요한 경우 시스템 로그를 확인하세요. 확인하지 않고 동일한 변경사항을 다시 제출하지 마세요. |
| 현재 입력이 최신 구성과 다릅니다. | 편집기를 닫았다가 다시 열기 전에 필요한 초안을 복사하세요. 최신 콘텐츠를 검토하고 수정사항을 입력하세요. 페이지에서는 초안을 병합하지 않습니다. |

성공적인 전환, 복원 또는 저장 후에는 작업 실행이 허용되는지와 작업이 완료되는지 확인하세요. 구성 일시 중지가 그대로 유지됩니다. 검토하고 “Enable automation”를 선택하여 재개하세요.“Disable automation”로 인한 일시 중지 또는 강제 삭제는 구성을 다시 시작하거나 전환해도 지워지지 않습니다.
