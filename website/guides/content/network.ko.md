# RM-01 네트워크 설정 가이드

## 1. 두 가지 네트워크 연결 경로

RM-01은 USB-C 기반 네트워크 연결 경로를 두 가지 제공합니다. 이 문서에서는 **C1 포트**와 **C3 포트**로 구분합니다. 둘 다 네트워크 연결에 쓰이지만 연결 대상과 네트워크 구성이 다릅니다.

| 포트 | 주요 용도 | 연결 후 네트워크 구성 |
| --- | --- | --- |
| C1 | 컴퓨터, 태블릿, 스마트폰 등 사용자 기기를 RM-01에 연결 | 사용자 기기가 RM-01 내부 스위치 네트워크의 노드로 참여합니다 |
| C3 | RM-01을 기존 LAN에 연결 | LPMU가 내부 노드의 라우팅을 맡아 시스템 전체를 스위치나 라우터가 있는 상위 네트워크에 연결합니다 |

## 2. C1과 C3 위치 확인

### C1 포트

C1은 본체 측면 뒤쪽에 있습니다. 위아래로 배치된 USB-C 포트 두 개 중 위쪽입니다. 포트 아래에 새겨진 연결 그림으로 위치를 확인할 수 있습니다.

### C3 포트

C3은 본체 상단에 있습니다. 자석식 덮개를 열면 USB-C 포트가 보입니다. 상단 공유 USB 포트로, TianshanOS에서 연결 대상을 ESP, AGX, LPMU로 바꿀 수 있습니다.

## 3. C1으로 사용자 기기를 RM-01에 연결

데이터 전송을 지원하는 USB-C 케이블로 iPad, 컴퓨터, 스마트폰 등을 C1에 연결합니다. RM-01이 DHCP로 주소를 자동 할당하므로 IP 주소, 게이트웨이, DNS를 직접 입력할 필요가 없습니다.

사용자 기기에서는 보통 `AX88179` 또는 USB Ethernet이라는 유선 네트워크 인터페이스로 인식됩니다. 기기는 RM-01 내부 스위치 네트워크에 참여하여 내부 장치와 통신할 수 있습니다.

> C1은 사용자 기기를 RM-01 내부 네트워크에 직접 연결합니다. 신뢰할 수 있는 기기만 연결하세요. 공공장소나 신뢰할 수 없는 환경에서는 관리되지 않은 기기를 C1에 연결하지 마세요.

## 4. 인터넷 연결 유지 및 RM-01과 공유

### 사용자 기기의 인터넷 연결에 미치는 영향

<!-- operational-note -->

일부 운영체제는 C1 연결 후 `AX88179`를 우선 네트워크 출구로 사용할 수 있습니다. C1은 주로 RM-01 내부 접속을 위한 경로이며 인터넷을 직접 제공하지 않으므로, 기존 인터넷 연결이 잠시 끊길 수 있습니다.

Wi-Fi, 이더넷 등으로 인터넷을 계속 사용하려면 기존 인터넷 연결의 우선순위를 `AX88179`보다 높게 설정하세요.

| 운영체제 | 설정 이름 | 설정 원칙 |
| --- | --- | --- |
| macOS | 서비스 순서(Service Order) | 인터넷을 제공하는 Wi-Fi 또는 이더넷을 `AX88179`보다 위에 둡니다 |
| Windows | 인터페이스 메트릭(Interface Metric) | 값이 작을수록 우선합니다. 인터넷 인터페이스의 값을 `AX88179`보다 작게 설정합니다 |
| Linux | 경로 메트릭(Route Metric) | 값이 작을수록 우선합니다. 인터넷 기본 경로의 값을 `AX88179`보다 작게 설정합니다 |

### RM-01 네트워크 연결 도구 사용

사용자 기기의 인터넷을 RM-01과 공유하려면 웹사이트 다운로드 페이지에서 **RM-01 네트워크 연결 도구**를 받으세요. 사용자 기기와 C1 사이의 DHCP, 경로, 공유 규칙을 설정하여 인터넷 트래픽을 RM-01 내부 네트워크로 전달합니다.

현재 지원하는 운영체제는 다음과 같습니다.

- macOS
- Linux
- Windows Pro

Windows Home은 현재 지원하지 않습니다.

> 도구는 사용자 기기의 네트워크 주소, 경로, 공유 설정을 변경합니다. 실행 중 기존 연결이 잠시 끊길 수 있습니다. 다운로드, 원격 세션 등 네트워크에 의존하는 작업을 저장한 뒤 시작하세요.

## 5. AI로 C1 네트워크 공유 설정

Codex, Hermes처럼 로컬 명령 실행이 가능한 Agent Harness는 자연어 요청에 따라 네트워크 구성을 확인하고 사용자 컴퓨터에서 RM-01 내부로의 전달 및 공유 설정을 도울 수 있습니다. 대상 컴퓨터에서 시스템 명령을 실행할 수 있어야 합니다. 일반 대화형 AI는 절차를 안내할 수 있을 뿐 설정을 직접 수행하지 못합니다.

### AI Agent 실행 위치

C1에 연결된 사용자 컴퓨터에서 직접 실행하는 것을 권장합니다. 인터넷 출구, 기본 경로, 공유 규칙은 해당 컴퓨터가 관리하며, 설정하려면 그 컴퓨터의 관리자 권한이 필요합니다.

Codex, Hermes 등이 RM-01 내부에서 실행된다면, 먼저 사용자 컴퓨터에 대한 원격 명령 실행 권한과 관리자 승인을 확보해야 합니다. 그렇지 않으면 사용자 컴퓨터의 공유, 경로, 방화벽 설정을 바꿀 수 없습니다.

### 실행 전 확인

- 사용자 컴퓨터가 C1에 연결되어 `AX88179` 또는 USB Ethernet 인터페이스가 보이는지 확인합니다.
- 컴퓨터의 C1 주소가 `10.10.99.100/24`이고 내부 노드가 계속 `10.10.99.99`, `10.10.99.98`, `10.10.99.97`을 사용하는지 확인합니다.
- 컴퓨터가 Wi-Fi, 이더넷 등의 다른 인터페이스로 인터넷에 정상 접속하는지 확인합니다.
- Agent Harness가 컴퓨터에서 명령을 실행하고 필요할 때 관리자 권한을 요청할 수 있어야 합니다.
- 다운로드, 원격 세션 등 네트워크 작업을 저장하고 로컬에서 네트워크 설정을 복구할 수 있어야 합니다.

### Agent에 바로 전달할 프롬프트

다음 프롬프트는 출하 시 네트워크 구성을 유지하면서 확인 후 변경하고, 검증 및 복구 방법을 제시하도록 요청합니다. 명령 실행을 지원하는 Codex, Hermes 등에 복사하여 사용할 수 있습니다.

```text
RM-01의 C1 네트워크 공유 설정을 도와주세요. 먼저 현재 운영체제, 네트워크 인터페이스, 주소, 기본 경로, 방화벽 상태를 확인하고 아래 구성과 일치할 때만 변경하세요. 인터페이스 이름만으로 추정하거나 RM-01 내부 노드의 고정 주소를 바꾸지 마세요.

현재 구성:
- 사용자 컴퓨터는 USB-C로 RM-01의 C1에 연결되어 있습니다. 보통 AX88179 또는 USB Ethernet으로 표시되며 주소는 10.10.99.100/24입니다.
- RM-01 내부 네트워크는 10.10.99.0/24입니다.
- 애플리케이션 컴퓨터(LPMU)는 10.10.99.99입니다.
- 추론 컴퓨터(AGX)는 10.10.99.98입니다.
- 대역 외 관리 컴퓨터는 10.10.99.97입니다.
- 사용자 컴퓨터는 다른 네트워크 인터페이스로 인터넷에 연결되어 있습니다.

목표는 기존 인터넷 연결을 유지하면서 C1의 AX88179 / USB Ethernet 인터페이스를 통해 RM-01 내부에 공유하여 10.10.99.99, 10.10.99.98, 10.10.99.97이 인터넷을 사용하게 하는 것입니다.

다음 조건을 지켜주세요.
1. 운영체제, 실제 인터넷 출구 인터페이스, C1 인터페이스를 확인하고 변경할 항목을 설명하세요.
2. 운영체제 기본 기능으로 변경을 최소화하여 필요한 IP 전달, NAT, 경로 또는 Internet Connection Sharing을 설정하세요.
3. 기존 인터넷 인터페이스의 우선순위와 기본 경로, 위 RM-01 노드 주소는 바꾸지 마세요. 관련 없는 방화벽 규칙을 지우거나 덮어쓰지 마세요.
4. 관리자 권한이 필요하면 용도를 설명한 뒤 요청하세요. 현재 시스템이나 권한으로 안전하게 설정할 수 없다면 중단하고 이유를 설명하세요.
5. 완료 후 컴퓨터의 인터넷 연결, 10.10.99.99, 10.10.99.98, 10.10.99.97에 대한 접근, 내부 노드의 공인 IP 접속 및 도메인 이름 해석을 검증하세요.
6. 마지막으로 실제 실행한 명령 또는 변경 사항, 검증 결과, 원래 설정으로 복구하는 절차를 제시하세요.
```

macOS는 보통 인터넷 공유와 시스템 라우팅을, Linux는 IP 전달과 nftables 또는 iptables를, Windows Pro는 Internet Connection Sharing(ICS)을 사용합니다. 실제 명령과 인터페이스 이름은 Agent가 현재 컴퓨터에서 확인한 결과를 따라야 합니다. Windows Home은 현재 지원하지 않습니다.

### 설정 성공 여부 확인

설정 후 다음 조건을 모두 충족해야 합니다.

1. 컴퓨터의 기존 인터넷 연결을 계속 사용할 수 있습니다.
2. 컴퓨터에서 `10.10.99.99`, `10.10.99.98`, `10.10.99.97`에 접근할 수 있습니다.
3. RM-01 내부 노드에서 공인 IP에 접속하고 도메인 이름을 해석하여 접속할 수 있습니다.
4. Agent가 성공했다는 말뿐 아니라 실제 변경 사항과 실행 가능한 복구 절차를 제시했습니다.

### 보안 안내

> 관리자 또는 root 권한을 허용하면 Agent는 경로, IP 전달, NAT, Internet Connection Sharing, 방화벽 규칙을 변경할 수 있습니다. 신뢰할 수 있는 Agent Harness만 사용하고 승인 전에 작업 계획을 확인하세요. 컴퓨터가 원격 연결 등 중요한 네트워크 작업을 담당한다면 먼저 로컬 복구 수단을 확보하세요.

## 6. C3으로 RM-01을 상위 네트워크에 연결

여기서 상위 네트워크는 스위치나 라우터가 있는 기존 LAN을 뜻합니다.

### 어댑터 준비

다음 연결 장비를 별도로 준비합니다.

- USB-C ↔ RJ45 이더넷 어댑터 1개
- 스위치 또는 라우터에 연결할 RJ45 케이블 1개

USB-C 쪽을 C3에 연결하고 RJ45 케이블을 스위치나 라우터에 연결합니다. 물리 연결만으로 DHCP와 경로 설정이 끝나지는 않습니다. 이후 RM-01 내장 네트워크 설정 프로그램을 실행해야 합니다.

### 상단 USB를 LPMU로 전환

1. TianshanOS 홈 화면을 엽니다.
2. USB 전환 영역(‘USB 切换’)을 찾습니다.
3. ‘USB’ 버튼으로 상단 포트의 대상을 `LPMU`로 바꿉니다.
4. 현재 대상이 `LPMU`로 표시되는지 확인한 뒤 계속 진행합니다.

<!-- operational-note -->

전환 중 현재 연결이 잠시 끊길 수 있습니다. 데이터를 전송하는 중에는 대상을 바꾸지 마세요.

## 7. LPMU를 통해 시스템 전체 연결

출하 시 LPMU에는 네트워크 자동 설정 프로젝트가 준비되어 있습니다. LPMU가 상위 네트워크에 연결되면 내부 라우팅과 NAT로 AGX 등 내부 노드의 트래픽을 전달하여 시스템 전체를 연결합니다.

### 프로젝트 위치와 사용자 작업

프로젝트는 **LPMU 현재 사용자의 홈 디렉터리** 아래 `~/network-setup/`에 있으며 LPMU용 스크립트는 `~/network-setup/lpmu/`에 있습니다.

출하 상태의 장치는 프로젝트를 다시 다운로드하거나 README의 엔지니어링 배포용 `scp`, `chmod`, 설치 절차를 반복할 필요가 없습니다. 일반 사용자는 TianshanOS에서 설정을 실행하세요. 문제 진단이나 추가 개발 때만 프로젝트 디렉터리에서 스크립트와 로그를 확인하면 됩니다.

> `~/network-setup/`을 임의로 이동하거나 이름을 바꾸거나 삭제하지 마세요. TianshanOS의 네트워크 설정 기능은 출하 시 준비된 경로와 스크립트에 의존합니다.

### 자동 설정이 수행하는 작업

LPMU에서 다음 작업을 순서대로 수행합니다.

1. 게이트웨이가 있는 인터페이스를 찾고 연결 시험으로 사용 가능한 상위 네트워크 출구를 선택합니다.
2. 선택한 인터페이스로 트래픽이 나가도록 LPMU 기본 경로를 다시 설정합니다.
3. IPv4 전달을 켜고 `iptables`의 NAT 및 FORWARD 규칙을 설정합니다.
4. 내부 AGX(기본 `10.10.99.98`)가 LPMU(내부 `10.10.99.99`)를 통해 상위 네트워크에 접속하게 합니다.
5. AGX 접속용 포트 전달 규칙을 설정합니다.

선택적으로 켤 수 있는 지능형 경로 모니터링 서비스도 포함됩니다. 켜면 30초마다 현재 출구를 확인하고 연결이 끊기면 다른 사용 가능한 인터페이스로 전환을 시도하며, 우선 인터페이스가 복구되면 돌아갑니다.

### TianshanOS에서 실행

1. C3이 USB-C ↔ RJ45 어댑터를 통해 스위치나 라우터에 연결되어 있는지 확인합니다.
2. 홈 화면의 상단 USB 대상이 `LPMU`인지 확인합니다.
3. 위쪽 탐색 메뉴에서 네트워크(‘网络’)를 엽니다.
4. 상위 네트워크 접속(‘接入上层网络’)을 찾습니다.
5. LPMU를 통해 접속(‘通过LPMU接入’)을 선택합니다.
6. 처리 중(‘处理中’)에서 성공(‘成功’) 또는 실패(‘失败’)로 바뀔 때까지 기다립니다. 처리 중 다시 실행하지 마세요.

성공은 스크립트가 사용 가능한 상위 출구를 찾고 LPMU 경로와 내부 전달·NAT 설정을 실행했다는 뜻입니다. 버튼 상태만으로 판단하지 말고 AGX의 IP 연결과 DNS 이름 해석도 확인하는 것이 좋습니다.

### 연결 성공 여부 확인

먼저 TianshanOS에 성공(‘成功’)이 표시되는지 확인합니다. AGX 터미널 권한이 있다면 AGX에서 순서대로 실행합니다.

```bash
ping -c 3 10.10.99.99  # AGX에서 LPMU로 연결 확인
ping -c 3 8.8.8.8       # 인터넷 IP 연결 확인
ping -c 3 google.com    # DNS 이름 해석 확인
```

각각 내부 링크, 인터넷 전달, DNS를 확인합니다. 첫 번째 실패는 주로 내부 연결이나 주소 문제입니다. 첫 번째만 성공하면 LPMU의 상위 연결, 기본 경로, NAT를 확인합니다. 앞의 두 개가 성공하고 세 번째만 실패하면 DNS 설정을 확인합니다.

### 포트 전달 및 보안 범위

현재 프로젝트는 LPMU의 상위 네트워크 인터페이스에 다음 전달 규칙을 설정합니다.

| LPMU 진입 포트 | 전달 대상 | 용도 |
| --- | --- | --- |
| TCP `58022` | AGX TCP `22` | LPMU를 통해 AGX SSH 접속 |
| TCP/UDP `58000–58999` | AGX의 동일 포트 | AGX에서 실행되는 애플리케이션 서비스 접속 |

예를 들어 SSH는 LPMU의 상위 네트워크 주소로 접속하지만 사용자 이름과 인증 정보는 AGX의 것을 사용합니다.

```bash
ssh -p 58022 <AGX_USERNAME>@<LPMU_IP>
```

> 포트 전달은 상위 네트워크에서 AGX 서비스에 접근할 수 있는 범위를 넓힙니다. 신뢰할 수 있는 LAN에서만 사용하고 스위치, 라우터 또는 상위 방화벽으로 출발지 주소를 제한하세요. 이 포트들을 공용 인터넷에 직접 노출하지 마세요.

### 위험 및 문제 해결

> ‘通过LPMU接入’은 LPMU의 기존 기본 경로를 삭제하고 `iptables` NAT 테이블과 FORWARD 체인 규칙을 비운 뒤 FORWARD 기본 정책을 DROP으로 설정합니다. 이후 RM-01에 필요한 경로, NAT, 포트 전달 규칙을 기록합니다. 원격 연결이 즉시 끊길 수 있고 기존 사용자 지정 네트워크·방화벽 설정이 덮어써질 수 있습니다. LPMU를 변경해 사용했다면 먼저 경로표와 방화벽 규칙을 내보내고 로컬 복구 수단을 확보하세요.

실패하면 다음 순서로 확인합니다.

1. C3의 USB-C ↔ RJ45 어댑터와 케이블이 제대로 연결되었는지 확인합니다.
2. 스위치나 라우터 포트가 켜져 있는지 확인합니다.
3. 홈 화면의 상단 USB 대상이 `LPMU`인지 확인합니다.
4. 상위 네트워크가 LPMU에 유효한 주소, 게이트웨이, DNS를 제공하는지 확인합니다.
5. 상위 네트워크 접속 영역의 오류와 출력을 확인합니다.
6. AGX에서 LPMU 내부 주소 `10.10.99.99`에 접근할 수 있는지 확인합니다.
7. LPMU의 사용자 지정 규칙이 기본 경로, NAT, FORWARD 체인, 포트 전달과 충돌하는지 확인합니다.
